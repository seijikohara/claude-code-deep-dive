Claude Code をクラウドの VM で動かし、手元のマシンを閉じても作業を続ける仕組みです。この章では、CLI からの起動と追送、バンドル送信、Teleport、GitHub の接続、クラウド環境（ネットワーク・変数・シークレット・セットアップスクリプト）、VM の制限と Auto-fix を扱います。

<span id="ch50-overview" />

## 全体像: クラウド・ローカル・Remote Control の違い

|                  | クラウドセッション                                                     | ローカルセッション                    | ローカル + Remote Control                               |
| ---------------- | ---------------------------------------------------------------------- | ------------------------------------- | ------------------------------------------------------- |
| コードの実行場所 | クラウド VM（既定は Anthropic 管理）                                   | 自分のマシン                          | 自分のマシン                                            |
| 開始する場所     | claude.ai/code、モバイルアプリ、Desktop の **Cloud**、`claude --cloud` | ターミナル、IDE、Desktop の **Local** | ターミナル、VS Code 拡張、Desktop                       |
| チャットする場所 | claude.ai、モバイルアプリ、Desktop                                     | 開始した場所                          | 開始した場所に加え、claude.ai とモバイルアプリ          |
| ローカル設定     | 使わない（リポジトリのみ）                                             | 使う                                  | 使う                                                    |
| GitHub           | 必要（`--cloud` のバンドル送信を除く）                                 | 不要                                  | 不要                                                    |
| 切断後の継続     | 続く                                                                   | 止まる                                | マシン上でセッションが開いている間                      |
| 権限モード       | Accept edits・Plan・Auto                                               | ターミナルは全モード                  | claude.ai とアプリから Manual・Accept edits・Plan・Auto |
| ネットワーク     | 環境ごとに設定                                                         | マシンのネットワーク                  | マシンのネットワーク                                    |

- Pro・Max・Ultra・Team と Enterprise の対象シートで使えます。使用量はプランに計上され、VM の追加料金はありません。ZDR・HIPAA・CMEK（顧客管理の暗号鍵）の組織は使えません。

## `claude --cloud` で新しいクラウドセッションを作る

```bash
claude --cloud "Fix the auth bug in src/auth/login.ts"

# 計画はローカル、実行はクラウド
claude --permission-mode plan
#   計画をリポジトリに保存し、commit して push
claude --cloud \
  "Execute the migration plan in docs/migration-plan.md"

# --cloud ごとに独立したセッションが並列に動く
claude --cloud "Fix the flaky test in auth.spec.ts"
claude --cloud "Update the API documentation"
```

- クラウド VM は、カレントディレクトリの GitHub リモートを現在のブランチで clone します。ローカルの checkout ではないため、先に push します。
- `Branch <name> is not on GitHub` が出ても、セッションは push 済みの祖先コミットか既定ブランチから始まります。
- 1 回の `--cloud` で扱うリポジトリは 1 つです。旧表記 `--remote` は非推奨の別名として動きます。

* VM の準備中は、clone やセットアップスクリプトの進行をチェックリストで表示します。準備中に入力したメッセージは、準備完了後に送られます。
* CLI からの受け渡しは一方向です。既存のターミナルセッションをクラウドへ送ることはできません。Desktop は **Open in** メニューで送れます（[Ch52](/claude-code-deep-dive/ja/platforms/desktop/)）。
* claude.ai のサインイン（`claude auth login`）が必要です。Bedrock・Agent Platform などのサードパーティプロバイダでは使えません。`ANTHROPIC_BASE_URL` だけで設定したゲートウェイはサードパーティ扱いになりませんが、サインインは必要です。
* 組織ポリシー `allow_remote_sessions` が有効である必要があります。Enterprise のカスタムロールでは、クラウドセッションの権限が要ります。
* 環境の選び方: `/remote-env` で選んだ環境、なければ Anthropic ホストの環境、なければ一覧で最初の bridge 以外の環境です。`--environment ccpool_...` はその 1 回だけセルフホスト環境を指定します（`env_` の ID は拒否）。
* `--cloud` と `--remote-control` は無関係です（[Ch49](/claude-code-deep-dive/ja/platforms/remote-control/)）。

## `-p --cloud <id>` で実行中のセッションに追送する

```bash
claude -p "your message" --cloud <session-id>
echo "your message" | claude -p --cloud <session-id>
```

- メッセージを 1 件キューに入れ、返信を待たずに終了します。ローカルのセッション状態は送らないため、`claude auth login` 済みならどのマシンからでも送れます。
- ID は `session_...`・`cse_...`、または `claude.ai/code/<id>` の URL（スキームやクエリの有無は問わない）です。
- `--output-format json` は成功時 `{ok, session_id, url}`、失敗時 `{ok: false, session_id, error}` です。プロバイダや組織ポリシーの設定エラーは JSON にならず stderr に出ます。
- `--output-format stream-json` は使えません。

```text
Sent to cloud session.
Session ID: session_01…
View: https://claude.ai/code/session_01…?from=cli&m=0
```

| エラー（`Error: `が前に付く）                                             | 意味                                  |
| ------------------------------------------------------------------------- | ------------------------------------- |
| `Cloud sessions aren't available with <provider>. …`                      | サードパーティプロバイダの設定がある  |
| `Cloud sessions are disabled by your organization's policy. …`            | `allow_remote_sessions` がオフ        |
| `Attaching to an existing cloud session is not enabled for your account.` | `-p` なしで `--cloud <id>` を実行した |
| `Session not found: <id>`                                                 | ID が一致しない                       |
| `cloud session <id> is archived and cannot accept new messages`           | アーカイブ済み                        |

:::danger[食い違い]
`--cloud <id>` の説明が食い違っています（未検証）。

- **`claude --help`**: 「attach to an existing one by session ID or claude.ai/code URL」
- **docs**: ID の指定は `-p` と組み合わせたメッセージの追送。`-p` なしは上表のエラー
  :::

## GitHub を使わないバンドル送信

- git リモートがない、または Claude GitHub App が入っていない github.com のリポジトリでは、`--cloud` がローカルリポジトリをバンドルして直接アップロードします。`/web-setup` で接続済みでも同じです。
- 完全な clone なら、全ブランチの履歴と、追跡ファイルの未コミット変更を含みます。未追跡ファイルは含みません（`git add` しておく）。
- macOS・Linux・WSL では、`.env`・`*.tfvars`・`id_rsa`・`*.pem` など認証情報らしい名前のファイルと、Git LFS などの filter 管理ファイルの未コミット変更を除外し、`Left on this machine:` で通知します。
- **ネイティブ Windows では除外しません**。追跡ファイルの未コミット変更は名前にかかわらずそのまま送られます。
- リモートがあってもバンドルさせるには `CCR_FORCE_BUNDLE=1` を付けます。GitLab・Bitbucket などもこの方法で送れますが、結果をそのリモートへ push できません。

```bash
CCR_FORCE_BUNDLE=1 claude --cloud \
  "Run the test suite and fix any failures"
```

### 制限

- 1 つ以上のコミットがある git リポジトリであること。

- 100 MB 未満であること。超えると現在のブランチだけ、次に作業ツリーの単一スナップショットに縮め、それでも大きければ失敗します。

- バンドルから作ったセッションが GitHub へ push できるのは、GitHub 接続にその push 権限がある場合だけです。

- macOS・Linux・WSL では git 2.31 以降が必要です。次の構成は `Not uploading this working tree:` で拒否されます。

  - submodule の中、`--separate-git-dir`・`--shared`・`--reference` の clone、`core.worktree` の設定、reftable
  - sparse checkout の linked worktree（`worktree.sparsePaths` を含む）
  - 作業ツリー内のファイルを include する git 設定

- `git clone --filter` の部分 clone は、履歴なしのスナップショットとして送られます。

## Teleport: クラウドセッションをターミナルに取り込む

| 方法                                | 内容                                                                |
| ----------------------------------- | ------------------------------------------------------------------- |
| `claude --teleport [id]`            | ピッカー、または ID 指定で再開。未コミット変更があると stash を提案 |
| `/teleport`（`/tp`）                | 実行中の CLI から同じピッカーを開く                                 |
| `/tasks` で <kbd>t</kbd>            | バックグラウンドセッションから取り込む                              |
| claude.ai の **Open in > Terminal** | 貼り付けるコマンドをコピー                                          |
| クラウドセッション内の `/teleport`  | `claude --teleport <session-id>` を返す（v2.1.223 以降）            |

- 取り込むとリポジトリを確認し、ブランチを fetch・checkout して会話を読み込みます。
- ターミナル側は独立したコピーです。以後のローカル作業はクラウドに反映されません。続けて端末から操作するなら `/remote-control` を使います。
- 圧縮済みのセッションは、要約された部分を持ち込まず要約から続けます。`--resume` はクラウドセッションを一覧しません。

### 要件

|                     |                                                                       |
| ------------------- | --------------------------------------------------------------------- |
| クリーンな git 状態 | 未コミット変更なし（stash を提案）                                    |
| 同じリポジトリ      | fork は不可。SSH ホスト別名は確認のうえ owner/repo の一致で受け入れる |
| ブランチ            | リモートに push 済み                                                  |
| 同じアカウント      | 同じ claude.ai アカウントで認証                                       |

- fetch は入力を待ちません。パスワード・鍵のパスフレーズ・新しい SSH ホストの確認が必要だと失敗します。`ssh-agent` に鍵を載せ、一度手で `git fetch` しておきます。
- claude.ai のサブスクリプション認証が必要です。API キーなら `claude auth login` を実行します。
- Teleport は Remote Control と同じ基盤を使うため、`Remote Control session expired` や `Access denied` と表示されることがあります。

## GitHub の接続: GitHub App と `/web-setup`

| 方法         | 接続のしかた                                          | 届くリポジトリ                                     | 向いている用途                          |
| ------------ | ----------------------------------------------------- | -------------------------------------------------- | --------------------------------------- |
| GitHub App   | Web のオンボーディングで Claude GitHub App を承認     | 公開リポジトリ全部と、App を入れた非公開リポジトリ | ブラウザでの導入、Auto-fix を使うチーム |
| `/web-setup` | ローカルの `gh auth token` を Claude アカウントへ送る | `gh` のトークンで届く全リポジトリ（App 不要）      | すでに `gh` を使う個人                  |

- Auto-fix と Projects のスレッドは、接続方法にかかわらず各リポジトリに GitHub App が必要です。
- Anthropic ホストの環境では、GitHub の認証情報は暗号化されてサーバーに残り、VM には入りません。
- Team・Enterprise では、Owner が **Organization settings > Connectors** で GitHub コネクタをオンにするまで、Web の GitHub サインインは使えません。
- **Quick setup**（Team・Enterprise、既定オフ）をオンにすると、`/web-setup` が使えるようになり、App のインストール案内を省き、**Default** 環境を自動作成します。

* `/web-setup` は確認のあとトークンを送り、`Connected as <your-github-username>` を表示して claude.ai/code を開きます。環境がなければ Trusted・セットアップなしの環境を作ります。
* ブラウザで接続済みの場合は、置き換えになると警告します。`gh` が未インストール・未認証なら、ブラウザのオンボーディングに切り替わります。
* 削除は `claude.ai/customize/connectors` で GitHub を切断します。トークン自体を無効にするには GitHub 側で取り消します。
* ZDR・HIPAA 構成の組織では `/web-setup` を使えません。

## クラウド環境: Default・選択・ネットワークアクセス

- 環境は、ネットワークアクセス・環境変数・ネットワークシークレット・セットアップスクリプトをまとめた保存済み設定です。Desktop・モバイル・claude.ai/code・`--cloud`・クラウドのスケジュールタスク・Claude Tag で共通です。
- **Default** は Trusted ネットワークで、環境変数とセットアップスクリプトを持ちません。`/web-setup` などの CLI フローと Pro・Max・Ultra の Web 導入では自動で作られ、Team・Enterprise では作成フォームが出ます（Quick setup がオンなら自動）。
- `/remote-env` は CLI の既定環境を選び、user 設定の `remote.defaultEnvironmentId` に保存します。`env_` の ID は通常の優先順位に従い、`ccpool_` の ID は user・managed・`--settings` からだけ読みます。
- Owner は組織共有の環境を作れます。選択肢では **Personal** の後ろに **Organization** として並びます。Claude Tag のチャネルは組織レベルの環境だけを使います。
- Anthropic ホストの環境は削除できず、アーカイブだけです。実行中のセッションは動き続けます。

| レベル      | 外向き接続                                                                   |
| ----------- | ---------------------------------------------------------------------------- |
| **None**    | セッションのネットワーク経由の外向き接続なし                                 |
| **Trusted** | 許可リストのドメインだけ（既定）: パッケージレジストリ、GitHub、クラウド SDK |
| **Full**    | 任意のドメイン                                                               |
| **Custom**  | 自分のリスト。既定リストを含めるかを選べる                                   |

```text
api.example.com
*.internal.example.com
registry.example.com
```

- どのレベルでも届くもの: GitHub（専用プロキシ）、有効にした MCP コネクタ（Anthropic 経由）、ネットワークシークレットのホスト、Anthropic API（None でも届くため、データが VM から出る経路になりうる）。
- 変更は約 1 分で実行中のセッションに届きます。組織全体に配る許可リストはなく、server-managed settings でも追加できません。

## 環境変数とネットワークシークレット

### 環境変数

- `.env` 形式で 1 行に `KEY=value` です。クォートしない値では `#` 以降がコメントになるため、`#` や改行を含む値はクォートします。
- Claude が実行するコマンドから読めます。ただし `OTEL_*` は Claude Code 自身のテレメトリ送信に使い、コマンドには渡しません。
- セッション作成時と、VM で Claude Code が再起動するとき（アイドル後の復元、回収後の再構築）に読みます。編集は実行中のセッションに即時反映されません。
- `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` はセッションが自分で設定するため、ここに書いても効きません。
- 環境を使う全員が値を読めます。キーはネットワークシークレットに置きます。

### ネットワークシークレット

- Anthropic の agent proxy が、VM を出た後のリクエストにキーを付けます。キーは VM に入りません。
- 既定の種類は **Bearer**（`Authorization: Bearer`）です。ホストは `*.` でサブドメインを指定できます。Team・Enterprise の管理者ロールがない人は、1 ホストの短いフォーム（**Token** か **Username and password**、ワイルドカード不可）を使います。
- 付けない宛先: GitHub、`api.anthropic.com`、`registry.npmjs.org`・`jsr.io`・`npm.jsr.io`・`pypi.org`・`files.pythonhosted.org`・`index.crates.io`・`proxy.golang.org`、セットアップスクリプトの通信、テレメトリ送信。
- 完全一致しない重なったホストを持つ 2 つのシークレットは、片方だけ送られ、印も付きません。
- セルフホスト環境と CMEK の組織では使えません。値は保存後に再表示できません。

## GitHub プロキシとセッションへのリンク

- Anthropic ホストの環境では、GitHub への操作はすべて専用プロキシを通ります。VM 内の git はスコープ付きの認証情報を使い、プロキシが本物のトークンに差し替えます。
- ブランチの削除とタグなどの push を拒否します。push 先のブランチは制限しないため、ブランチ保護や rulesets で絞ります。
- API はセッションに付けたリポジトリだけを通します。他は 403 `GitHub access to … is not enabled for this session` です。
- GraphQL は 403 `GitHub GraphQL is not available from Claude Code sessions` です。`gh pr`・`gh issue` も失敗するため、`gh api repos/{owner}/{repo}/...` を使います。
- `GH_TOKEN`・`GITHUB_TOKEN` を設定しない場合、両方とも `proxy-injected` という文字列として見えます。

* セッションは `CLAUDE_CODE_REMOTE_SESSION_ID` で自分の ID を読めます。`CLAUDE_CODE_REMOTE` はクラウドセッションで `true` です。
* Claude が作るコミットには `Claude-Session: <url>` トレーラーが付き、PR 本文にはセッション URL が入ります。`attribution.sessionUrl: false` で止めます。
* それ以外の場所にリンクを書くときは、`cse_` を `session_` に置き換えます（下の 1 行目）。
* claude.ai/code の URL には `prompt`（別名 `q`）・`prompt_url`・`repositories`（別名 `repo`）・`environment` を付けて事前入力できます（下の 2 行目）。

```bash
echo "https://claude.ai/code/${CLAUDE_CODE_REMOTE_SESSION_ID/#cse_/session_}"
```

```text
https://claude.ai/code?prompt=Fix%20the%20login%20bug&repositories=acme/webapp
```

## セットアップスクリプト・SessionStart フック・持ち込まれる設定

- セットアップスクリプトは、Claude Code の起動前に root で動く Bash です（Ubuntu 24.04）。**Choose file** で 64 KB までのファイルを読み込めます。
- 終了コード 0 で終えます。重要でないコマンドには `|| true` を付けます。2.1.314 から、Web・Desktop・モバイルのセッションはスクリプトが失敗しても起動します。
- 約 5 分以内に終わると、ファイルシステムのスナップショットがキャッシュされ、以後のセッションはスクリプトを省きます。プロセスは残りません。
- キャッシュは、スクリプトか許可ホストの変更時と約 7 日の期限で作り直します。アイドル後の復元では再実行しません。
- スクリプトの実行時点では、環境変数はまだ設定されていません。

|          | セットアップスクリプト         | SessionStart フック    |
| -------- | ------------------------------ | ---------------------- |
| 実行時点 | 起動前。キャッシュがあれば省略 | 起動後。再開を含む毎回 |
| 実行場所 | クラウドのみ                   | ローカルとクラウド     |

- フックをクラウドだけで動かすには、`CLAUDE_CODE_REMOTE` が `true` でなければ早期 exit します。
- 複数リポジトリのセッションと Projects のクラウドスレッドでは、リポジトリの `.claude/settings.json` のフックは動きません。

### クラウドに持ち込まれるもの

|                |                                                                                                                                                                                                            |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 持ち込まれる   | リポジトリの `CLAUDE.md`・`.claude/rules/`・`skills/`・`agents/`・`commands/`。単一リポジトリなら `.claude/settings.json` のフック・権限ルールと `.mcp.json`。server-managed settings（Claude Tag を除く） |
| 持ち込まれない | `~/.claude/` 配下、user・local スコープの MCP、リポジトリが `enabledPlugins` で有効にしたプラグイン、MDM の managed settings、`NODE_EXTRA_CA_CERTS` などの接続用変数、AWS SSO などの対話認証               |

個人の好みは、セットアップスクリプトで `~/.claude/CLAUDE.md` を書けば読み込まれます（`/root/.claude/CLAUDE.md`）。

## VM・時間制限・セッション中の操作・Auto-fix

- VM は Ubuntu 24.04 x86_64 で、目安は 4 vCPU・16 GB RAM・30 GB ディスクです。Python・Node 20/21/22・Ruby・PHP・Java 21・Go・Rust・Docker・PostgreSQL 16・Redis 7.0・Chrome for Testing などが入っています（`check-tools` で確認）。シェルには入れず、Claude がすべて実行します。
- Bash は既定 2 分・最大 10 分で、超えるとバックグラウンドへ移って最大 30 分続きます。`BASH_DEFAULT_TIMEOUT_MS`・`BASH_MAX_TIMEOUT_MS` で延ばせます。SessionStart フックは 600 秒です。
- 数分アイドルで VM は一時停止し、後で回収されることがあります（Environment expired）。再開すると会話は戻りますが、シェル・サブエージェント・セッション内のスケジュールタスクは戻りません。
- 権限モードは Auto・Accept edits・Plan です。`/model`・`/effort`・`/color`・`/rename` は引数で指定し、`/fast` は v2.1.271 以降で使えます。Agent Teams <Badge text="Experimental" variant="caution" size="small" class="badge experimental" /> は `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` で有効にします。
- レート制限は他の利用と共有です。組織の IP 許可リストがあると、Anthropic ホストのセッションは認証エラーになります。

### Auto-fix pull requests

- Claude が PR の CI 失敗とレビューコメントを受け取り、明確な修正なら push します。曖昧な指摘は確認を求めます。Claude GitHub App が必要です。
- 有効化: セッションの **Changes** カードの PR メニュー、ターミナルで `/autofix-pr [prompt]`（`gh` で PR を検出しクラウドセッションを起動）、モバイルでの指示、PR の URL を貼って指示。
- ベースブランチの進行による競合は GitHub が webhook を出さないため、自動では対応しません。
- レビュースレッドへの返信は自分の GitHub アカウント名で投稿され、Claude Code 作成と明示されます。

:::caution[注意]
Atlantis・Terraform Cloud・`issue_comment` で動く Actions など、コメントで起動する自動化があるリポジトリでは、Claude の返信がそれらを起動しうると docs は警告しています。
:::
