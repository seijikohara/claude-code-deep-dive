## 解析・連結・キューイング

### 解析と Skill の連結

- コマンドはメッセージの先頭にあるときだけ認識されます。後ろのテキストは引数になります。一覧の `<arg>` は必須、`[arg]` は任意の引数です。
- 端末のプロンプトでは、先頭に Skill を重ねられます。`/skill-a /skill-b do XYZ` は両方を読み込み、末尾のテキストを各 Skill に引数として渡します。
- 展開されるのは先頭の Skill と後続の最大 5 個（計 6 個）です。インラインで呼べるユーザー起動 Skill ではないトークンで展開は止まります。
- フォークしたサブエージェントで動く Skill（`/code-review` など）や、引数が別のコマンドで始まりうる Skill（`/loop`）でも、展開はそこで終わります。
- `claude -p` と Agent SDK では先頭の Skill だけを読み込み、残りは引数になります。
- 文中の `run the tests, then /com` でも補完できますが、挿入したコマンドは文字列として入るだけです。

### Claude の応答中に送ったとき

| コマンド                    | 扱い                                                                                |
| --------------------------- | ----------------------------------------------------------------------------------- |
| 大半のコマンド              | ターン終了まで保留し、送った順に 1 つずつ実行                                       |
| `/status` `/tasks` `/usage` | すぐに実行し、応答を中断しない                                                      |
| `/model`                    | 同じターンの次のリクエストから新モデル（キャッシュ警告が出たら確認後）              |
| `/effort`                   | 次に送るメッセージから新レベル                                                      |
| `/fast`                     | 実行中のターンは元の速度。次のターンから反映                                        |
| `/bug` `/feedback`          | ダイアログをすぐ開く（v2.1.232 以降）                                               |
| `/add-dir`                  | すぐに確認を求め、確認後は同じターンの次のツール呼び出しから使える（v2.1.234 以降） |
| `/theme` `/help` など       | フルスクリーン描画ではダイアログをすぐ開く（v2.1.234 以降）                         |

メッセージのキューイングと <kbd>Ctrl</kbd>+<kbd>Enter</kbd> は [Ch13](/claude-code-deep-dive/ja/operation/keyboard/) で扱います。

## メニュー照合と非表示コマンド

### / メニューの照合

- v2.1.236 以降、先頭の候補を強調するのは、`/` の後の文字がコマンド名か別名の先頭、または名前の中の単語の先頭と一致したときだけです。`:`・`_`・`-` の区切りは無視します。
- 例: `/adddir` は `/add-dir` を、`/new` は別名を通じて `/clear` を強調します。<kbd>Enter</kbd> で強調中の候補を実行します。
- 打ち間違えたときは何も強調しません。近い候補は一覧に残り、<kbd>Tab</kbd> か矢印キーで選べます。<kbd>Enter</kbd> は入力どおりに送信し、`Unknown command` になります。
- プラグインの Skill は短い名前でも一致します。`/deploy` で `myplugin:deploy-app` が見つかり、挿入すると `/myplugin:deploy-app` と書かれます。

### メニューに出ないコマンド

| 種類             | 振る舞い                                                                                                                                                                                                                      |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 使えないコマンド | メニューから外れる。何も一致しないと `No commands match "/name"`。送信すると大半は `Unknown command`。Console API キーでの `/schedule` など一部は独自の案内を返す。組織ポリシーで無効なものも独自のメッセージを返す場合がある |
| 非表示コマンド   | 設計上メニューから外す。部分入力では出ず、完全な名前を打つと一覧に出て、送信すれば実行される。例: `/heapdump`                                                                                                                 |
| 条件付きで非表示 | `/setup-bedrock` は `CLAUDE_CODE_USE_BEDROCK=1`、`/setup-vertex` は `CLAUDE_CODE_USE_VERTEX=1` を設定するまで非表示                                                                                                           |
| すべて無効化     | `--disable-slash-commands`（Skill とコマンドをすべて無効にする）                                                                                                                                                              |

公式一覧に無いのに binary が認識する名前は [情報源の突き合わせ](/claude-code-deep-dive/ja/operation/commands/#ch12-sources) にまとめています。

## 組み込み・Skill・Workflow の違い

| 種類              | 実体                                                                                  | 件数 | 例                               |
| ----------------- | ------------------------------------------------------------------------------------- | ---- | -------------------------------- |
| 組み込みコマンド  | CLI にコード化された固定ロジック                                                      | 95   | `/clear` `/model` `/config`      |
| バンドル Skill    | Claude に渡すプロンプト（自作 Skill と同じ仕組み）。Claude がツールで作業を組み立てる | 20   | `/code-review` `/loop` `/doctor` |
| バンドル Workflow | 多数のサブエージェントへ作業を分散し、バックグラウンドで動く dynamic workflow         | 1    | `/deep-research <question>`      |

### 呼び出しと前提条件

- Claude が場面に応じて自動で呼ぶバンドル Skill もあります。`/verify` と `/deep-research` は、ユーザーが呼んだときだけ動きます。
- 特定の機能に依存する Skill があります。例: `/workflow-authoring` は dynamic workflows が有効なときだけ使えます。
- `/deep-research` には WebSearch ツールが必要です。詳細は [Ch29](/claude-code-deep-dive/ja/extensions/skills/)（Skill）と [Ch41](/claude-code-deep-dive/ja/parallel/workflows/)（Workflow）で扱います。

### 無効化と名前の衝突

- `disableBundledSkills`（`CLAUDE_CODE_DISABLE_BUNDLED_SKILLS=1`）はバンドル Skill と Workflow を取り除きます。`/init` などの組み込みコマンドは入力できますが、モデルからは見えなくなります。
- `/doctor` は入力できるまま残ります。隠すには `DISABLE_DOCTOR_COMMAND` か `skillOverrides` の `"doctor": "off"` を使います。
- 同名の自作 Skill はバンドル Skill を置き換えますが、別名は置き換えません（`code-review` Skill があっても `/review` はバンドル側）。ローカル端末では組み込みコマンドも同様です。

## `/config` の主要キー (1/2): 書式と true|false のキー

- 書式は `/config [key=value ...]`（別名 `/settings`）です。引数なしで Settings 画面を開きます。
- `key=value` を 1 組以上並べると、画面を開かずに設定します。例: `/config thinking=false`、`/config theme=dark`、`/config model=sonnet`
- `key=value` は -p と Remote Control でも動きます（2.1.181）。
- パネルで確認が要る設定（例: `autoContinueAtUsageLimit`）は、`key=value` で無効にはできますが、有効にはできません。
- `/config --help`（2.1.183）が shorthand キーを一覧します。実測では 37 キーで、この節の表の 24 キーと次の節の 13 キーです。

### `true|false` を取るキー（24）

`agentPushNotifEnabled` `autoCompact` `autoConnectIde` `autoScroll` `checkpoints` `copyFullResponse` `copyOnSelect` `defaultToAgentsView` `externalEditorContext` `gitignore` `inputNeededNotifEnabled` `leftArrowOpensAgents` `prStatus` `progressBar` `promptSuggestionEnabled` `recap` `reduceMotion` `thinking` `tips` `turnDuration` `useAutoModeDuringPlan` `verbose` `workflowKeywordTriggerEnabled` `workflows`

:::danger[食い違い]
`--help` の一覧に無いキーの記述があります。

- **docs**: `/config autoContinueAtUsageLimit=false` が動く。
- **changelog 2.1.285**: `/config chrome=true` は /config パネルへ案内し、`/config chrome=false` は有効だった場合に無効化する。

どちらも未検証です。
:::

## 詳細: `/init` `/import` `/doctor` `/insights`

### `/init`

- 既存の `CLAUDE.md` は上書きせず、改善案を出します。
- `CLAUDE_CODE_NEW_INIT=1` では、CLAUDE.md・Skill・Hooks のどれを作るか尋ね、サブエージェントで調べ、書き込む前に案を示します。
- `.cursor/rules/`・`.cursorrules`・`.github/copilot-instructions.md` を取り込みます。`CLAUDE_CODE_NEW_INIT=1` では `AGENTS.md`・`.devin/rules/`・`.windsurf/rules/`・`.windsurfrules`・`.clinerules` も対象です。

### `/import [codex|gemini|cursor] [--dry-run] [--yes]`

- 指示ファイル・MCP サーバー・コマンド・サブエージェント・Skill を取り込みます。指示ファイルは対応する `CLAUDE.md` に 1 回限り追記されます。端末からは `claude import [source]`。
- Bedrock・Agent Platform・Foundry・Claude Platform on AWS・Claude apps gateway 経由と、feature flag の取得を止めた環境では使えません。Cursor は v2.1.265 以降です。

### `/doctor [prompt-audit [path]]`（Skill、別名 `/checkup`）

- インストール、拡張（未使用の Skill・MCP サーバー・プラグイン、遅い Hooks）、`CLAUDE.md`、権限、利用量（v2.1.305 以降、直近 7 日）を点検し、修正は確認後に適用します。
- `prompt-audit`（v2.1.283 以降）は指示ファイルの古い記述や矛盾を調べます。読み取り専用の診断は `claude doctor` です。

### `/insights`

- 未分析のセッションを 1 回で最大 200 件分析し、`~/.claude/usage-data/report.html` に書きます。`cleanupPeriodDays`（既定 30 日）で削除され、トークンは通常の利用として計上されます。

### `/heapdump`

- 報告に添付するのは `-diagnostics.json` だけにします。`.heapsnapshot` には会話全体と認証情報が入り、`claude purge` でも消えません。
