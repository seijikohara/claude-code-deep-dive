CLI の描画方式と端末まわりの設定です。この章では、フルスクリーン描画（Preview）の切り替えと操作、端末の設定とテーマ、音声入力、スクリーンリーダーモード、`claude-cli://` ディープリンクを扱います。

<span id="ch17-fullscreen" />

## フルスクリーン描画: 切り替えと既定の決まり方 <span class="badge preview">Preview</span>

- vim や htop と同じく端末の代替画面に描き、見えているメッセージだけを描画します。ちらつきが消え、長い会話でもメモリが一定になり、マウスが使えます。
- `/tui fullscreen` は設定 `tui` を保存し、会話を保ったまま再起動します。`/tui default` で戻り、`/tui` は現在の描画方式を表示します（v2.1.110 で追加）。
- 再起動で引き継ぐもの: 画面上の会話（`/rewind` 後はその地点から）、権限モード、effort、`/model` の選択、`--allowed-tools`/`--disallowed-tools`、`--agent`、`--agents`、`--append-system-prompt`、`--system-prompt-snapshot`、`--chrome`/`--no-chrome`。
- `--system-prompt`・`--tools`・`--setting-sources` や、Hook・SDK がこのセッションだけに足した deny/ask ルールがあると、`Cannot switch renderers in this session` を出して何も変えません。
- 起動時に描画方式の切り替えを勧めるダイアログは、**Not now** を選ぶか 3 回表示すると出なくなります。

| 状況（上から最初に一致した行）                                         | 描画           |
| ---------------------------------------------------------------------- | -------------- |
| `CLAUDE_CODE_DISABLE_ALTERNATE_SCREEN=1` か `CLAUDE_CODE_NO_FLICKER=0` | クラシック     |
| `CLAUDE_CODE_NO_FLICKER=1`                                             | フルスクリーン |
| このマシンで起動失敗によりフルスクリーンを止めた                       | クラシック     |
| iTerm2 の `tmux -CC`、または Windows 上の Claude Code に SSH           | クラシック     |
| 設定 `tui` がある                                                      | その値         |
| feature flag を取得せず、起動ダイアログの提示を終えた                  | クラシック     |
| feature flag を取得せず、このマシンの初回起動が v2.1.239 以降          | フルスクリーン |
| feature flag を取得し、初回利用が 2026-05-06 以降                      | フルスクリーン |
| それ以外                                                               | クラシック     |

表より先に、アタッチしたバックグラウンドセッションは常にフルスクリーン、スクリーンリーダーモードは常にクラシックになります。flag を取得しないのは Bedrock・Agent Platform・Foundry やテレメトリ無効のセッションです。

## フルスクリーン描画: マウス・スクロール・検索・起動失敗 <span class="badge preview">Preview</span>

- クリックでカーソル移動、`/`・`@` の候補やメニュー・`/config` の値の選択、折りたたまれたツール結果の展開ができます。<kbd>Cmd</kbd>（macOS）/ <kbd>Ctrl</kbd>＋クリックで URL やパスを開きます。
- ドラッグ・ダブルクリック・トリプルクリックで選択し、離すとコピーします（`/config` の Copy on select）。手動コピーは <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>C</kbd>、選択中の <kbd>Ctrl</kbd>+<kbd>C</kbd> はコピーになります。
- コピー先は `pbcopy`、`wl-copy`/`xclip`/`xsel`、`Set-Clipboard`、tmux バッファ、SSH では OSC 52 です。
- 端末本来の選択は <kbd>Fn</kbd>（Terminal.app）、<kbd>Option</kbd>（iTerm2）、<kbd>Shift</kbd>（その他）を押しながらドラッグします。`CLAUDE_CODE_DISABLE_MOUSE=1` はマウス取得をやめ、`CLAUDE_CODE_DISABLE_MOUSE_CLICKS=1` はホイールだけ残します（前者が優先）。
- 起動失敗の判定: 最初のフレームを描いてから 10 秒保つか正常終了すれば成功です。1 回目の失敗後は次のセッションだけクラシックで、その次に再挑戦します。2 回でアップデートか `/tui fullscreen` までクラシックのままです（版ごとに数える。v2.1.236 以降）。

| キー                                                                           | 動作                                                                 |
| ------------------------------------------------------------------------------ | -------------------------------------------------------------------- |
| <kbd>PgUp</kbd> / <kbd>PgDn</kbd>                                              | 半画面スクロール                                                     |
| <kbd>Ctrl</kbd>+<kbd>Home</kbd> / <kbd>Ctrl</kbd>+<kbd>End</kbd>               | 先頭へ / 最新へ移動し自動追従を再開                                  |
| <kbd>Ctrl</kbd>+<kbd>O</kbd> の後 <kbd>/</kbd> <kbd>n</kbd> <kbd>N</kbd>       | トランスクリプト内を検索                                             |
| <kbd>j</kbd> <kbd>k</kbd> <kbd>g</kbd> <kbd>G</kbd> <kbd>\{</kbd> <kbd>}</kbd> | 1 行、先頭・末尾、前後のプロンプトへ                                 |
| <kbd>\[</kbd> / <kbd>v</kbd>                                                   | 会話を端末のスクロールバックへ書き出す / `$VISUAL`・`$EDITOR` で開く |

- 上へスクロールすると自動追従が止まり、`Jump to bottom` ボタンに新着数が出ます。追従自体は `autoScrollEnabled: false` で切れます。
- ホイール速度は `CLAUDE_CODE_SCROLL_SPEED`（20 まで、小数可）か `/scroll-speed`（最大 10、`~/.claude/settings.json` に保存）。加速は `wheelScrollAccelerationEnabled: false` で止めます。
- MacBook では <kbd>Ctrl</kbd>+<kbd>Fn</kbd>+<kbd>→</kbd> が届かないため、`scroll:bottom` を割り当て直します。

## 端末の設定: `/terminal-setup`・通知・tmux

| 端末                           | `/terminal-setup` がすること                                                                    |
| ------------------------------ | ----------------------------------------------------------------------------------------------- |
| VS Code・Cursor・Devin Desktop | <kbd>Shift</kbd>+<kbd>Enter</kbd> を追加し、`terminal.integrated.gpuAcceleration` を `"off"` に |
| Alacritty 0.16 未満・Zed       | <kbd>Shift</kbd>+<kbd>Enter</kbd> を追加。Zed の `keymap.json` は `.bak` を作ってからマージ     |
| Apple Terminal                 | Option を Meta にし、音のベルを切る（スクリーンリーダーモードではベルを残す）                   |
| iTerm2                         | クリップボードへのアクセスを許可（`/copy` と OSC 52 用）                                        |

- tmux や screen の中ではなく、ホストの端末で実行します。
- macOS で <kbd>Option</kbd> ショートカットを使うには Option as Meta が必要です（iTerm2 は Left/Right Option を `Esc+`、VS Code は `"terminal.integrated.macOptionIsMeta": true`）。
- Windows で <kbd>Backspace</kbd> が単語ごと消える場合は `CLAUDE_CODE_BS_AS_CTRL_BACKSPACE=0` にします。
- 同期出力が自動検出されない端末（Emacs `eat` など）のちらつきは `CLAUDE_CODE_FORCE_SYNC_OUTPUT=1`。文章の幅は `maxProseWidth`（40 以上、v2.1.282 以降）。

* `preferredNotifChannel` の既定 `auto` は、iTerm2・Ghostty・Kitty でデスクトップ通知を出し、Terminal.app では音のベルが無効なときだけベル文字を送り、他では何もしません。
* ほかの値は `terminal_bell` `iterm2` `iterm2_with_bell` `kitty` `ghostty` `notifications_disabled`。SSH 先では手元の端末の値にします。
* OSC 7501 Program Status Protocol 対応の端末は、セッションごとに作業中・入力待ち・完了を表示します（v2.1.295 以降）。tmux 内では端末でなく tmux の対応を調べ、バックグラウンドセッションは報告しません。`CLAUDE_CODE_DISABLE_TERMINAL_TITLE=1` で止まります。
* tmux では次の設定で <kbd>Shift</kbd>+<kbd>Enter</kbd> と通知のパススルーが動きます。フルスクリーンのホイールには `set -g mouse on` も要ります。

```bash
set -g allow-passthrough on
set -g focus-events on
set -s extended-keys on
set -as terminal-features 'xterm*:extkeys'
```

## テーマとカスタムテーマ

| 設定 `theme` の値                      | 内容                           |
| -------------------------------------- | ------------------------------ |
| `auto`                                 | 端末の背景の明暗に合わせる     |
| `dark`（既定） / `light`               | 標準のダーク / ライト          |
| `dark-daltonized` / `light-daltonized` | 色覚多様性に配慮した配色       |
| `dark-ansi` / `light-ansi`             | 端末の ANSI パレットだけを使う |
| `custom:<slug>`                        | `~/.claude/themes/<slug>.json` |
| `custom:<plugin-name>:<slug>`          | プラグインが提供するテーマ     |

- `/theme`（または `/config`）で選びます。`/theme` の中では <kbd>Ctrl</kbd>+<kbd>T</kbd> でシンタックスハイライトを切り替え、<kbd>Ctrl</kbd>+<kbd>E</kbd> で選択中のカスタムテーマを編集し、**New custom theme…** で新規作成します。端末そのものの配色は変えません。

```json
{
  "name": "Dracula",
  "base": "dark",
  "overrides": {
    "claude": "#bd93f9",
    "error": "#ff5555",
    "success": "#50fa7b"
  }
}
```

- 3 フィールドとも任意です。`base` は 6 つの組み込み（既定 `dark`）から選び、`overrides` に無いトークンは `base` の色になります。色は `#rrggbb` `#rgb` `rgb(r,g,b)` `ansi256(n)` `ansi:<name>` で、不正な値は無視されます。
- `~/.claude/themes/` を監視して再読み込みします。起動時にフォルダが無かった場合だけ、初回作成後に 1 回再起動します。
- トークンは文字、状態、入力欄とモード（`planMode` `bashBorder` など）、diff、フルスクリーン用背景、使用量メーター、shimmer、`<color>_FOR_SUBAGENTS_ONLY`、`rainbow_<color>` の群に分かれます。

## 音声入力: `/voice`

- 音声は Anthropic のサーバーへ送って文字起こしします（ローカル処理ではない）。`/usage` の上限には数えません。プロジェクト名とブランチ名が認識のヒントに加わります。
- 要件は claude.ai アカウントでのサインイン、ローカルのマイク（クラウドセッションや SSH では不可）、WSL では WSLg です。`ANTHROPIC_API_KEY`・`ANTHROPIC_AUTH_TOKEN`・`apiKeyHelper`・他社プロバイダが優先される間は `Unknown command: /voice` です。

| コマンド      | 効果                              |
| ------------- | --------------------------------- |
| `/voice`      | オン/オフを切り替え、モードは保つ |
| `/voice hold` | 押している間だけ録音するモード    |
| `/voice tap`  | タップで開始・送信するモード      |
| `/voice off`  | 無効化                            |

設定 `"voice": {"enabled": true, "mode": "tap"}` として残ります（旧キー `voiceEnabled` は v2.1.92 から非推奨）。`-p "/voice"` は `/voice isn't available in this environment.` を返しました（実測）。

- **hold**（既定）: <kbd>Space</kbd> を押し続けます。キーリピートで長押しを検出するので、`keep holding…` から `listening…` までの待ちがあります。離すとカーソル位置に挿入し、`"autoSubmit": true` なら 3 語以上で送信します。
- **tap**: 空のプロンプトで <kbd>Space</kbd> をタップすると `● REC · tap to send`、もう一度で停止し、3 語以上なら自動送信します。日本語・中国語・タイ語も語数で数えます。無音 15 秒か合計 2 分で止まります。
- <kbd>Esc</kbd>・<kbd>Ctrl</kbd>+<kbd>C</kbd> は録音を取り消して元の入力に戻すだけです。言語は設定 `language`（空なら英語）で、`ja` を含む 20 言語に対応します。
- キーは `Chat` の `voice:pushToTalk`（1 つだけ。変えると <kbd>Space</kbd> を置き換える）。`meta+k` など修飾キー付きなら待ちがありません。

## スクリーンリーダーモードとアクセシビリティ設定

- 有効化は `claude --ax-screen-reader`、`CLAUDE_AX_SCREEN_READER=1`、ユーザー設定の `"axScreenReader": true` で、この順に優先します。`CLAUDE_AX_SCREEN_READER=0` は設定が `true` でも無効にします。起動行 `[Screen Reader Mode: on via flag]` が経路を示します。
- プロジェクトの `.claude/settings*.json` にある `axScreenReader` と `env` の `CLAUDE_AX_SCREEN_READER` は無視され、他で有効化していなければ `Screen reader mode is off: project settings can't turn it on` と出ます（2.1.305 以降、changelog 2.1.307）。
- 常にクラシック描画で、`tui` は無視されます（アタッチしたバックグラウンドセッションを除く）。`-p` の出力は変わりません。

:::danger[食い違い]
スクリーンリーダーモードの最小バージョンが食い違っています。

- **cli-reference・env-vars**: 「Requires Claude Code v2.1.181 or later」
- **changelog 2.1.208**: 「Added screen reader mode」
  :::

- 罫線・色だけの合図・再描画をやめ、表は `Header: value`、diff は行頭の `+`/`-` で読みます。各メッセージに `you:` `claude:` `tool:` `error:` などのラベルが付きます。
- メニューは番号付きの一覧と `Select with numbers` になり、`/effort` のスライダーも一覧になります。yes/no は `y`/`n` を入力します。
- <kbd>Shift</kbd>+<kbd>Tab</kbd> では `[plan mode on]` のように移った権限モードを告げます（`/plan` での変更は告げない）。
- 返答の完了、回答待ち、5 秒を超えたツールの完了でベルを鳴らし、ターン境界に OSC 133 マーカーを出します。
- 起動行のあと 3 秒待ちます（`CLAUDE_AX_STARTUP_QUIET_MS`）。`CLAUDE_AX_PREPARK_MS` の既定は 2.1.287 で 50 から 0 になりました。
- ほかの選択肢: `CLAUDE_CODE_ACCESSIBILITY=1`（拡大鏡向けに端末カーソルを表示）、`prefersReducedMotion`、daltonized テーマ、`preferredNotifChannel: "terminal_bell"`。

## ディープリンク: `claude-cli://open`

| 引数   | 意味と制約                                                                                                         |
| ------ | ------------------------------------------------------------------------------------------------------------------ |
| `q`    | 入力欄に入れる文。URL エンコードし、改行は `%0A`（v2.1.91 以降）。最大 5,000 文字                                  |
| `cwd`  | 作業ディレクトリの絶対パス。UNC などのネットワークパス、`..`、不可視・双方向制御文字を含むものは拒否               |
| `repo` | GitHub の `owner/name`。最後に `claude` を実行したクローンか worktree に解決し、無ければホーム。ブランチは変えない |

- 両方あれば `cwd` が勝ち、パスが存在しなくても `repo` は無視されます。
- リンクは新しい端末ウィンドウを開き、入力欄を埋めるだけです。<kbd>Enter</kbd> を押すまで何も送りません。入力欄の下に `Prompt from an external link` が出て、1,000 文字を超えると文字数と確認の促しが加わります。

```bash
open "claude-cli://open?repo=acme/payments&q=review%20open%20PRs"
```

- ハンドラーは、対話セッションで何かを送信したとき、または信頼済みフォルダで agent view（Preview）を起動したときに自動で登録されます。

| OS      | 登録先（ユーザー単位）                                             |
| ------- | ------------------------------------------------------------------ |
| macOS   | `~/Applications/Claude Code URL Handler.app`                       |
| Linux   | `$XDG_DATA_HOME/applications` の `claude-code-url-handler.desktop` |
| Windows | `HKEY_CURRENT_USER\Software\Classes\claude-cli`                    |

- 開く端末は、macOS では直近の対話セッションの端末、Linux では `$TERMINAL`→`x-terminal-emulator`→既知の一覧、Windows では Windows Terminal→PowerShell→`cmd.exe` の順です。VS Code 拡張の `vscode://anthropic.claude-code/open`、Desktop の `claude://` は別物です。
- 登録を止めるには `"disableDeepLinkRegistration": "disable"`（v2.1.83 以降、管理設定で強制可）。GitHub の Markdown は `http`/`https` 以外のリンクを消すので、コードブロックに入れます。
