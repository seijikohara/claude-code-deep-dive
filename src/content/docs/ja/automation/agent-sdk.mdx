Claude Code をライブラリとして TypeScript と Python から使う SDK です。この章では、パッケージと認証、最小例、ループの上限とメッセージ型、CLI と既定値が違うオプション、セッションと SessionStore、権限・フック・カスタムツール・MCP、サブエージェントとシステムプロンプト、運用時のコストと分離を扱います。SDK のコード例は docs からの転記で、実行はしていません。

## パッケージ・要件・認証

|                            | TypeScript                                                                              | Python                                                                               |
| -------------------------- | --------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| パッケージ                 | `@anthropic-ai/claude-agent-sdk`                                                        | `claude-agent-sdk`（import は `claude_agent_sdk`）                                   |
| 要件                       | Node.js 18.14 以上                                                                      | Python 3.10 以上                                                                     |
| 旧名                       | `@anthropic-ai/claude-code`                                                             | `claude-code-sdk`。`ClaudeCodeOptions` は `ClaudeAgentOptions` に改名                |
| バイナリが同梱されない場合 | `npm ci --omit=optional` など。ネイティブ版を入れて `pathToClaudeCodeExecutable` を指定 | sdist で入った場合（ARM64 Windows など）。ネイティブ版を入れると `PATH` から見つける |

- SDK は `claude` CLI をサブプロセスとして起動し、stdio で通信します。1 セッションが 1 サブプロセスです。
- 同梱バイナリは SDK のバージョンに固定され、SDK の更新が CLI の更新になります。SDK は semver に従います。例: TS v0.3.290・Python v0.2.164 から CLI v2.1.290 以降を同梱します。
- TS の V2 セッション API（`unstable_v2_createSession` など）は試験的な API で、TS SDK 0.3.142 で削除されました。

### 認証

- `ANTHROPIC_API_KEY` を、エージェントを動かすプロセスの環境に設定します。SDK は `.env` を自動では読みません。
- Bedrock は `CLAUDE_CODE_USE_BEDROCK=1`、Claude Platform on AWS は `CLAUDE_CODE_USE_ANTHROPIC_AWS=1` と `ANTHROPIC_AWS_WORKSPACE_ID`、Agent Platform は `CLAUDE_CODE_USE_VERTEX=1`、Foundry は `CLAUDE_CODE_USE_FOUNDRY=1` です。
- 事前の承認がない限り、サードパーティの製品（SDK で作ったエージェントを含む）で claude.ai のログインやレート制限を提供することは認められていません。

### ブランドとライセンス

- 使える表記: 「Claude Agent」、Agents メニュー内の「Claude」、「\{YourAgentName} Powered by Claude」
- 使えない表記: 「Claude Code」「Claude Code Agent」、Claude Code に似せた ASCII アートや見た目
- 利用は Anthropic の Commercial Terms of Service に従います。

## 最小例: Python と TypeScript

同じエージェントを 2 つの言語で書いた例です。

<Tabs syncKey="sdk-lang">
<TabItem label="Python">

```python
import asyncio
from claude_agent_sdk import query, ClaudeAgentOptions, AssistantMessage, ResultMessage


async def main():
    # Agentic loop: streams messages as Claude works
    async for message in query(
        prompt="Review utils.py for bugs that would cause crashes. Fix any issues you find.",
        options=ClaudeAgentOptions(
            allowed_tools=["Read", "Edit", "Glob"],  # Auto-approve these tools
            permission_mode="acceptEdits",  # Auto-approve file edits
        ),
    ):
        # Print human-readable output
        if isinstance(message, AssistantMessage):
            for block in message.content:
                if hasattr(block, "text"):
                    print(block.text)  # Claude's reasoning
                elif hasattr(block, "name"):
                    print(f"Tool: {block.name}")  # Tool being called
        elif isinstance(message, ResultMessage):
            print(f"Done: {message.subtype}")  # Final result


asyncio.run(main())
```

</TabItem>
<TabItem label="TypeScript">

```typescript
import { query } from "@anthropic-ai/claude-agent-sdk";

// Agentic loop: streams messages as Claude works
for await (const message of query({
  prompt: "Review utils.py for bugs that would cause crashes. Fix any issues you find.",
  options: {
    allowedTools: ["Read", "Edit", "Glob"], // Auto-approve these tools
    permissionMode: "acceptEdits" // Auto-approve file edits
  }
})) {
  // Print human-readable output
  if (message.type === "assistant" && message.message?.content) {
    for (const block of message.message.content) {
      if ("text" in block) {
        console.log(block.text); // Claude's reasoning
      } else if ("name" in block) {
        console.log(`Tool: ${block.name}`); // Tool being called
      }
    }
  } else if (message.type === "result") {
    console.log(`Done: ${message.subtype}`); // Final result
  }
}
```

</TabItem>
</Tabs>

- `query()` は非同期イテレータを返し、作業の進行に合わせてメッセージを流します。
- `allowedTools` は列挙したツールを確認なしで通します。使えるツールを絞る指定ではありません。
- `permissionMode: "acceptEdits"` はファイル編集を自動で承認します。
- 結果メッセージ（`type: "result"`）の後にも `prompt_suggestion` などが届くことがあります。結果で `break` せず、最後まで読み切ります。
- Python 版は `isinstance` で型を判定します。

## ループの上限・メッセージ型・結果の扱い

| オプション（TS / Python）         | 既定               | 到達時                                         |
| --------------------------------- | ------------------ | ---------------------------------------------- |
| `maxTurns` / `max_turns`          | 無制限             | `error_max_turns`                              |
| `maxBudgetUsd` / `max_budget_usd` | 無制限             | `error_max_budget_usd`                         |
| `effort`                          | Claude Code が解決 | `low`〜`max`。`AgentDefinition` で個別に上書き |

- ターン数は「ツールを呼ぶターン + 最後の文章だけのターン 1」で数えます。足りないと最終応答なしで終わります。
- 予算の判定は応答の到着後です。超過は最大で応答 1 回分と、実行中のサブエージェントの支出です。上限後のサブエージェント起動は `Budget limit reached` で失敗します（v2.1.217 以降）。
- セッション全体のタイムアウトはありません。`maxTurns` で抑えます。

### 主なメッセージ型

- `SystemMessage`: `init`・`compact_boundary`・`informational`・`worker_shutting_down`。TS では init 以外が別の型です。
- `AssistantMessage`: 内容ブロック 1 つにつき 1 件。同じ応答のものは同じメッセージ ID を共有します。
- `UserMessage`・`StreamEvent`（部分メッセージ有効時）・`ResultMessage`

### 結果の扱い

- `result` があるのは `success` だけです。全 subtype が `total_cost_usd`・`usage`・`num_turns`・`session_id` を持ちます。
- 単発の `query()` はエラー結果を出した後に例外を投げます（意図した動作）。ストリーミング入力のセッションは、クラッシュ以外では続きます。
- 拒否は `stop_reason === "refusal"` で判定します。クラッシュ後は `stop_reason` が `null` で、費用が 0 になることがあります。

## オプションと CLI の対応・既定値の違い

| TS オプション                                                       | CLI                                                                       |
| ------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| `allowedTools` / `disallowedTools` / `tools`                        | `--allowedTools` / `--disallowedTools` / `--tools`                        |
| `permissionMode` / `permissionPrompts` / `permissionPromptToolName` | `--permission-mode` / `--permission-prompts` / `--permission-prompt-tool` |
| `additionalDirectories`                                             | `--add-dir`（docs が明記）                                                |
| `settingSources` / `settings` / `strictMcpConfig`                   | `--setting-sources` / `--settings` / `--strict-mcp-config`                |
| `maxTurns` / `maxBudgetUsd` / `fallbackModel`                       | `--max-turns` / `--max-budget-usd` / `--fallback-model`                   |
| `outputFormat: { type: 'json_schema', schema }`                     | `--json-schema`                                                           |
| `continue` / `resume` / `forkSession` / `sessionId`                 | `--continue` / `--resume` / `--fork-session` / `--session-id`             |
| `persistSession: false`（TS のみ）                                  | `--no-session-persistence`                                                |
| `extraArgs`                                                         | 任意のフラグ（値なしは `null`）                                           |

`--add-dir` 以外の対応は名前と説明による照合です。

### CLI と既定値が違う点

- `systemPrompt` の既定は**最小のプロンプト**です（v0.1.0 以降）。ツール呼び出しだけを扱い、Claude Code の安全・コーディングの指示を含みません。`claude -p` は Claude Code のプロンプトを使います。
- TS の `env` はサブプロセスの環境を**置き換えます**。`{ ...process.env, YOUR_VAR: 'value' }` と渡します。Python の `env` は継承した環境に重ねます。
- `settingSources` の既定は CLI と同じ全ソースです。v0.1.0 で一時的に「なし」に変わり、戻されました。
- Python で `skills` を指定し `setting_sources` を省くと、user と project だけを読みます。
- `bypassPermissions` には TS で `allowDangerouslySkipPermissions: true` も必要です。
- `taskBudget`（API 側のトークン予算）と `loadTimeoutMs`（既定 60000）は docs が _Alpha_ と記しています。

## `settingSources`: 読み込むファイル系の設定

| ソース      | 読み込むもの                                                                                                  | 場所（`<cwd>` は `cwd` オプション）                                                                                                       |
| ----------- | ------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `"project"` | プロジェクトの `settings.json` とフック、CLAUDE.md と `.claude/rules/*.md`、skill・コマンド・サブエージェント | `settings.json` は `<cwd>/.claude/` だけ（親へは遡らない）。CLAUDE.md と rules は親ディレクトリすべて。skill などはリポジトリのルートまで |
| `"user"`    | ユーザーの `settings.json`、CLAUDE.md と `~/.claude/rules/*.md`、skill・コマンド・サブエージェント            | `~/.claude/` と、その `skills/`・`commands/`・`agents/`                                                                                   |
| `"local"`   | CLAUDE.local.md、`.claude/settings.local.json`                                                                | `settings.local.json` は `<cwd>/.claude/`（git 内ならリポジトリのルートからも）。CLAUDE.local.md は `<cwd>` と親ディレクトリすべて        |

- 省略は `["user", "project", "local"]` と同じです。`[]` で 3 つとも読みません。
- 2.1.281 以降、`settingSources` と `--setting-sources` はチームメイトや `/bg` など、起動したセッションにも引き継がれます。
- `additionalDirectories` の各ディレクトリは `--add-dir` として渡され、`project` ソースがあればその skill・コマンド・サブエージェントも読み込みます。

### `settingSources` が制御しないもの

- managed ポリシーと server-managed settings
- `~/.claude.json`（`CLAUDE_CONFIG_DIR` で移す）
- auto memory（`CLAUDE_CODE_DISABLE_AUTO_MEMORY=1` か `autoMemoryEnabled: false`）
- claude.ai の MCP コネクタ。`mcpServers: {}` では消えません（`strictMcpConfig: true` などで止める）
- `sandbox.credentials` の `deny` と `mask`

## セッションと SessionStore

| 作るもの                 | 使うもの                                                                                 |
| ------------------------ | ---------------------------------------------------------------------------------------- |
| 単発のタスク             | 何も要らない。`query()` 1 回                                                             |
| 1 プロセス内の複数ターン | Python は `ClaudeSDKClient`、TS は `continue: true`                                      |
| 再起動後に続ける         | `continue_conversation=True` / `continue: true`（最新のセッション）                      |
| 特定のセッションを再開   | ID を保存して `resume` に渡す                                                            |
| 元を残して別案を試す     | fork（`forkSession`）                                                                    |
| ディスクに何も書かない   | `persistSession: false`（TS のみ）。Python は `env` に `CLAUDE_CODE_SKIP_PROMPT_HISTORY` |

- 保存先は `~/.claude/projects/<encoded-cwd>/` の `.jsonl` です。保存されるのは会話で、ファイルシステムではありません。ファイルの巻き戻しは `enableFileCheckpointing` と `rewindFiles()` です（[チェックポイント](/claude-code-deep-dive/ja/fundamentals/checkpoints/)）。
- 別ホストで再開するには、SessionStore を使うか、`.jsonl` を新ホストの `~/.claude/projects/` 配下に置きます。

### SessionStore

- 必須は `append(key, entries)` と `load(key)`。任意で `listSessions`・`listSessionSummaries`・`delete`・`listSubkeys`。キーは `{ projectKey, sessionId, subpath? }` です。
- `projectKey` は作業ディレクトリから作るので、同じ `cwd` から再開します。
- サブプロセスがまずローカルに書き、SDK がストアへ複製します。ストアから再開した実行は終了時にローカルの写しを消すため、ストアが唯一の写しになります。
- `append` の失敗は計 3 回まで試し、だめなら `mirror_error` を出してそのバッチを捨てます。`entry.uuid` で重複を除きます。
- `persistSession: false` やファイルチェックポイントとの併用は、起動時に例外です。SDK はストアから削除しません。
- 開発用に `InMemorySessionStore` があり、S3・Redis・Postgres の参考実装が各 SDK リポジトリにあります。

## ストリーミング入力と単発入力

```typescript
import { query, type SDKUserMessage } from "@anthropic-ai/claude-agent-sdk";
import { readFile } from "fs/promises";

async function* generateMessages(): AsyncGenerator<SDKUserMessage> {
  // First message
  yield {
    type: "user",
    message: {
      role: "user",
      content: "Analyze this codebase for security issues"
    },
    parent_tool_use_id: null
  };
```

docs の例の冒頭部分です。この後、2 秒待って画像付きの 2 通目を `yield` します。

- CLI では `--input-format stream-json` で、1 行 1 メッセージの JSON を流します。改行なしで 268,435,456 文字を超えると終了コード 1 です。

### ストリーミング入力（推奨）

- `prompt` に `AsyncIterable` を渡します。
- 画像の添付、メッセージのキュー、途中の割り込み、権限の確認、自然な複数ターンを扱えます。

### 単発入力

- `prompt` に文字列を渡します。単発の応答や、Lambda のような状態を持たない環境向けです。
- 画像の直接添付、動的なキュー、リアルタイムの割り込み、自然な複数ターンは使えません。
- エラー結果のあと例外を投げます。

画像ブロックの `source` が欠けてもエラーにはならず、代わりの文字列が Claude に渡されます。

## 権限の評価順・`canUseTool`・AskUserQuestion

### 評価の 6 段階

1. **フック**: 拒否するか次へ渡す。`allow` を返しても deny・ask ルールは評価される
2. **deny ルール**（`disallowedTools`・設定）: `bypassPermissions` でも拒否
3. **ask ルール**: `canUseTool` へ回す。`AskUserQuestion` と `requiresUserInteraction` の MCP ツールもここで止まる
4. **モード**: `bypassPermissions` は承認、`acceptEdits` はファイル操作を承認、`default`・`dontAsk` は次へ
5. **allow ルール**（`allowedTools`・設定）と、作業ディレクトリ内の読み取りなど自己承認する呼び出し
6. **`canUseTool`**: `dontAsk` では呼ばれず拒否。`permissionPrompts: 'none'` でも呼ばれない

モード未指定の SDK は v2.1.302 以降 `default` で始まり、コールバックがなければ承認待ちは拒否です（[パーミッションモード](/claude-code-deep-dive/ja/settings/permission-modes/)）。`bypassPermissions` などでは、TS が `CLAUDE_SDK_CAN_USE_TOOL_SHADOWED` 警告を出します。

Python の docs の例は、ストリーミングの `prompt` と、`{"continue_": True}` を返すダミーの `PreToolUse` フックを「必須の回避策」として併用しています。

### `canUseTool` の戻り値

|      | Python                                     | TypeScript                            |
| ---- | ------------------------------------------ | ------------------------------------- |
| 許可 | `PermissionResultAllow(updated_input=...)` | `{ behavior: "allow", updatedInput }` |
| 拒否 | `PermissionResultDeny(message=...)`        | `{ behavior: "deny", message }`       |

- 3 番目の引数の `suggestions` を `updatedPermissions` で返すと「次から聞かない」になります。`updatedInput` は v2.1.207 以降省略可です。

### AskUserQuestion

- 1 回に質問 1〜4 個、各 2〜4 択。`header` は 12 文字まで、`multiSelect` で複数選択です。
- 回答は `answers: { "<質問文>": "<label>" }` で返します。サブエージェントでは使えません。`tools` を指定する場合は `AskUserQuestion` を含めます。

## フック: 登録・入出力・判定

- `hooks` にイベント名をキー、matcher の配列を値として渡します。matcher は `matcher`・`hooks`（必須）・`timeout`（秒）・`onFailure` を持ちます。
- コールバックは TS で `(input, toolUseID, { signal })`、Python で `(input_data, tool_use_id, context)` です。
- 出力形式は設定ファイルのコマンドフックと同じ JSON です。`{}` で何もせず通します。
- `PreToolUse` は `hookSpecificOutput` に `permissionDecision`（`allow`・`deny`・`ask`・`defer`）、`permissionDecisionReason`、`updatedInput` を返します。`defer` は `stop_reason` が `tool_deferred` の結果でターンを終えます。
- 判定が割れたら `deny` > `defer` > `ask` > `allow` の順で強い方を採ります。一致したフックは並列に動き、完了順は決まりません。
- 非同期にするには `{ async: true, asyncTimeout: 30000 }` を返します（Python は `async_`）。
- `settingSources` で読んだ設定ファイルのシェルフックも同じイベントで動きます。

```typescript
for await (const message of query({
  prompt: "Your prompt",
  options: {
    hooks: {
      PreToolUse: [{ matcher: "Bash", hooks: [myCallback] }]
    }
  }
})) {
  console.log(message);
}
```

docs の登録例（TypeScript）です。`myCallback` は別途定義したコールバックです。

イベントの詳細と終了コードの意味は [Hooks](/claude-code-deep-dive/ja/extensions/hooks/) です。

## フック: TS と Python の違い・失敗時の扱い

```python
options = ClaudeAgentOptions(
    hooks={"PreToolUse": [HookMatcher(matcher="Bash", hooks=[my_callback])]}
)

async with ClaudeSDKClient(options=options) as client:
    await client.query("Your prompt")
    async for message in client.receive_response():
        print(message)
```

### イベントの対応

- 33 イベントのうち、Python で使えるのは 10 個です: `PreToolUse`・`PostToolUse`・`PostToolUseFailure`・`UserPromptSubmit`・`Stop`・`SubagentStart`・`SubagentStop`・`PreCompact`・`PermissionRequest`・`Notification`。
- 残る 23 個（`SessionStart`・`SessionEnd`・`PostToolBatch`・`Setup` など）は TS だけです。Python では `SessionStart`・`SessionEnd` を設定ファイルのシェルフックとしてだけ使えます。

### コールバックの失敗

- 既定では、例外や検証に通らない出力があっても処理は進み、`SDKInformationalMessage` の警告が届きます。
- `onFailure: "block"`（Python は `on_failure="block"`）で、失敗時に処理を止めます。TS SDK v0.3.317・Python SDK v0.2.177 以降、CLI 2.1.317 以降です。
- 止めたときのツール結果には `failed; blocking because onFailure is "block"` が入り、元のエラー文は Claude に見せません。

## カスタムツール（SDK MCP サーバー）

- ツールを同じプロセス内の MCP サーバーに包みます。TS は `tool(name, description, schema, handler, extras?)` と `createSdkMcpServer({ name, version, tools })`、Python は `@tool` と `create_sdk_mcp_server()` です。
- ツール名は `mcp__{server_name}__{tool_name}` です。`{server_name}` は `mcpServers` のキーで、`.` や空白は `_` に置き換えます。
- ハンドラーは `content`（`text`・`image`・`audio`・`resource`・`resource_link`）と任意の `isError` を返します。
- 捕まえない例外は生のメッセージのままエラー結果になり、ループは続きます。文面を決めるなら `isError: true` を返します。
- TS だけ、`createSdkMcpServer()` の戻り値の `tools` 配列に `permission_policy` を書けます。`always_ask` は `allowedTools` の承認を無効にして `canUseTool` へ回し（`destructiveHint: true` を明示）、`always_deny` は deny ルールの段階で拒否します。
- 注釈はメタデータで、強制ではありません。

| 注釈              | 既定  | 意味                                 |
| ----------------- | ----- | ------------------------------------ |
| `readOnlyHint`    | false | 環境を変えない（並列に呼べる）       |
| `destructiveHint` | true  | 破壊的な更新がありうる               |
| `idempotentHint`  | false | 同じ引数の繰り返しで追加の効果がない |
| `openWorldHint`   | true  | プロセス外のシステムに届く           |

```typescript
import { query } from "@anthropic-ai/claude-agent-sdk";

for await (const message of query({
  prompt: "What's the temperature in San Francisco?",
  options: {
    mcpServers: { weather: weatherServer },
    allowedTools: ["mcp__weather__get_temperature"]
  }
})) {
  // "result" is the final message after all tool calls complete
  if (message.type === "result" && message.subtype === "success") {
    console.log(message.result);
  }
}
```

## MCP サーバーと tool search

### MCP

- `mcpServers` に stdio・HTTP/SSE・SDK（同一プロセス）のサーバーを渡します。HTTP は `"type": "http"` です。
- init の `status` は `connected`・`failed`・`needs-auth`・`pending`・`disabled` のどれかです。
- 最初のターンの待ち: stdio とキャッシュのない HTTP/SSE、SDK サーバーは `MCP_TIMEOUT`（既定 30 秒）まで待ちます。キャッシュ済みのリモートは待ちません。
- 設定ファイル・プラグインのサーバーは、tool search が有効なら、`alwaysLoad: true` か名前を挙げたサーバー（`allowedTools` に `mcp__github__*` など）だけを最大 2 秒待ちます。`CLAUDE_CODE_MCP_STARTUP_WAIT_MS` で変えられます（v2.1.274 以降）。
- SDK はブラウザでの OAuth を行いません。トークンがなければ `needs-auth` になり、トークンを `headers` で渡します。

### tool search（既定で有効）

| `ENABLE_TOOL_SEARCH` | 動作                                                                                     |
| -------------------- | ---------------------------------------------------------------------------------------- |
| 未設定・`true`       | 有効。定義を後から検索して読み込む。古いモデルや Azure 上の Foundry では最初から全部読む |
| `auto`               | 後回しにできる定義がコンテキストの 10% に達するまで無効                                  |
| `auto:N`             | しきい値を N% にする（例 `auto:5`）                                                      |
| `false`              | 無効。毎ターン全定義を読む                                                               |

- 1 回の検索で最大 5 個を読み込み、カタログは最大 10,000 ツールです。
- 対応モデルは Opus 4・Sonnet 4・Haiku 4.5 以降（Agent Platform では 4.5 以降）です。
- `ANTHROPIC_BASE_URL` のゲートウェイ越しでも v2.1.304 以降は既定で有効です。`CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS` があると無効のままです。

## サブエージェント・システムプロンプト・skills・plugins

### サブエージェント

- `agents` に `AgentDefinition` を渡します。必須は `description` と `prompt`、任意は `tools`・`model`・`skills`（先頭 32 個）・`maxTurns`・`effort` などです。既定でバックグラウンドで動きます（`status: "async_launched"`）。
- v2.1.302 以降、fork は設定なしで使えます。止めるには `disallowedTools: ["Agent(fork)"]` です。
- 呼び出しは `tool_use` では `"Agent"`、init の `tools` では `"Task"` です。両方で照合します。
- 上限: 深さ `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`（既定 3）、同時数 `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`（既定 20）。詳細は [サブエージェント](/claude-code-deep-dive/ja/parallel/subagents/) です。

### skills

- skill はファイル（`SKILL.md`）だけで、登録 API はありません。`skills` に `"all"`・名前の配列・`[]` を渡すと、`Skill` が `allowedTools` に加わります。

### システムプロンプト

- 既定（指定なし）は最小のプロンプトです。Claude Code のものを使うには `{ type: "preset", preset: "claude_code" }` を渡し、`append` で追記します。
- `excludeDynamicSections: true` は利用者固有の文脈を最初のユーザーメッセージへ移し、同じプロンプトのキャッシュを共有します。プリセット形だけで、TS v0.2.98・Python v0.1.58 以降です。
- TS の独自プロンプトは文字列の配列にでき、`SYSTEM_PROMPT_DYNAMIC_BOUNDARY` で静的部と動的部を分けます。
- CLAUDE.md や出力スタイル、フックの `additionalContext` などの system reminder は会話に入るため、独自プロンプトでも多くが届きます。

### plugins とコマンド

- plugin は `plugins: [{ type: "local", path }]` だけです。プロンプトに `/<name>` を送るとコマンドや skill を実行し、未知の名前は通常のターンになります（v2.1.274 以降）。

## コスト・OTel・ホスティング・セキュアな運用

### コストと OTel

- `total_cost_usd` と `costUSD` は同梱の価格表（か `modelPricing`）によるクライアント側の推定です。`inference_geo: "us"` は 1.1 倍します。利用者への請求に使ってはいけません。
- ステップごとの使用量はメッセージ ID で重複を除き、`output_tokens` は結果メッセージから読みます。
- テレメトリは子プロセスの CLI が OTLP で送ります。traces は `CLAUDE_CODE_ENHANCED_TELEMETRY_BETA=1` が要る beta です。送信間隔は metrics 60 秒、traces・logs 5 秒です。stdout は SDK の通信路なので `console` exporter は使いません（[監視・コスト・分析](/claude-code-deep-dive/ja/enterprise/monitoring-costs/)）。

### ホスティング

- 出発点は 1 エージェントあたり RAM 1 GiB・ディスク 5 GiB・1 CPU です。コンテナは 1 時間約 $0.05 で、費用の大半はトークンです。
- マルチテナントでは `settingSources: []`、`CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`、テナントごとの `CLAUDE_CONFIG_DIR` と `cwd` を使います。認証情報はサンドボックス外のプロキシで注入します。

### 分離の選択肢

| 技術                    | 分離の強さ                       | 負荷       |
| ----------------------- | -------------------------------- | ---------- |
| Sandbox runtime         | 良い（安全な既定値）             | とても低い |
| コンテナ（Docker）      | 設定次第                         | 低い       |
| gVisor                  | 非常に強い（正しく設定した場合） | 中〜高     |
| VM（Firecracker・QEMU） | 非常に強い（正しく設定した場合） | 高い       |
