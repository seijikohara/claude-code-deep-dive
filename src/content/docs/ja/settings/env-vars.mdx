env-vars リファレンスに載る 402 個の環境変数から、上級者がよく使うものを分野別に抜き出します。設定ファイルの `env` ブロックの規則、値の書き方、changelog にだけ載る変数、廃止された変数とキーも扱います。全件は [付録 B](/claude-code-deep-dive/ja/appendix/env/) にあります。

<span id="ch20-env-block" />

## `env` ブロックの規則と値の書き方

```json
{
  "env": {
    "DISABLE_AUTO_COMPACT": "1",
    "ANTHROPIC_BASE_URL": "https://proxy.example.com"
  }
}
```

- 値は文字列で、シェルを通さずにコピーされます。`~` や `$HOME` は展開されないので、パスは絶対パスで書きます。
- シェルで export した同名の変数を上書きします。例外として、Claude Desktop や self-hosted runner が起動環境を作る場合は起動環境が勝ちます。
- シェルの export を打ち消すには `""` を設定します。プロバイダ選択では未設定として扱い、サブプロセスには空文字列が渡ります。
- `NO_COLOR` と `FORCE_COLOR` はサブプロセスにだけ届きます。
- 適用のタイミング: user・`--settings`・managed は起動時、project・local は trust 後（`-p` では起動時）。どちらも保存のたびに反映し、削除は再起動まで残ります。

### 値の書き方

- on/off の変数は `1`・`true`・`yes`・`on` と `0`・`false`・`no`・`off` を受け付けます。大文字小文字は問いません。
- 次の 5 つは**設定されているかだけ**を見ます。`0` でも有効になるので、止めるには unset か空文字列にします。`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`、`DISABLE_TELEMETRY`、`DISABLE_ERROR_REPORTING`、`CLAUDE_CODE_TMUX_TRUECOLOR`、`IS_DEMO`
- 数値は `2e3`（2000）や `64_000`（64000）も読めます（2.1.211 から）。行に「plain digits only」とある変数は例外です。

### 優先順位

- シェルの変数は起動時にだけ読みます。
- フラグとの関係は変数ごとです。`--model`・`/model` は `ANTHROPIC_MODEL` に勝ち、`CLAUDE_CODE_EFFORT_LEVEL` は `--effort`・`/effort` に勝ちます（[Ch18](/claude-code-deep-dive/ja/settings/settings-files/#ch18-per-key)）。

## `env` ブロックで無視される変数

### project・local の `env` では無視

- 保存先: `CLAUDE_CONFIG_DIR`、`CLAUDE_CODE_TMPDIR`、`HOME`、`TMPDIR`、`TMP`、`TEMP`、`XDG_*`、Windows の `SystemRoot` など
- 内容の書き出し: `OTEL_LOG_RAW_API_BODIES`、`ENABLE_BETA_TRACING_DETAILED`、`BETA_TRACING_ENDPOINT`
- OTel exporter: `CLAUDE_CODE_ENABLE_TELEMETRY`、`OTEL_METRICS_EXPORTER` などの selector、`OTEL_LOG_USER_PROMPTS` などの内容変数、`OTEL_EXPORTER_OTLP_*` の接続設定。off の値（`none`、`0`）だけは効く（2.1.282 以降）
- 起動と同期: `CLAUDE_CODE_PROCESS_WRAPPER`、`CLAUDE_CODE_SYNC_SKILLS`、`CLAUDE_CODE_SYNC_PLUGINS` ほか
- サインインほか: `CLAUDE_CODE_OAUTH_TOKEN`、`CLAUDE_AX_*`、`CLAUDE_CODE_DISABLE_ATTACHMENTS`、`CLAUDE_CODE_DISABLE_FILE_MENTIONS` ほか

これらはシェル、user・managed 設定、`--settings` では効きます。

### どのファイルでも無視（起動環境からだけ読む）

- `CLAUDE_CODE_REMOTE`、`CLAUDE_CODE_ACCOUNT_UUID`、`CLAUDE_CODE_PROJECT_DIR_NAME`、`CLAUDE_CODE_RESTRICTED`
- `CLAUDE_CODE_MESSAGING_SOCKET`、`CLAUDE_CODE_MESSAGING_TOKEN`
- `CLAUDE_CODE_DISABLE_DANGEROUS_RM_TIMEOUT` などの rm 確認を外す変数、`CLAUDE_CODE_EVEN_MORE_DANGEROUSLY_SKIP_PERMISSIONS`
- `CLAUDE_CODE_WARN_DISK_FREE_GIB`、`CLAUDE_CODE_WARN_MEMORY_FREE_GIB`

### 無視されたことの確かめ方

- project・local の telemetry 変数を無視すると、対話セッションは起動時に通知し、`/status` と `claude doctor` が名前だけを表示します。`-p` と SDK では通知が出ません。
- その他の変数は、`claude --debug` のログに警告が出ます。

## 認証・プロバイダ・モデル

| 変数                                                                                                                                      | 要点                                                                                                          |
| ----------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `ANTHROPIC_API_KEY`                                                                                                                       | `X-Api-Key` として送る。ログイン中のサブスクリプションより優先。`-p` では常に使い、対話では初回に承認を求める |
| `ANTHROPIC_AUTH_TOKEN`                                                                                                                    | `Authorization` ヘッダーの値。`Bearer `を前置して送る                                                         |
| `ANTHROPIC_BASE_URL`                                                                                                                      | プロキシ・ゲートウェイへ送る。Anthropic 以外のホストでは Remote Control が無効（2.1.196 から）                |
| `CLAUDE_CODE_OAUTH_TOKEN`                                                                                                                 | claude.ai の OAuth アクセストークン。`claude setup-token` で発行。keychain の認証情報より優先                 |
| `CLAUDE_CODE_USE_BEDROCK`・`CLAUDE_CODE_USE_VERTEX`・`CLAUDE_CODE_USE_FOUNDRY`・`CLAUDE_CODE_USE_ANTHROPIC_AWS`・`CLAUDE_CODE_USE_MANTLE` | プロバイダの選択（[Ch59](/claude-code-deep-dive/ja/enterprise/providers/)）                                   |
| `CLAUDE_CODE_API_KEY_HELPER_TTL_MS`                                                                                                       | `apiKeyHelper` を再実行する間隔（ミリ秒）                                                                     |
| `ANTHROPIC_MODEL`                                                                                                                         | 開始モデル。`model` キーより先、`--model` より後                                                              |
| `ANTHROPIC_DEFAULT_MODEL`                                                                                                                 | どのファイルも `model` を持たないときの既定（2.1.236 以降）                                                   |
| `ANTHROPIC_DEFAULT_OPUS_MODEL` ほか                                                                                                       | エイリアスの解決先を固定（[Ch2](/claude-code-deep-dive/ja/fundamentals/models/)）                             |
| `CLAUDE_CODE_SUBAGENT_MODEL`                                                                                                              | サブエージェント・teammate・workflow エージェントの既定モデル                                                 |
| `CLAUDE_CODE_EFFORT_LEVEL`                                                                                                                | `low`〜`max`。`--effort`・`/effort`・設定より優先。`auto` で effort を送らない                                |
| `CLAUDE_CODE_MAX_OUTPUT_TOKENS`                                                                                                           | 出力トークンの上限。未知のモデル ID では既定 32000・上限 128000                                               |

## ネットワーク・キャッシュ・コンテキスト

| 変数                              | 要点                                                                                                          |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `API_TIMEOUT_MS`                  | 各試行がレスポンスヘッダーを受け取るまでの時間。既定 600000（10 分）。`0` で解除（2.1.305 以降）              |
| `CLAUDE_CODE_MAX_RETRIES`         | 失敗したリクエストの再試行回数。既定 10。`529` では早めに止まる                                               |
| `HTTPS_PROXY`・`NO_PROXY`         | プロキシと、プロキシを通さない宛先（[Ch60](/claude-code-deep-dive/ja/enterprise/network-gateways/)）          |
| `CLAUDE_CODE_CERT_STORE`          | CA 証明書の取得元。`bundled`・`system` をカンマ区切り                                                         |
| `DISABLE_PROMPT_CACHING`          | 全モデルでプロンプトキャッシュを無効化。モデル別の指定より優先                                                |
| `CLAUDE_CODE_PROMPT_CACHE_TTL`    | `5m` か `1h`。`promptCacheTtl` と `ENABLE_PROMPT_CACHING_1H` より優先                                         |
| `FORCE_PROMPT_CACHING_5M`         | 他の TTL 指定をすべて上書きして 5 分にする                                                                    |
| `DISABLE_AUTO_COMPACT`            | 自動圧縮とアイドル圧縮を止める。`/compact` は使える（[Ch6](/claude-code-deep-dive/ja/fundamentals/context/)） |
| `DISABLE_COMPACT`                 | 手動の `/compact` を含め、すべての圧縮を止める                                                                |
| `CLAUDE_CODE_AUTO_COMPACT_WINDOW` | `100000`〜`1000000`。`200k` のような表記は 2.1.304 以降                                                       |
| `CLAUDE_CODE_DISABLE_1M_CONTEXT`  | 1M コンテキストを無効化し、既定で 1M のモデルも 200K に抑える                                                 |
| `CLAUDE_CODE_DISABLE_CLAUDE_MDS`  | user・project・auto memory を含め、CLAUDE.md を読まない                                                       |

| 変数                                       | 要点                                                              |
| ------------------------------------------ | ----------------------------------------------------------------- |
| `CLAUDE_CODE_ENABLE_TELEMETRY`             | OTel を有効化。シェル・user・managed で設定                       |
| `DISABLE_TELEMETRY`                        | テレメトリ停止。`0` でも停止                                      |

| `DEBUG`                                                                 | `--debug` と同じ。`1`・`true`・`yes`・`on` のときだけ |
| `CLAUDE_CODE_DEBUG_LOGS_DIR`                                            | ログの**ファイル**パス。単独では有効にならない        |

## feature flag の取得を止める変数と、その影響

### 取得しないセッション

- `DISABLE_GROWTHBOOK`、`DISABLE_TELEMETRY`、`DO_NOT_TRACK`、`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` のどれかを設定したセッション。どの値で止まるかは変数ごとに違います（`DISABLE_GROWTHBOOK` は `0` なら取得を続ける）。
- サードパーティのプロバイダ（Bedrock、Claude Platform on AWS、Agent Platform、Foundry）。埋め込みホストが `CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST` を設定した場合を除きます。
- Claude apps gateway のセッション。

### 最初のセッションの注意

- インストールや更新の直後のセッションでは、flag に依存する機能が欠けることがあります。取得した flag はマシンに保存され、次のセッションから効きます。
- 毎回クリーンな CI コンテナでは、毎回が最初のセッションです。

### 取得を止めると使えなくなるもの

- Remote Control（`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` か `DISABLE_GROWTHBOOK` の場合）
- 他のマシンのセッションへのメッセージ
- `claude import` と `/import`、`/skill-doctor`
- `/restart`（Pro・Max・Ultra）
- claude.ai の Skill とプラグインの同期
- advisor、Artifact のコメント
- Claude が下書きするフィードバック
- 大きな貼り付けを貼り付けとして扱う処理
- API が拒否する入力スキーマを持つ MCP ツールの除外

docs は MCP タスクもこの一覧に挙げていますが、2.1.319 からターミナルでは flag の取得なしで動きます（changelog、[Ch30](/claude-code-deep-dive/ja/extensions/mcp/)）。
