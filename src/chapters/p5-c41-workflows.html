Dynamic Workflows

Claude が書いた JavaScript のスクリプトを、ランタイムがバックグラウンドで実行し、多数のサブエージェントを動かす仕組みです。この章では、他の手段との違い、opt-in の経路と承認、スクリプト API と保存、実行中の管理と再開、上限・サイズ目安・コスト・無効化を扱います。

opt-in の経路と、起動前の承認

  • workflow が動くのは 3 通りです。既存の workflow コマンド（/deep-research、保存した /<name>）を実行する。プロンプトで頼む。Ultracode を ON にする。
  • プロンプトにキーワード ultracode を入れるか、"use a workflow" のように頼むと、そのタスクを workflow にします。例: ultracode: audit every API endpoint under src/routes/ for missing auth checks
  • キーワードが効くのは、人が入力したプロンプトだけです。-p のプロンプト、human の印が無い SDK 入力、スケジュールタスクのプロンプト、webhook や PR コメントの中継では効きません。
  • 取り消しは Option+W（macOS）・Alt+W か、キーワード直後の Backspace です。/config の Ultracode keyword trigger で無効にできます。
  • Ultracode が ON だと、Claude が実質的なタスクごとに workflow を計画し、トークンと時間が増えます。ON の間は Large workflow 警告・同時サブエージェント上限・auto mode の初回承認が働きません。切り替えは Ch3 を参照してください。

CLI の承認プロンプトの選択肢: Yes, run it / Yes, and don't ask again for <name> in <path>（名前で実行した workflow のみ）/ View raw script / No。Ctrl+G でエディタ、Tab でコメントです。

権限モード承認プロンプト
Auto初回だけ。Yes で user 設定に同意を記録。Ultracode が ON なら出ない
Manual・acceptEdits毎回。don't ask again を選んだ workflow を除く
bypassPermissions出ない
-p・Agent SDK出ない。Workflow の呼び出しとして通常の権限評価を受ける
  • -p・SDK で許可する方法: allow ルール Workflow か Workflow(<name>)、auto mode、bypass、PreToolUse の "allow"（plan mode では不可）、--permission-prompt-tool・canUseTool。
  • Desktop は Once / Always / Deny の承認カードです。起動したエージェントにも通常の権限ルールが効き、auto mode の分類器は agent() のプロンプトをあなたの依頼と見なしません。

スクリプト API

export const meta = {
  name: 'audit-routes',
  description: 'Audit every route handler for missing auth checks',
}

const found = await agent('List every .ts file under src/routes/.', {
  schema: { type: 'object', required: ['files'], properties: { files: { type: 'array', items: { type: 'string' } } } },
})

const audits = await pipeline(found.files, file =>
  agent(`Audit ${file} for missing authentication checks.`, { label: file }),
)

return audits.filter(Boolean)
  • agent() は 1 体、pipeline() は要素ごと、parallel() は同時に動かして全部を待ちます。ほかに phase()・log()・args があります。
  • export const meta は先頭の文で、リテラルにします。式を含むと /<name> が補完から消えます。phases のタイトルは phase() と一致させます。
  • import() を含むスクリプトは開始前に失敗します。
  • Date.now()・Math.random()・引数なしの new Date() は例外になります。時刻は args で渡します。
  • agent() は停止や回復不能な API エラーで null を返し、pipeline() はそれを残します。
  • schema を渡すと JSON で返り、矛盾を証明できるスキーマは起動前にエラーです。検証は 5 回まで（MAX_STRUCTURED_OUTPUT_RETRIES）です。

保存・配布・Workflow ツールの入出力

  • /workflows で run を選び s で保存します。Tab で .claude/workflows/（リポジトリで共有）と ~/.claude/workflows/（個人。CLAUDE_CONFIG_DIR があればその下）を切り替え、以後は /<name> で動きます。
  • プロジェクト側は .claude・.claude/workflows・対象ファイルのどれかが symlink なら拒否します。個人側は対象ファイルだけを確認します。
  • monorepo では、ルートまでで最も近い既存の .claude/workflows/ に保存します。読み込みは経路上のすべてからで、同名は最も近いものが、個人と同名ならプロジェクトが勝ちます。
  • プラグインはルートの workflows/ かマニフェストの workflows に置き、/acme-tools:release-audit のように名前空間が付きます。
  • Run /triage-issues on issues 1024, 1025, and 1030 と頼むと、構造化データが args に入ります。
  • 編集前に /workflow-authoring（v2.1.248 以降）を実行し、編集後は /reload-skills で読み直します。
WorkflowInput意味
script?: stringインラインのスクリプト
name?: string同梱か .claude/workflows/ の名前
scriptPath?: stringファイルのパス。最優先。Read が無いセッションではエラー
args?: unknownグローバル args。JSON 文字列ではなく値で渡す
resumeFromRunId?: string再開する run。同じセッション内だけ
title・description無視される。meta が決める
  • script・name・scriptPath のどれかが必須です。
  • 出力は受理した時点で返り、status は "async_launched" か、クラウドに送った "remote_launched" です。構文エラーでも "async_launched" に error が付くので、error を先に確認します。
  • ファイルのパスから起動した場合を除き、実行ごとのスクリプトは ~/.claude/projects/ のセッションディレクトリに書かれます。外部のファイルは、セッションが読める場所のものだけ起動できます。

/workflows・停止・再開

キー動作キー動作
↑ ↓選択p一時停止・再開
Enter →中へ入る・詳細の展開xエージェントか run 全体を止める
Esc ←1 階層戻るr実行中のエージェントを再起動
j k詳細のスクロールsスクリプトを保存
f状態で絞り込み
  • run が 1 つなら一覧を飛ばして開きます。入力欄の下のタスクパネルにも 1 行の進捗が出ます。
  • 止めた run は、エージェントのプロセスが残る間パネルに残ります。もう一度止めると再シグナルします。
  • 出力が途絶えたエージェントは同じプロンプトでやり直します（(retry 1)、attempt 2 (stalled)）。r を含め 5 回までで、6 回目も止まると agent stalled on all 6 attempts などで失敗します。待ち時間は agent(prompt, { stallMs: 1800000 }) か CLAUDE_ASYNC_AGENT_STALL_TIMEOUT_MS で延ばします。
  • 一時停止した run は p で再開します。止めた run は、同じスクリプトでの再実行を Claude に頼みます。前回のエージェントが終わるまで拒否されます。
  • 再実行は起動順に再生されます。完了済みは保存結果を返しますが、プロンプトが前回と違う最初のエージェント以降はすべて再実行です。止めた時点で実行中のものは最初から、失敗したもの（x で単独停止を含む）はそれ以降も含めて再実行です。例: A・B・C・D で B が失敗すると、A はキャッシュ、B・C・D は再実行です。
  • セッションを背景に送るか終了すると、run は自分では続きません。Claude が Workflow を呼び直したときだけ保存結果から再生します。結果が無ければ nothing to resume です。claude --resume で戻れば、終了したセッションの run も再実行できます。
  • claude.ai の使用量上限では一時停止し、リセット後に自動で続きます（v2.1.271 以降）。条件は、対話セッションと claude.ai サブスクリプション、autoContinueAtUsageLimit が ON、24 時間以内のリセット、それまでの待ちが 2 回未満、のすべてです。
