CI/CD

GitHub Actions（anthropics/claude-code-action@v1）と GitLab CI/CD から Claude Code を動かす方法です。この章では、セットアップ、入力と v1 への移行、ワークフロー例、クラウドプロバイダの OIDC 連携、GitLab と GitHub Enterprise Server を扱います。クラウドの定期実行（routines）は Ch43、PR の自動レビューは Ch47 です。

GitHub Actions のセットアップ

クイックセットアップ: /install-github-app

  • github.com のリポジトリ専用です。リモートが gitlab.com や bitbucket.org なら、案内を出して終了します。
  • 管理者権限と gh auth login 済みの GitHub CLI が要ります。アプリを入れ、シークレット ANTHROPIC_API_KEY か CLAUDE_CODE_OAUTH_TOKEN を保存します。
  • 選んだワークフロー（claude.yml、任意で claude-code-review.yml）をブランチに push し、PR 作成画面を開きます。再実行で Update workflow file with latest version を選べます。
  • クラウドプロバイダは対象外です（後述）。

手動セットアップ

  1. github.com/apps/claude をインストール
  2. シークレットを追加。OAuth トークンは claude setup-token で作る（Pro・Max・Ultra・Team・Enterprise）
  3. examples/claude.yml を .github/workflows/ にコピー

組織への展開

  • アプリを組織単位で入れ、組織の Actions シークレットを共有します。OAuth トークンは発行者個人に紐づくため、共有には API キーを使います。
  • 長期のシークレットを置かない方法として workload identity federation があります。入力は anthropic_federation_rule_id（fdrl_...）・anthropic_organization_id・anthropic_service_account_id（任意）・anthropic_workspace_id（任意）で、id-token: write が必要です。

GitHub App の権限

  • 1 つのアプリを各機能で共有し、部分的な承認はできません。
  • 読み書き: Actions・Checks・Contents・Discussions・Issues・Pull requests・Repository hooks・Workflows。読み取り: Administration・Members・Merge queues・Metadata・Statuses。
  • Action 自体が使うのは Contents・Issues・Pull requests だけです。この 3 つだけのカスタムアプリも使えますが、Code Review と auto-fix には公式アプリが必要です。

入力・claude_args・v1 への移行

入力内容
prompt指示。文字列か skill 呼び出し。省くとトリガー語に反応
claude_argsClaude Code の CLI 引数
anthropic_api_keyClaude API キー（クラウドプロバイダでは不要）
claude_code_oauth_tokenclaude setup-token のトークン
github_token省くと Claude GitHub App として認証
plugin_marketplacesマーケットプレイスの Git URL（改行区切り）
plugins実行前に入れるプラグイン（plugin-name@marketplace-name）
settings設定の JSON 文字列かファイルパス
trigger_phrase反応する語。既定は @claude
use_bedrock / use_vertex / use_foundryClaude API の代わりにクラウドプロバイダを使う

docs の表は「よく使う入力」だけです。全入力はアクションのリポジトリの docs/usage.md にあります。

  • 対話モード（prompt なし）: issue・PR のコメント、PR レビュー、新しい issue の本文・タイトルのトリガー語に反応し、経過をコメントで返します。
  • 自動化モード（prompt あり）: 任意のイベントで動き、結果は既定でワークフローのログに出ます。
  • 起動者の検査: issue・PR では書き込み権限が要ります（例外は allowed_non_write_users）。bot は allowed_bots になければ拒否され、cron の実行も対象です。
  • claude_args は任意の CLI 引数を受けます。例: claude_args: "--max-turns 5 --model claude-sonnet-5 --mcp-config /path/to/config.json"。--model がなければ Claude Code の既定モデルです。

@beta から @v1 へ

  1. uses 行の @beta を @v1 に変える
  2. mode を削除する（自動判定）
  3. direct_prompt を prompt に変える
  4. max_turns・model を claude_args に移す。custom_instructions は --append-system-prompt になる

ワークフロー例 (1/2): @claude への応答

name: Claude Code
on:
  issue_comment:
    types: [created]
  pull_request_review_comment:
    types: [created]
jobs:
  claude:
    if: contains(github.event.comment.body, '@claude')
    runs-on: ubuntu-latest
    permissions:
      contents: write
      pull-requests: write
      issues: write
      id-token: write
      actions: read
    steps:
      - uses: actions/checkout@v6
        with:
          fetch-depth: 1
      - uses: anthropics/claude-code-action@v1
        with:
          anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}
  • id-token: write: Action の既定の GitHub App 認証に必要です。
  • actions: read: PR の CI 結果を読めるようにします。
  • actions/checkout: 作業用にリポジトリの写しを用意します。
  • if: @claude を含まないコメントでランナーを起動しないためです。Action 自身もトリガー語を検査します。
  • サブスクリプションで認証するなら、anthropic_api_key の行を claude_code_oauth_token: ${{ secrets.CLAUDE_CODE_OAUTH_TOKEN }} に変えます。

動かないとき

  • @claude は単語として書きます。/claude や @claude-bot では起動しません。
  • 既定の GITHUB_TOKEN で作ったコミットは CI を起動しません。github_token を外してアプリとして認証するか、カスタムアプリのトークンを渡します。
  • 公開リポジトリでは、fork からの PR の実行にシークレットが渡りません。

ワークフロー例 (2/2): skill でのレビューと定期実行

PR を開いたら code-review プラグインの skill を実行する（steps の抜粋）

      - uses: anthropics/claude-code-action@v1
        with:
          anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}
          plugin_marketplaces: "https://github.com/anthropics/claude-plugins-official.git"
          plugins: "code-review@claude-plugins-official"
          prompt: "/code-review:code-review --comment ${{ github.repository }}/pull/${{ github.event.pull_request.number }}"
          claude_args: '--allowedTools "mcp__github_inline_comment__create_inline_comment"'
  • --comment で PR にコメントします。Action は claude_args の --allowedTools にこのツール名があるときだけ、インラインコメント用の MCP サーバーを起動します。draft・クローズ済みの PR は飛ばします。

毎日 09:00 UTC にレポートを作る（steps の抜粋。トリガーは cron: "0 9 * * *"）

      - uses: anthropics/claude-code-action@v1
        with:
          anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}
          prompt: "Generate a summary of yesterday's commits and open issues"
          claude_args: |
            --model claude-opus-5-5
            --allowedTools "mcp__github__list_commits,mcp__github__list_issues"
  • 許可したツールだけを使います。GitHub は既定ブランチのスケジュールだけを実行し、公開リポジトリでは 60 日間活動がないと止めます。

クラウドプロバイダ（OIDC）で動かす

  1. GitHub の ID: 公式アプリ、カスタムアプリ（3 権限、webhook 無効）、GITHUB_TOKEN（CI を起動しない）
  2. クラウド側の信頼を設定する
    • AWS: OIDC プロバイダ https://token.actions.githubusercontent.com、audience sts.amazonaws.com。ロールの信頼条件を repo:your-org/your-repo:* などに絞る
    • Google Cloud: IAM Credentials・STS・aiplatform.googleapis.com を有効化。WIF プールと roles/aiplatform.user のサービスアカウント
    • Azure: フェデレーション資格情報付きの Entra アプリに Azure AI User ロール
  3. シークレット: AWS_ROLE_TO_ASSUME、GCP_WORKLOAD_IDENTITY_PROVIDER・GCP_SERVICE_ACCOUNT、AZURE_CLIENT_ID・AZURE_TENANT_ID・AZURE_SUBSCRIPTION_ID、カスタムアプリなら APP_ID・APP_PRIVATE_KEY
  4. ワークフローに id-token: write を付ける

公開リポジトリでは、誰のコメントでも認証の手順まで進みます。先に投稿者の権限を確かめる手順を足します。

      - name: Configure AWS Credentials (OIDC)
        uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: ${{ secrets.AWS_ROLE_TO_ASSUME }}
          aws-region: us-west-2

      - uses: anthropics/claude-code-action@v1
        with:
          github_token: ${{ steps.app-token.outputs.token }}
          use_bedrock: "true"
          claude_args: '--model us.anthropic.claude-sonnet-4-6'

Bedrock の例の後半です。モデル ID の us. はクロスリージョン接頭辞です。

  • Agent Platform: google-github-actions/auth@v2 の後に use_vertex: "true"。env に ANTHROPIC_VERTEX_PROJECT_ID: ${{ steps.auth.outputs.project_id }} と CLOUD_ML_REGION: us-east5
  • Foundry: azure/login@v2 の後に use_foundry: "true"。env に ANTHROPIC_FOUNDRY_RESOURCE: your-resource-name

GitLab CI/CD と GitHub Enterprise Server

GitLab CI/CD Beta

  • GitLab が保守する統合で、サポートは GitLab の issue で受けます。.gitlab-ci.yml のジョブで claude -p を動かし、変更は MR で戻します。
  • マスクした CI/CD 変数 ANTHROPIC_API_KEY を置き、ジョブ内で curl -fsSL https://claude.ai/install.sh | bash で入れます。GitLab API には CI_JOB_TOKEN か、api スコープのトークンを GITLAB_ACCESS_TOKEN として使います。
  • @claude のコメントで起動するには、自前の webhook リスナーからパイプラインのトリガー API を AI_FLOW_INPUT・AI_FLOW_CONTEXT・AI_FLOW_EVENT 付きで呼びます。
  • Bedrock は id_tokens の GITLAB_OIDC_TOKEN で、Agent Platform は WIF で認証します。--max-turns とジョブの timeout: 30m で費用を抑えます。
    - >
      claude
      -p "${AI_FLOW_INPUT:-'Review this MR and implement the requested changes'}"
      --permission-mode acceptEdits
      --allowedTools "Bash Read Edit Write mcp__gitlab"
      --debug

docs の .gitlab-ci.yml の例の script 末尾です。

GitHub Enterprise Server

  • Team と Enterprise のプランで使えます。Owner か Primary Owner が Organization settings > Git providers から一度だけ接続します（表示名は 20 文字まで）。
  • 対応: クラウドセッション・Code Review・テレポート・プラグインのマーケットプレイス・GitHub Actions（手動設定のみ）・Claude Security（Enterprise 向け public beta）。
  • 非対応: contribution metrics、GitHub MCP サーバー（gh auth login --hostname github.example.com で代える）。
  • ホスト型のセッションと Code Review のため、GHES を Anthropic の送信元 IP から届くようにします。
