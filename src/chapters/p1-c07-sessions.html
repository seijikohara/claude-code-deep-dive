セッション

セッションは、プロジェクトのディレクトリに紐づいて保存される会話です。この章では、トランスクリプトの実体、再開の入口と復元される状態、ピッカーと命名、分岐、保持と永続化の制御、ヘッドレスで使えるコマンド、そして /goal の使い方と内部動作を扱います。

トランスクリプトの実体と格納場所

  • 既定の保存先は ~/.claude/projects/<project>/<session-id>.jsonl です。<project> は作業ディレクトリのパスの英数字以外を - に置き換えた名前で、200 文字を超えると 200 文字で切ってパス全体のハッシュを付けます。
  • 1 行が 1 つの JSON です。メッセージ、ツールの呼び出しと結果、モデルへ送ったリクエストの記録、メタデータが入ります。2.1.300 からは各リクエストのシステムプロンプト・ツール・パラメータも記録します。
  • 形式は内部仕様で、リリースごとに変わります。スクリプトから直接解析せず、/export か下の手段を使います。
  • 同じディレクトリの <session>/subagents/ にサブエージェントのトランスクリプト、<session>/tool-results/ に大きなツール出力が入ります。
  • 暗号化はされず、OS のファイル権限だけが保護です。ツールが読んだ .env の値も書き込まれます。
用途手段
人が読む/export [filename]。引数なしはクリップボードかファイルを選ぶメニュー
1 回の実行を構造化して取るclaude -p --output-format json または stream-json
既存セッションに質問するclaude -p --resume <session-id>
イベントに反応するフックとステータスラインが受け取る transcript_path。SessionEnd フックで保存できる
アプリに組み込むAgent SDK
 
claude -p --resume  --output-format json \
  "summarize what we changed" | jq -r '.result'
  • Bash・フック・stdio の MCP サーバーには CLAUDE_CODE_SESSION_ID が渡ります。
  • CLAUDE_CONFIG_DIR と一緒に CLAUDE_CODE_PROJECT_DIR_NAME（英数字・-・_ の 1〜64 文字、起動時の環境のみ、v2.1.234 以降）を設定すると、<project> の名前を固定できます。

コマンド動作

再開で復元されるもの・されないもの

復元される

  • 会話履歴: 圧縮済みなら Conversation compacted の行から開きます。最後の要約、要約されなかったメッセージ、その後のメッセージだけを読み込みます。
  • モデル: 使っていたモデルで続けます（例外は Ch2）。
  • エージェント: --agent か agent 設定で始めたセッションは、そのエージェントのツール制限とモデルを保ちます。元のディレクトリ（信頼済みの場合）、次に再開したディレクトリの順に定義を探し、見つからなければ既定のツールで警告付きで再開します。
  • 権限モード: 経路によります（次スライド）。
  • 有効な /goal: 条件を引き継ぎ、ターン数・経過時間・トークン量はリセットします。
  • 期限内のセッションスコープの予定タスク。背景の Bash と monitor は戻りません。

復元されない

  • 中断したツール呼び出しは再実行されません。
  • 前のプロセスと一緒に終わった背景サブエージェント・背景 Bash・workflow は「完了しなかった」という注記になります。注記からターンは始まりません。
  • 起動フラグの --mcp-config、--settings、--plugin-dir、--fallback-model、--add-dir、セッション中の /add-dir は再指定が必要です。settings.json などの設定ファイルは起動時に読み直します。
  • --system-prompt・--append-system-prompt を変えても、記録済みのプロンプトを圧縮まで使い続けます（--system-prompt-snapshot off で毎回作り直す）。

"Resume this conversation?" ダイアログ

Pro・Max・Ultra で、長い中断の後や別モデルで長い会話を再開すると出ます。見積もりは、保存済みの会話だけで 5 時間の利用上限の何割を使うかです。消費は Resume を選んだ時点ではなく、最初のメッセージを送った時点です。

再開したときの権限モード

再開の経路権限モード
ターミナル: --continue、--resume <id>、一意な名前（-p なし）終了時のモードを復元する（右表の例外あり）。--permission-mode か --dangerously-skip-permissions で上書きできる
claude -p --resume / --continue新しい -p 実行と同じモード。plan だけ条件付きで復元
起動時のピッカー同じコマンドラインで新規に始めたときのモード。plan だけは復元（--permission-mode・--dangerously-skip-permissions・--fork-session を付けると復元しない）
セッション内の /resume現在のモードを引き継ぐ。plan で終わった会話は plan。この実行中に一度開いた会話は現在のモード

deny ルールで ExitPlanMode が消えていると、plan は復元しません。開始時のモードの決まり方は Ch23。

終了時（ターミナル）再開後
bypassPermissions新規セッションのモード。再び使うには起動フラグか、user・--settings・managed の permissions.defaultMode で指定する
planplan。--fork-session 付きなら新規セッションのモード
autoアカウントが auto mode の要件を満たす場合だけ auto
Manual組み込みの既定で auto から始まる環境なら Manual。設定ファイルの defaultMode が効く場合はそのモード

-p の再開が plan を復元する条件（すべて、v2.1.246 以降）:

  • --permission-prompt-tool を渡し、--permission-prompts none を渡さない
  • --permission-mode・--dangerously-skip-permissions・--fork-session を渡さない
  • channels 経由の実行ではなく、ExitPlanMode が deny されていない

ピッカー・名前・/rename

キー動作
↑/↓、k/j移動
→/←グループの展開・折りたたみ
Enter、1〜9選択中、またはその位置のセッションを再開
Space（Ctrl+V）内容のプレビュー
Ctrl+R名前の変更
/ か文字入力検索。PR・MR の URL を貼るとそれを作ったセッションを探す
Ctrl+A / Ctrl+W全プロジェクト / リポジトリの全 worktree へ広げる
Ctrl+B現在の git ブランチに絞る

既定の表示範囲は現在の worktree（背景セッションは bg 印）と、/add-dir でこのディレクトリを加えたセッションです。/branch や --fork-session の分岐は 1 行にまとまり、→ で展開します。

  • 名前の付け方: 起動時 claude -n auth-refactor、実行中 /rename auth-refactor、ピッカーの Ctrl+R、plan の承認、claude.ai（Remote Control、v2.1.221 以降）、Desktop。
  • /rename は引数なしなら履歴から名前を生成します。-p でも使えます。制御文字と不可視文字は空白に置き換え、200 文字で切ります（v2.1.221 以降）。
  • 名前のないセッションにも既定の表示名（例: my-app-3f）が付きますが、実行中の一覧用で、再開には使えません。
  • 生成タイトルは最初のプロンプトを small/fast モデルが要約したもので、再開に使えます。シェルから直接起動した claude -p には付きません。
$ claude -p --output-format json "/rename lab-ctx-name"
"result": "Session renamed to: lab-ctx-name"
$ claude -p -n lab-start-name --output-format json "/rename"
"result": "Could not generate a name: no conversation
context yet. Usage: /rename "

分岐: /branch・--fork-session・/fork・/subtask

手段結果引き継ぐもの・注意
/branch [name]現時点までの会話をコピーし、コピー側へ切り替える。元はそのまま残り /resume で戻れる。名前の既定は最初のプロンプト同じプロセスなので「このセッションで許可」を保つ。実行中の背景サブエージェントと背景 Bash の出力は分岐側に出る。Remote Control も追従する
claude --continue --fork-session
claude --resume <id> --fork-session		新しいセッション ID で再開する。元のトランスクリプトは変わらない別プロセスなので許可は引き継がず、承認し直す。plan mode も復元しない。--session-id <uuid> を併用すると分岐の ID を指定できる
/fork [prompt]会話を新しい背景セッションへコピーし、自分はこのまま作業を続ける（2.1.212 から）コピーは自分の worktree を作るよう指示される（v2.1.221 以降）。agent view が off なら fork サブエージェントを起動する（Ch38）
/subtask <task>会話全体を引き継ぐ背景の fork サブエージェントに作業を渡す結果はこの会話に返る。agent view が off だと使えない（Ch37）
  • /fork は 2.1.77 で /branch に改名され、2.1.212 で背景セッションへのコピーとして再定義されました。それまで /fork が起動していた会話内のサブエージェントは /subtask になりました。
  • 分岐で始まったセッションでは、SessionStart の source が fork です。フォークせずに同じセッションを 2 つのターミナルで再開すると、両方のメッセージが 1 つのトランスクリプトに混ざります。
  • --fork-session を --resume・--continue なしで渡しても、エラーにならず新規セッションとして動きました。 Undocumented

  • CLAUDE_CODE_SKIP_PROMPT_HISTORY を付けたセッションは、--resume・--continue・↑ の履歴に出ません。
  • 背景セッションを claude rm <id> で消しても、トランスクリプトは残ります。ディレクトリ全体の一覧は Ch10。

  • すぐ消すなら claude purge [path]（--dry-run、-y、-i、--all）。トランスクリプト、auto memory、tasks/・debug/・file-history/、history.jsonl の該当行、~/.claude.json の項目を消します。2.1.288 より前は claude project purge でした。

/goal の使い方

/goal all tests in test/auth pass and the lint step is clean
/goal         # 状態を表示
/goal clear   # 早めに解除
  • 条件を設定すると、条件そのものを指示としてすぐにターンが始まります。実行中は ◎ /goal active が表示され、Ctrl+O で評価の理由を読めます。
  • 引数なしは条件・経過時間・評価したターン数・トークン量・直近の理由を表示します。clear の別名は stop・off・reset・none・cancel。
  • 1 セッションに 1 つです。新しい /goal は置き換え、/clear は消します。条件は 4,000 文字まで。
  • 良い条件は、測れる終了状態、証明の方法（例: npm test が exit 0）、変えてはいけないものを含みます。評価モデルはコマンドもファイルも見ません。上限も条件に書きます（例: or stop after 20 turns）。
  • 権限モードは変わりません。無人で回すには auto mode と組み合わせます。
claude -p \
  "/goal CHANGELOG.md has an entry for every PR merged this week"

-p は 1 回の起動でループを完了まで回します。途中経過は --output-format stream-json --verbose で見ます。Ctrl+C で中断できます。

$ claude -p "/goal the file done.txt exists … or stop
  after 4 turns"
Goal set: the file done.txt exists in the current directory
and contains the single word DONE; prove it by running cat
done.txt, or stop after 4 turns

Claude が done.txt を作って cat で示し、評価 1 回で達成した

  • 再開ではどの経路でも有効な goal を戻します（ピッカーは v2.1.239 以降）。達成済み・解除済みは戻りません。
  • フックと同じワークスペース信頼が必要です。disableAllHooks: true や managed の allowManagedHooksOnly では使えず、理由を表示します。

/goal の内部動作

/goal はセッションスコープの prompt 型 Stop フックの包みです。ターンが終わるたびに、条件と会話を small fast モデルへ送り、理由付きの判定を受け取ります。

判定動作
Not yet met理由を指針に次のターンへ
Metgoal を消し、達成エントリを記録
Impossiblegoal を消し、失敗エントリと理由を記録
  • 数ターン続けてツールを使わずに評価へ答えるだけになると、警告を出して止まります。goal は残ります。
  • 直すまで治らないエラー（自前の認証の失敗、クレジット切れ、自動圧縮で解消できない context overflow、使えないモデル）は goal を消し、Goal cleared after an unrecoverable error で始まる警告を出します。
  • それ以外は goal を残します（v2.1.269 以降の対話セッション）。一時的なエラーは Goal still active で 3 回まで再試行し、rate limit・利用上限・フックが終えたターンは Goal paused で止まります。
（トランスクリプトの isMeta ユーザーメッセージ）
A session-scoped Stop hook is now active with condition:
"the file done.txt exists … or stop after 4 turns". Briefly
acknowledge the goal, then immediately start (or continue)
working toward it — … The hook will block stopping until
the condition holds. It auto-clears once the condition is
met — …

（評価後の attachment）
{"type": "goal_status", "met": true, "condition": "…",
 "reason": "…", "iterations": 1, "durationMs": 11881,
 "tokens": 695}

指示文と goal_status はドキュメントに記載がない Undocumented

  • 背景作業の実行中は評価を飛ばします。30 分で確認を入れ、以降 1 時間、その後 2 時間ごとです。間隔は CLAUDE_CODE_GOAL_CHECKIN_MINUTES（既定 30、最大 10080、0 で確認と自動再試行を止める）。アイドル中の自発的な確認は対話セッションだけで、プロンプトの間に 3 回までです。
  • 評価モデルは ANTHROPIC_DEFAULT_HAIKU_MODEL で変わります（haiku エイリアスとタイトル生成にも効く）。

/goal・/loop・Stop フックの使い分け

手段次のターンが始まる時止まる時置き場所と判定
/goal前のターンの終了時。対話セッションではアイドル時の確認や自動再試行の時刻モデルが達成か不可能と判定、直すべきエラー、/goal clear現在のセッションだけ。small fast モデルが判定
/loop指定した間隔が経過したときユーザーが止めるか、Claude が完了と判断セッション内の予定タスク（Ch43）
Stop フック前のターンの終了時自分のスクリプトかプロンプトが決める設定ファイル。そのスコープの全セッションに効く
  • /goal と Stop フックはどちらも毎ターン後に発火します。決定的な検査ならスクリプトの Stop フック、モデルに判定させるなら type: "prompt" の Stop フックか /goal です。
  • auto mode はターン内のツール確認を省き、/goal はターン間の確認を省きます。完了は作業中のモデルではなく、別の評価モデルが判定します。
  • prompt 型 Stop フックのモデルは JSON で答えます。"ok": false なら reason を Claude に返して作業を続けさせ、"impossible": true を添えると停止を許してターンを終えます。
  • Stop フックが、Claude のツール呼び出しを挟まずに 8 回続けてブロックすると、Claude Code はフックを無視して止めます。入力の stop_hook_active を見て早めに抜けます。
