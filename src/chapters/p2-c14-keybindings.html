キーバインド

~/.claude/keybindings.json で、UI のコンテキストごとにキーとアクションの対応を変える仕組みです。この章では、ファイルの構造とコンテキスト、キー表記とコード（連続キー）、変えられないキー・優先関係・検証を扱います。

ファイルの構造とコンテキスト

  • /keybindings が ~/.claude/keybindings.json を作成または開きます。グローバルのみで、保存すると再起動なしで反映します（v2.1.18 で追加）。--safe-mode では読み込みません。
{
  "$schema": "https://www.schemastore.org/claude-code-keybindings.json",
  "$docs": "https://code.claude.com/docs/en/keybindings",
  "bindings": [
    {
      "context": "Chat",
      "bindings": {
        "ctrl+e": "chat:externalEditor",
        "ctrl+s": null
      }
    }
  ]
}
  • アクションは namespace:action 形式です。command:<name> は任意のコマンドを実行し、Chat に "meta+g": "command:compact" と書くと Meta+G で /compact が走ります。

$schema（補完用）と $docs は任意です。bindings の各要素は context と、キー → アクション（または null）の表です。

キーの書き方とコード（連続キー）

種類書き方
Controlctrl control
Shiftshift
Alt / Optionalt opt option meta
Cmd / Win / Supercmd command super win。Super を報告する端末（Kitty キーボードプロトコル、modifyOtherKeys）でだけ検出
特殊キーescape/esc enter/return tab space up down left right pageup pagedown home end backspace delete wheelup wheeldown
  • 修飾キーは + でつなぎます（ctrl+shift+c）。キー名は大文字小文字を区別せず、K は k と同じです。Shift 付きは shift+k と書きます。
  • Ctrl のキー名は配列に関係なくラテン文字で書きます。キリル文字などの配列では、Kitty プロトコルで物理位置を報告する端末に限り US 配列の位置で照合します。AZERTY などは、そのキーが入力する文字で照合します。
  • 既定の割り当てを外すには、アクションを null にします。

コードは空白区切りで書きます（ctrl+k ctrl+s）。各キーは前のキーから 3 秒以内に押し、超えると取り消して通知します。

  • 有効なコンテキストに同じ接頭辞のコードが 1 つでも残ると、接頭辞は予約されたままです。一部だけ外すと、接頭辞を押した時点で次のキー待ちに入ります。
  • ctrl+x を単独キーとして取り戻すには、上の全コードを定義元のコンテキストごとに null にしてから、Chat に "ctrl+x": "chat:newline" などを書きます。

変えられないキー・優先関係・検証

予約キー理由
Ctrl+C / Ctrl+D中断・終了に固定
Ctrl+M / Ctrl+I常に Enter / Tab として届く
Ctrl+[常に Esc（Kitty プロトコルでは v2.1.242 以降）
Ctrl+HASCII のバックスペース。Windows では端末と CLAUDE_CODE_BS_AS_CTRL_BACKSPACE 次第
Caps Lock端末アプリに届かない
  • 端末側との衝突: Ctrl+B（tmux の prefix。2 回押す）、Ctrl+A（GNU screen）、Ctrl+Z（SIGTSTP）。
  • アクションが無く変えられないもの: 単語系の編集キー、vim のキー、フルスクリーンの履歴検索ダイアログの Enter/Tab/Esc、/effort スライダーの Enter/Esc。
  • 検証の警告は --debug のログに出ます（構造の誤り、不正なコンテキスト、予約キーとの衝突、同一コンテキスト内の重複など）。ctl+k は k に割り当てられ、ctrl+ k は発火しないコードになります。未知のアクションはその行を飛ばし、既定を残します。

優先関係

  • agent view（Preview）では Agents の割り当てが、同じキーの Chat・Global より勝ちます（Ctrl+S は stash ではなくグループ切り替え）。
  • ダイアログ内のテキスト欄では、修飾なしの印字キーは文字になります。非印字キー、修飾キー付き、コードの 2 打目は割り当てどおり動きます。
  • フッター項目の選択中は、Chat で Enter を変えていても Enter で開きます。
  • Confirmation に裸の文字を割り当てると、その文字を表示しないダイアログにも効きます。y/n の既定割り当ては v2.1.280 で外れましたが、それ以前に生成したファイルには残ります。

旧名と無効なアクション

  • 旧名 messageSelector:*・diff:viewDetails（v2.1.283 より前）は対応する select:* として動きます。confirm:previousField・permission:toggleDebug・footer:dismiss は何もしませんが、書いても有効です。
