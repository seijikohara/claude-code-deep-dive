ヘッドレス実行（-p）

claude -p でスクリプトや CI から Claude Code を動かす方法です。この章では、print モードで使うフラグ、実測した終了コードと result JSON、--bare などの分離モード、stream-json のイベント、無人実行の権限、システムプロンプトとセッションの扱いを扱います。

全体像: -p が何をして、何をしないか

  • -p（--print）は、非対話で 1 ターンを実行し、結果を出力して終了します。docs は「CLI から使う Agent SDK」と位置づけています。
  • stdout が TTY でない場合も、-p なしで非対話モードになります（--help）。
  • 標準入力はプロンプトの文脈として読み込まれます。パイプ入力の上限は 10MB で、超えると非ゼロで終了します。
  • ワークスペースの信頼ダイアログは出ません。検証に失敗した設定ファイルは、エラーを出さずに無視されます（--help）。
  • --bare がない場合、未信頼のフォルダでも、プロジェクトの .claude/settings.json のフックと .mcp.json のサーバーが動きます。サーバーごとの承認もありません。
  • --bg と、タスク文付きの --cloud はエラーで拒否されます。セッション ID 付きの --cloud は、そのクラウドセッションにメッセージを積んで終了します（Ch50）。

-p でのスラッシュコマンド

  • ユーザーが呼び出す skill とカスタムコマンドは使えます。プロンプトに /skill-name を含めます。
  • /login など、端末 UI 専用の組み込みコマンドは使えません。
  • /model・/effort・/fast・/color・/rename は、/model sonnet のように値を引数で受け取ります。
  • 設定の変更は /config thinking=false の形です。/output-style は v2.1.269 以降です。実測の一覧は Ch7 と Ch12 です。
Warning: no stdin data received in 3s, proceeding

stdin にデータが 3 秒届かないと、この警告を出して先に進みます。CI では < /dev/null を付けます。

init イベントを CI ゲートに使う（実測）

  • --mcp-config の各エントリは起動時に検証され、不正なものは飛ばされます。実行は続き、正常終了します。
  • 端末なら stderr に Warning: 1 MCP server skipped due to invalid config: が出ます。CI や SDK ホストが stderr を捕まえると、mcp_server_errors にだけ残ります。
  • plugin_errors・mcp_server_errors は、エラーがないときキーごと省かれます。
  • mcp_server_errors の type は unknown_type・url_missing_type・invalid_config・reserved_name など。未知の値もスキップ扱いです。
  • キャッシュ済みツール一覧を持つリモートサーバーは pending のまま載ります。機能の判定は capabilities 配列で行います。
  • --safe-mode の init でも plugins には "path": "builtin" の組み込みプラグインが並びます。「空であること」は条件にできません。
  • init の主なキー（実測）: tools・mcp_servers・model・permissionMode・slash_commands・agents・skills・plugins・capabilities ほか（Ch21・Ch12）。

無人実行の権限（実測）

  • モード未指定の -p は、v2.1.302 以降 Manual（設定値は default）で始まります。2.1.285〜2.1.301 は、サードパーティのプロバイダやテレメトリ無効時に auto で始まりました（Ch23）。
  • Manual の -p では、承認が要る呼び出しは拒否されます。承認できるのは allow ルール、PermissionRequest フック、--permission-prompt-tool です。
  • --allowedTools は権限ルール構文です。Bash(git diff*) は git diff-index にも一致するため、* の前に空白を入れます。auto で始まる実行では素の Bash が捨てられます。
  • dontAsk: 確認になる呼び出しをすべて拒否します。AskUserQuestion、組織が ask にしたコネクタ、requiresUserInteraction の MCP ツール、ネットワークパスの読み取りは、allow ルールがあっても拒否です。
  • --permission-prompts none: ホスト（canUseTool・プロンプトツール）に問い合わせず待ちません。AskUserQuestion を外し、未応答の elicitation を取り消します。ルール・フック・モードが先に判定します。
claude -p "Update the dependency pins and run the tests" \
  --permission-mode auto --permission-prompts none
$ claude -p --permission-prompts none \
    --output-format stream-json --verbose \
    "Use the Write tool to create a file named out.txt …"

フラグ動作

--append-system-prompt既定のプロンプトに追記する

  • 5 つとも対話・非対話の両方で使えます。-file の 2 つは --help に単独の行がありません。
  • 置き換えと追記は併用できます。v2.1.283 以降は文字列形とファイル形も併用でき、ファイル、空行、文字列の順に並びます。置き換えると git status のスナップショットも付きません。
  • 置き換え文の __SYSTEM_PROMPT_DYNAMIC_BOUNDARY__ だけの行で、キャッシュする静的部と動的部を分けます（v2.1.275 以降）。

記録（スナップショット）の規則

  • プロンプトは会話の最初のリクエストで組み立てて記録し、圧縮まで再利用します。--resume・--continue で別のフラグを渡しても、効くのは圧縮後か新しい会話からです。文言を詰める間は off にします。
  • --bare（または CLAUDE_CODE_SIMPLE=1）では、クラウドセッション以外で記録が off です。on を渡すと記録します。
  • v2.1.265 より前は、フラグを渡すと記録が off でした。v2.1.268 より前は、feature flag を取得しないセッション（Bedrock など）で常に再構築でした。
  • off は 2.1.267 から（changelog）。フラグ自体は docs 上 v2.1.257 以降です。
claude -p --append-system-prompt-file ./style.md --append-system-prompt "Always reply in French" "Summarize README.md"

セッションと実行の終わり方

  • --continue: このディレクトリの最新の会話を開きます。対話モードは -p・SDK・/loop のセッションを飛ばしますが、claude -p --continue は含めます。v2.1.257 以降は終了済みのバックグラウンドセッションも対象です。
  • --resume: ID・名前・.jsonl の絶対パスを受け取ります。ID は現在のプロジェクトと worktree、次に全プロジェクトから探します（v2.1.223 以降）。
  • --fork-session は新しい ID に分岐し、--session-id は ID を先に決めます（Ch7）。ファイルの巻き戻しは SDK の rewindFiles() です（Ch45）。

バックグラウンド処理の待ち

  • ターン終了後も、Claude が始めたバックグラウンドのコマンド・サブエージェント・ワークフロー・Monitor・/loop の wakeup を待ちます。MCP タスクは待ちません。
  • 連続 10 分の待機で残りを止めます（CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS、0 で無制限）。メインが始めたコマンドの実行中は、この上限で止まりません。

SIGTERM

  • 終了コード 143 です。Bash のプロセスツリーを止め、SessionEnd フックだけを実行します。
  • ターンを終えるには先に SIGINT か SDK の interrupt() を送ります。再開時に続けるには CLAUDE_CODE_RESUME_INTERRUPTED_TURN=1 です。
session_id=$(claude -p "Start a review" --output-format json | jq -r '.session_id')
claude -p "Continue that review" --resume "$session_id"
