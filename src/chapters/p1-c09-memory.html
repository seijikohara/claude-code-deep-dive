メモリ

Claude Code は、自分で書く CLAUDE.md と Claude が書く auto memory の 2 系統で、セッションをまたいで知識を引き継ぎます。この章では、CLAUDE.md のスコープと読み込み順、オンデマンド読み込みとサイズ上限、@path インポート、.claude/rules、AGENTS.md、組織向けの制御、auto memory、/memory を扱います。読み込み順と条件は、2 階層のフィクスチャで -p を実行して確かめました。

サブディレクトリのオンデマンド読み込みとサイズ上限

  • 作業ディレクトリより下の CLAUDE.md・CLAUDE.local.md は起動時に読みません。Claude がそのサブディレクトリのファイルを読む・書く・編集したときに 1 回だけ読みます。
  • 単一ファイルへの cat・head など、読み取りとみなす Bash コマンドも対象です。Bash での読み取りは 2.1.293、Write・Edit は 2.1.288 で修正されました。
  • 読み込むとターミナルに Loaded 行とパスが出ます。起動時のファイルではないため、/context all の Memory files には出ません。試すときはシェルでファイルを作り、Claude にそのディレクトリのファイルを読ませます。
  • ブロック単位の HTML コメント（<!-- maintainer notes -->）は、注入前に取り除かれます。コードブロック内のコメントと、Read ツールで開いたときの表示は残ります（2.1.72）。
  • /compact の後、ルートの CLAUDE.md はディスクから読み直して再注入されます。サブディレクトリの分と paths 付き rule は、必要時にまた読みます（Ch6）。
対象上限超えたとき
起動時に読む CLAUDE.md推奨 200 行未満。上限 4 MiB推奨の長さを超えると起動時と /status で警告（しきい値はウィンドウで変わる）。4 MiB 超えは読まない
起動時のファイルの合計合計の上限（値は記載なし）警告。CLAUDE.md・rule・import を各 1 ファイルと数える
サブディレクトリの CLAUDE.md とその import、サブディレクトリの rules、paths 付き rule200K ウィンドウ: 40,000 文字。1M: Opus 4.6・Sonnet 4.6 は 200,000、以降は 150,000 文字先頭だけ渡し、残りは Read で読むよう注記する（2.1.309 から）
  • 文字数は wc -m path/to/CLAUDE.md で確かめます。/doctor は、commit 済みの CLAUDE.md からコードで導ける内容を削る案を出します。
  • /doctor prompt-audit [path]（v2.1.283 以降）は、古いモデル向けの指示、存在しないファイルへの参照、矛盾を報告し、頼むまで変更しません。/claude-api Skill が無効だと使えません。

.claude/rules/ と paths（1/2）: 読み込み条件とパターン

your-project/
├── .claude/
│   ├── CLAUDE.md           # Main project instructions
│   └── rules/
│       ├── code-style.md   # Code style guidelines
│       ├── testing.md      # Testing conventions
│       └── security.md     # Security requirements
  • .claude/rules/ 配下の .md を再帰的に探します。frontend/ などのサブディレクトリに分けられます。
  • paths の無い rule は、.claude/CLAUDE.md と同じ優先度で起動時に読みます。
  • paths 付きの rule は、Claude が一致するファイルに Read・Write・Edit を使ったときと、単一ファイルの cat・head などで読んだときに読みます。プロジェクトへの symlink 経由のパスでも一致します。
  • パターンの基準は、プロジェクトの rule では .claude を含むディレクトリ、~/.claude/rules/ ではセッションの主作業ディレクトリです。
---
paths:
  - "src/**/*.{ts,tsx}"
  - "lib/**/*.ts"
  - "tests/**/*.test.ts"
---
パターン一致するもの
**/*.ts基準ディレクトリ配下のどこかの .ts
src/**/*基準の src/ 配下のすべて
*.md基準ディレクトリ配下のどこかの .md
/*.md基準ディレクトリ直下の .md だけ
src/components/*.tsxその直下の .tsx だけ（サブフォルダは含まない）

兄弟の git worktree のファイルに rule を効かせるには、その worktree で起動するか、/cd でセッションを移します。

.claude/rules/（2/2）: 境界条件・ユーザー rule・symlink

  • frontmatter: rule で読むのは paths だけです。他のフィールドはエラーなしで無視し、frontmatter は読み込む前に取り除きます。paths は YAML のリストでもカンマ区切りの文字列でも書けます。
  • YAML が解析できないと frontmatter を無視し、paths の無い rule として起動時に読みます。解析エラーは claude --debug で見えます。
  • ブレース展開: src/*.{ts,tsx} は 2 パターン、{a,b}/{c,d}/*.{ts,tsx} は 8 パターンに展開します。1 つの rule の paths 全体で 1,000 パターン・4 MiB の予算を共有し、ブレースの無いパターンは数えません。予算を超えるパターンは展開せずに使うため、括弧が文字どおり残って何にも一致しません。
  • [: 括弧式として読めない photos [2024/** は無効で何にも一致しません（同じ rule の他のパターンは有効）。文字の [ は photos \[2024/** と書きます。
  • ユーザー rule: ~/.claude/rules/ は全プロジェクトに効き、プロジェクトの rule より先に読みます。どちらも上書きはしないため、矛盾すると Claude はどちらにも従いえます。
  • --setting-sources から project を外すと、プロジェクトの rule は読みません。2.1.211 より前は、オンデマンドの rule だけは読まれていました。
  • symlink: 共有の rule を各プロジェクトにリンクできます。循環リンクは検出します。リンク先が作業ディレクトリの外なら外部インポートと同じ扱いで、承認後も paths の無い rule だけを読みます。承認なしで共有するなら ~/.claude/rules/ に置きます。
  • UNC 共有 \\server\share や /net・/Network 配下を指す CLAUDE.md・rules の symlink はたどりません。\\wsl$ はネットワークパスに含めません。
ln -s ~/shared-claude-rules .claude/rules/shared
ln -s ~/company-standards/security.md .claude/rules/security.md

  • symlink 経由の rule は、.claude/rules/ 側のパスとリンク先のどちらに一致しても除外されます（2.1.239 より前はリンク先だけ）。

    • Linux・WSL: /etc/claude-code/CLAUDE.md
    • Windows: C:\Program Files\ClaudeCode\CLAUDE.md
  • ファイルの代わりに、managed settings の claudeMd キーに本文を書けます。user・project・local 設定に書いても効きません。
  • どちらも user・project の CLAUDE.md より先に読みます。claudeMdExcludes では外せません。
  • CLAUDE.md の読み込み自体を止めたセッションでは、managed の内容も読まれません。強制したい規則は managed settings の permissions.deny などに置きます。
  • omitClaudeMd: true のサブエージェントも managed の CLAUDE.md は読みます（定義が managed settings にある場合を除く）。
  • server-managed settings の claudeMd は、2.1.260 から承認ダイアログを出しません。

auto memory（1/2）: 保存するもの・場所・読み込み

Claude は作業しながら 4 種類のメモを残し、種類を frontmatter の type に記録します。

type中身
userユーザーの役割、専門、作業上の好み
feedback受けた訂正と、確認された進め方
project進行中の作業、期限、コードや git 履歴から導けない決定
referenceIssue トラッカーやダッシュボードなど、外部情報の場所

コードから導けること（構成、ファイルパス、デバッグの修正）と CLAUDE.md に書いてあることは保存しません。毎セッション保存するわけでもありません。

~/.claude/projects//memory/
├── MEMORY.md           # Index, one line per memory, …
├── user_role.md        # One memory
├── feedback_testing.md # One memory
└── ...                 # Any other topic files Claude creates
  • <project> は git リポジトリから決まり、同じリポジトリの worktree とサブディレクトリで共有します。git の外ではプロジェクトのルートです。マシン間では共有しません。
  • 起動時に読むのは MEMORY.md の先頭 200 行または 25KB の早い方だけです。トピックファイルは、Claude が必要なときに通常のファイルツールで読みます。
  • 上限に近づくと短くするよう促し、超えると書き込みは成功させてエラーを返します（2.1.210 から）。frontmatter と HTML コメントは計測しません。
  • エラー例（docs）: Error: this write left the memory index at MEMORY.md at 214 lines, over its 200-line read limit. … Rewrite it to under 140 lines now: …
  • 書き込み時に frontmatter の modified へ ISO 8601 の時刻を記録します。Saved 2 memories・Recalled 2 memories の表示は、ここへの読み書きです。
  • メイン会話の auto memory は、fork 以外のサブエージェントに渡りません（自前のメモリは memory フィールド、Ch37）。
