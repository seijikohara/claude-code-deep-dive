Hooks

33 イベントの設定・入出力・決定制御・非同期実行・安全性を扱います（全件表は 付録 D）。

全体像: イベント・matcher グループ・ハンドラの 3 階層

  • フックは、ライフサイクルの決まった時点で自動実行される処理です。ターミナル・IDE 拡張・Desktop・クラウドセッションで、同じイベントが発火します。
  • 設定は 3 階層です。hook event（発火点）の下に matcher group（絞り込み）を置き、その下に hook handler（実行内容）を並べます。
  • ハンドラの型は 5 種類です: command・http・mcp_tool・prompt・agent。agent だけが Experimental です。
  • 解決の順序は、イベント発火、matcher の照合、ハンドラごとの if の照合、ハンドラの起動、結果の適用です。
  • exit 0 で何も出力しないフックは「判断なし」で、通常の権限フローに進みます。黙っていても承認にはなりません。
  • プラグインの JavaScript 関数フック（mod）は別の仕組みで、本章のフックと併用できます（Ch33）。
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "if": "Bash(rm *)",
            "command": "${CLAUDE_PROJECT_DIR}/.claude/hooks/block-rm.sh",
            "args": []
          }
        ]
      }
    ]
  }
}

matcher で Bash に絞り、if で rm のサブコマンドにさらに絞る例です。block-rm.sh は rm -rf を含むときだけ deny の JSON を返し、それ以外は exit 0 で判断を返しません。

ライフサイクル: 発火の順序と 3 つの周期

セッション内の順序

  1. Setup（--init-only、または -p で --init・--maintenance のときだけ）
  2. SessionStart
  3. ターン開始: UserPromptSubmit、コマンド入力なら UserPromptExpansion
  4. ツール呼び出しごと: PreToolUse、PermissionRequest、PostToolUse または PostToolUseFailure。並列バッチの後に PostToolBatch
  5. ループの中: SubagentStart/SubagentStop、TaskCreated/TaskCompleted、MCP ツール実行中の Elicitation/ElicitationResult、auto mode の拒否で PermissionDenied
  6. ターン終了: Stop（API エラーなら StopFailure）、TeammateIdle
  7. PreCompact、PostCompact、最後に SessionEnd

流れの外で発火するもの

種類イベント
単独・非同期Notification ConfigChange InstructionsLoaded CwdChanged FileChanged DirectoryAdded WorktreeCreate WorktreeRemove
単独・逐次PreModelSwitch（要求されたモデル切替の適用前）
単独・非同期PostModelSwitch（モデルが変わった後）
表示専用MessageDisplay（アシスタント本文の表示中）

3 つの周期

  • セッションごと: SessionStart、SessionEnd
  • ターンごと: UserPromptSubmit、Stop、StopFailure
  • ツール呼び出しごと: PreToolUse、PostToolUse。EndConversation の呼び出しはどちらも発火しません。

matcher の評価規則と、MCP・Monitor の照合

matcher の値評価のしかた例
"*"、""、省略すべてに一致そのイベントの発生ごとに発火
英数字・_・-・空白・,・| だけ完全一致。| か , で複数指定（前後の空白は可）Edit|Write と Edit, Write はどちらも 2 つのツールに完全一致
それ以外の文字を含むJavaScript の正規表現（アンカーなし）^Notebook、mcp__memory__.*
  • 正規表現は RegExp.prototype.test で評価し、値のどこかに一致すれば成立します。Edit.* は NotebookEdit にも一致するので、完全一致には ^Edit$ と書きます。
  • FileChanged と StopFailure は、完全一致とみなす文字が英数字・_・| だけです。-・空白・, を含むと正規表現扱いになります。
  • matcher に対応しないイベントに書いた matcher は、黙って無視されます。照合は大文字と小文字を区別します。
  • 照合対象はイベント一覧に、値は各イベントのスライドにあります。
  • MCP ツール名は mcp__<server>__<tool> です。サーバー単位で拾うには .* が必須です。mcp__memory は完全一致扱いになり、どのツールにも一致しません。
  • プラグイン同梱サーバーのツールは mcp__plugin_<plugin-name>_<server-name>__<tool> です。素のサーバーキーで書いた matcher は発火しません。
  • v2.1.314 以降、PreToolUse・PermissionRequest の Bash matcher（Bash|PowerShell、^Bash$、Bash.* を含む）は Monitor のシェルコマンドにも動きます。ただし allow と updatedInput は効きません。
  • Monitor を許可・書き換えするには、matcher を Bash|Monitor・.*・省略にし、if に Monitor(tail *) のように書きます。
出典: hooks#matcher-patterns · #match-mcp-tools · #match-monitor-commands · hooks-guide#hook-not-firing

if フィールド: ハンドラ単位の権限ルール照合

  • if は権限ルール構文で、ツール名と引数をまとめて照合します（例: "Bash(git *)"、"Edit(*.ts)"）。一致しなければハンドラのプロセスを起動しません。
  • 評価するのはツールイベント（PreToolUse PostToolUse PostToolUseFailure PermissionRequest PermissionDenied）だけです。他のイベントで if を書いたハンドラは一度も実行されません。
  • 書けるルールは 1 つです。&&・||・リストはないので、条件ごとにハンドラを分けます。Bash と PowerShell も、Bash(rm *) と PowerShell(Remove-Item *) の 2 ハンドラに分けます。
  • "Edit(src/**)" は作業ディレクトリ直下の src だけに一致します。どの深さにも一致させるなら "Edit(**/src/**)" です。
if のパターンBash コマンド実行理由
Bash(git *)FOO=bar git pushする先頭の代入は除いて照合する
Bash(git *)npm test && git pushするサブコマンドごとに照合し、git push が一致
Bash(rm *)echo $(rm -rf /)する$() とバッククォートの中も照合する
Bash(rm *)echo $(date)しないrm * に一致するサブコマンドがない
Bash(git push *)echo $(date)するコマンド名より詳しいパターンは、$()・バッククォート・$VAR があれば実行する

Bash の入力が何を実行するか判定できないときは、パターンに関係なくフックを実行します。if はベストエフォートなので、確実な許可・拒否には権限ルールを使います。

出典: hooks#common-fields · #bash-if-matching · #how-a-hook-resolves

once任意true なら最初の成功後に削除。失敗・exit 2・タイムアウトでは残る。skill の frontmatter でだけ有効で、settings と agent の frontmatter では無視

command フック: フィールドと exec form・shell form

フィールド内容
command必須。シェルに渡す文字列。args があるときは起動する実行ファイル
args引数の配列。あればシェルを介さずに直接起動する（exec form）
asynctrue でバックグラウンド実行
asyncRewakeバックグラウンド実行し、exit 2 で Claude を起こす。stderr（空なら stdout）を system reminder で渡す
shell"bash" か "powershell"。既定は bash（Git Bash のない Windows は powershell）。args があると無視
onFailure"continue" か "block"。v2.1.295 以降
 
{
  "type": "command",
  "command": "node",
  "args": ["${CLAUDE_PLUGIN_ROOT}/scripts/format.js", "--fix"]
}
  • exec form（args あり）: command を PATH から解決して直接起動します。args の各要素がそのまま 1 引数になり、$・バッククォート・アポストロフィも解釈されません。
  • shell form（args なし）: macOS と Linux は sh -c、Windows は Git Bash（なければ PowerShell）で実行します。パイプ・&&・リダイレクト・glob が使えます。
  • パスのプレースホルダを使うなら exec form を推奨します。shell form では二重引用符で囲みます。
  • どちらの形式も CLAUDE_PROJECT_DIR・CLAUDE_PLUGIN_ROOT・CLAUDE_PLUGIN_DATA を環境変数として渡します。
  • プラグインの ${user_config.*} は exec form でだけ置換されます。shell form で参照するとエラーになり、実行されません（v2.1.207 より前は置換）。shell form では $CLAUDE_PLUGIN_OPTION_<KEY> を読みます。
  • Windows の exec form には実際の実行ファイルが必要です。node_modules/.bin の .cmd・.bat は起動できないので、node とスクリプトのパスで呼びます。

http フック: POST とレスポンスの扱い

フィールド内容
url必須。POST 先の URL
headers追加ヘッダー。値に $VAR_NAME・${VAR_NAME} を展開できる
allowedEnvVarsヘッダーに展開してよい環境変数名。載っていない変数は空文字になる
onFailure"continue"（既定）か "block"。v2.1.295 以降
レスポンス結果
2xx・本文なし成功（exit 0・出力なしと同じ）
2xx・JSON オブジェクトcommand と同じスキーマで解析。検証失敗は非ブロッキングエラー
2xx・その他の本文非ブロッキングエラー。本文は Claude に渡らない
非 2xx・接続失敗非ブロッキングエラー
タイムアウト取り消し

mcp_tool フック: 設定済み MCP サーバーのツールを呼ぶ

フィールド内容
server必須。設定済み MCP サーバー名。プラグイン同梱なら plugin:<plugin-name>:<server-name>
tool必須。呼び出すツール名
inputツールの引数。文字列値でフック入力 JSON の ${path} を置換できる
  • ツールのテキスト出力は、command の stdout と同じ規則で読みます。isError: true は非ブロッキングエラーです。
  • 止める・変えるイベント（PreToolUse、Stop など）では、接続中のサーバーを MCP_TIMEOUT と timeout の範囲で待ちます。観測用のイベント（Notification など）では待ちません。

{
  "hooks": {
    "PostToolUse": [

        "matcher": "Write|Edit",

}

prompt フック: 1 回の LLM 判定

フィールド内容
prompt必須。$ARGUMENTS が入力 JSON に置き換わる。なければ末尾に追加。\$1.00 で $ をそのまま書く
model既定はバックグラウンド処理用のモデル
timeout既定 30 秒
continueOnBlock既定 false。true なら ok: false の理由を Claude に返してターンを続ける

LLM は次の JSON を返します。reason は ok: false のとき必須です。impossible は Stop・SubagentStop でだけ有効で、条件が満たせないと判断したときにターンを終えさせます。

{
  "ok": true | false,
  "reason": "Explanation for the decision",
  "impossible": true | false
}

ok: false の効果

  • Stop・SubagentStop: 理由を次の指示として渡し、続行（impossible: true なら停止を許可）
  • PreToolUse: 呼び出しを拒否し、既定ではターンを終えて警告行を出す。continueOnBlock: true なら理由をツールエラーとして返す
  • PostToolUse: 既定ではターンを終える。continueOnBlock: true なら理由を返して続行
  • PostToolBatch・UserPromptSubmit・UserPromptExpansion: ターンを終える
  • PostToolUseFailure・TaskCreated: 理由をツールエラーとして返し、続行
  • TaskCompleted: タスク完了の経路はツールエラーで続行。チームメイト停止の経路は TeammateIdle と同じ
  • TeammateIdle: 既定でチームメイトを止める。continueOnBlock: true なら作業を続けさせる
  • PermissionRequest・PermissionDenied: 効果なし
出典: hooks#prompt-based-hooks · #response-schema · #prompt-and-agent-hook-fields

agent フック: ツールで確かめる検証エージェント Experimental

  • ドキュメントは「experimental で、挙動と設定は今後変わりうる。本番では command フックを推奨」と明記しています。
  • Read・Grep・Glob などのツールを使えるサブエージェントを起動し、最大 50 ターンで { "ok": true/false } を返させます。
  • 設定は prompt フックと同じです。既定のタイムアウトは 60 秒で、continueOnBlock と impossible はありません。

  • 出力を捨てるイベント（StopFailure など）は、どの終了コードでも JSON を無視します。terminalSequence だけは効きます。

PreToolUse (2/2): allow の限界と defer

allow で省けない確認

  • どのモードでも自動承認されない操作、ネットワークパスからの読み取り、SDK が always_ask を付けたツール、requiresUserInteraction 付きの MCP ツール
  • AskUserQuestion・ExitPlanMode は allow だけでは足りません。updatedInput に回答を入れて返します。
  • plan mode でのファイル編集の allow は、フックがないときと同じ扱いです。
  • 逆に deny は、bypassPermissions を含むすべてのモードで効きます。PreToolUse は dontAsk を含むモード判定より先に発火します。詳しい優先関係は Ch22。
  • auto mode で permissionDecision なしの updatedInput を返すと、a hook changed this call's input after auto mode reviewed it で拒否されることがあります（Ch24）。

"defer": 呼び出しを保留して後で再開

  • -p で、そのターンのツール呼び出しが 1 つのときだけ有効です。対話セッションや複数呼び出しでは警告を出して無視します。
  • 結果は stop_reason: "tool_deferred" と deferred_tool_use（id・name・input）です。
  • 呼び出し側は同じ permission host で claude -p --resume <session-id> を実行し、再発火したフックが allow と updatedInput を返します。
  • タイムアウトや再試行の上限はありません。セッションは cleanupPeriodDays（既定 30 日）まで残ります。
  • 再開時にツールが無いと tool_deferred_unavailable になります。CLAUDE_CODE_DROP_UNAVAILABLE_DEFERRED_TOOL=1 で破棄できます（v2.1.319 で挙動変更）。

PostToolUseFailure・PostToolBatch・PermissionDenied

PostToolUseFailure

  • 実行を始めたツールが失敗したとき（例外、MCP のエラー結果）に発火します。
  • 検証エラー・未知のツール・権限拒否では発火しません。
  • 入力: error、is_interrupt、duration_ms。Bash の error は先頭行が Exit code N で、長いと中間が省略されます。
  • 出力: additionalContext

PostToolBatch

  • 並列バッチの全呼び出しが解決した後、次のモデル呼び出しの前に 1 回だけ発火します。matcher はありません。
  • tool_calls[] の tool_response は、モデルが見る tool_result の内容（直列化文字列かコンテンツブロック配列）です。PostToolUse の構造化出力とは形が違います。
  • additionalContext は 1 回だけ注入されます。decision: "block"・continue: false・exit 2 で、次のモデル呼び出しの前にループを止めます。

PermissionDenied

  • auto mode の拒否（判定なしの拒否を含む）でだけ発火します。手動の拒否、PreToolUse のブロック、deny ルールでは発火しません。
  • reason の例: [Data Exfiltration]、Classifier unavailable
  • retry: true で「再試行してよい」とモデルに伝えます。拒否は覆りません。判定なしの拒否では無視されます。

    "retry": true

UserPromptSubmit・UserPromptExpansion・タスク系イベント

  • UserPromptSubmit の入力は prompt と session_title です。/deploy staging のようなコマンドは展開前の文字列で届きます。貼り付けは展開済みで、<pasted_content id="…"> 行で囲まれることがあります。

  • ブロック時のメッセージは既定で Original prompt: と本文を含み、トランスクリプトに残ります。suppressOriginalPrompt: true で外せますが、プロンプト履歴などには残ります。

  • TaskCompleted: TaskUpdate での完了時と、チームメイトが進行中のタスクを残して終えたときに発火します。exit 2 で完了にせず、stderr をモデルに返します。continue: false はチームメイト経路でだけ停止です。

  • 対話セッションの起動と /clear ではバックグラウンドで動きます。すぐ入力できますが、最初の応答はフックの完了を待ちます。
  • 入力: source、model（省略あり）、agent_type、session_title。resume・fork で応答が 1 つ以上あれば seconds_since_last_response・context_tokens・prompt_cache_likely_expired・estimated_cache_write_usd も届きます（v2.1.251 以降）。
  • 出力: additionalContext（プレーン stdout も可）、initialUserMessage（-p のみ。プロンプトなしでも最初のターンになる）、sessionTitle、watchPaths、reloadSkills（フック後に skill を再走査）
  • CLAUDE_ENV_FILE に export 文を追記すると、以後の Bash コマンドに反映されます。

Setup

  • --init-only（matcher init）、-p --init（init）、-p --maintenance（maintenance）でだけ発火します。入力は trigger です。
  • --init-only は Setup と startup の SessionStart を実行して終了し、何も表示しません。
  • JSON は終了コードに関係なく捨てられます。-p では stream-json の hook_response でだけ見えます。実行されるのは command だけです。

SessionEnd

  • reason: clear、resume、logout、prompt_input_exit、other。bypass_permissions_disabled は v2.1.234 で廃止。
  • 予算は合計 1.5 秒です。settings の per-hook timeout の最大値まで（上限 60 秒）延び、プラグインのフックの値は数えません。CLAUDE_CODE_SESSIONEND_HOOKS_TIMEOUT_MS で明示でき、v2.1.268 以降は各フックの既定にもなります。
出典: hooks#sessionstart · #setup · #sessionend · #persist-environment-variables

PreModelSwitch・PostModelSwitch・PreCompact・PostCompact

  • PreModelSwitch（v2.1.251 以降）は、/model、Option+P/Alt+P のピッカー、/config の Model、モデルが変わる fast mode の有効化、SDK の set_model・apply_flag_settings で発火します。自動フォールバックと再開時の復元では発火しません。
  • matcher は切替先の正規名で、[1m] は無視します。正規名を決められないモデルでは全フックが動くので、ブロックするフックは入力の to_model も確かめます。
  • 入力: from_model、to_model、requested_model、source（command・picker・sdk）、context_tokens、prompt_cache_warm、cache_ttl、estimated_cache_write_usd、pricing
  • exit 2 か decision: "block" で取り消します。permissionDecision の allow はキャッシュが温かいときの確認を省きます。ask を出せるのは対話の /model だけで、他では拒否扱いです。優先は deny > ask > allow、タイムアウト（既定 30 秒）も取り消しです。
  • PostModelSwitch は、要求された切替、自動フォールバック、opusplan の plan mode 出入り、再開時の復元の後に発火します。1 ターンだけのフォールバックチェーンでは発火しません。source に auto・resume が加わります。
  • exit 0 の stdout か additionalContext は次のリクエストで届きます。次のプロンプトから 5 秒以内に終わらなければ、その次のリクエストに回ります。
  • PreCompact の matcher は manual（/compact）と auto（auto-compact とアイドル圧縮）です。入力は trigger と custom_instructions（auto では null）です。
  • exit 2 か decision: "block" で圧縮を止めます。事前の自動圧縮なら圧縮せずに続行し、上限エラーからの回復なら元のエラーでリクエストが失敗します。
  • exit 0 の stdout は要約への指示になり、10,000 文字で切られます。PostCompact は compact_summary を受け取るだけです。実測の発火順は Ch6。
出典: hooks#premodelswitch · #postmodelswitch · #precompact · #postcompact

ConfigChange・InstructionsLoaded・CwdChanged・DirectoryAdded・FileChanged

イベント発火と入力出力と制御
ConfigChangesettings、managed-settings.json・managed-settings.d/、skill ファイルの変更。matcher は user_settings project_settings local_settings policy_settings skills。入力 source・file_pathexit 2 か decision: "block" で新設定を適用しない。何も表示されず、デバッグログにだけ残る。policy_settings は止められない。サーバー管理設定では発火しない
InstructionsLoadedCLAUDE.md・.claude/rules/*.md の読み込み（起動時と遅延読み込み）。matcher は load_reason（session_start nested_traversal path_glob_match include compact）。入力 file_path memory_type globs trigger_file_path parent_file_path制御なし。観測用に非同期で動く。Project instructions 設定で直接読む AGENTS.md では発火しない

WorktreeCreate・WorktreeRemove・Elicitation・ElicitationResult

  • WorktreeCreate は --worktree、EnterWorktree、サブエージェントの isolation: "worktree"、ワークフロー、バックグラウンドセッション、claude remote-control の worktree モードで発火します。Bash の git worktree add では発火しません。
  • フックを置くと git の既定処理を置き換え、.worktreeinclude も処理されません。入力は name です。
  • command フックは stdout の最後の空でない行でパスを返します（ANSI は除去）。HTTP は hookSpecificOutput.worktreePath です。失敗かパスなしなら作成失敗です。.・.. を含む絶対パスと、リポジトリ内の symlink を通るパスは拒否されます。
  • WorktreeRemove は入力 worktree_path を受け、exit 0 で削除済みとみなします。ブランチは削除しません。サブエージェントとワークフローの worktree では発火しません。
  • Elicitation は exit 0 で action を返すと、ダイアログを出さずに答えます: accept（content に値）、decline、cancel。出力なしなら通常のダイアログです。
  • exit 2 か最上位 decision: "block" は decline です。複数のフックでは、どれか 1 つの decline が accept・cancel より優先します。
  • URL モードで accept を返すと、URL は開かれません。
  • ElicitationResult は、Elicitation フックが答えた場合は動きません。返した content は元の content 全体を置き換えます。
  • ユーザーが decline・cancel した応答でも動くので、入力の action が accept か確かめてから accept を返します。
{
  "hookSpecificOutput": {
    "hookEventName": "Elicitation",
    "action": "accept",
    "content": {
      "username": "alice"
    }
  }
}

表示系イベント: Notification・MessageDisplay・StopFailure

  • Notification の種類（matcher）: permission_prompt idle_prompt auth_success auth_storage_failure elicitation_dialog elicitation_url_dialog elicitation_complete elicitation_response agent_needs_input agent_completed quota_auto_resume_fired quota_auto_resume_stale quota_auto_resume_disabled plugin_notification

  • systemMessage・continue は捨てられます。terminalSequence は対話セッションでだけ出力され、-p・SDK・async では無視されます。

async・onFailure・並列実行

async と asyncRewake

  • command 専用です。decision・permissionDecision・continue は効きません。
  • 終了後、additionalContext と systemMessage を次のターンで Claude に渡します。ユーザーには表示しません。
  • JSON は stdout に単独で出すか（複数行は v2.1.295 以降）、1 行に収めます。型の違うフィールドは捨てられます。
  • timeout は効きません（asyncRewake には効く）。-p の終了時に動いていれば cancelled で止められます。
  • asyncRewake の exit 2 は、待機中でも Claude をすぐ起こします。

onFailure: "block"

  • command と http で使えます（v2.1.295 以降）。失敗時に、そのイベントの exit 2 と同じ効果を出します。PermissionRequest では拒否です。
  • 失敗とみなすもの: 起動できない、0・2 以外の終了コード（allow の JSON 付きでも）、HTTP エラー・非 2xx、タイムアウト、不正な出力
  • Stop・SubagentStop・TaskCompleted・TeammateIdle と、async のフックには効きません。
  • Git Bash のない Windows では、shell form の PreToolUse・PermissionRequest は未設定でも失敗でブロックすることがあります。

並列と結果の合成

  • 一致したフックは並列に動き、すべて完了してから結果を合成します。1 つの deny で他のフックは止まりません。
  • 同じイベントの prompt・agent フックは 12 個ずつ動きます。待機中のフックの timeout は開始時から数えます。
  • v2.1.312 で、prompt・agent フックに、セッション全体（サブエージェント含む）で同時 24 個、加えてイベントの timeout より長く待った 12 個まで、という上限が入りました。同じ項目で「1 秒未満の timeout は 1 秒とみなす」ようになりました。
  • 複数フックの updatedInput はマージされず、どれが使われるかも保証されません。

セキュリティ・管理・デバッグ

セキュリティ

  • command フックは自分のユーザー権限のすべてで動きます。
  • 対話セッションは、信頼ダイアログを承認するまで全 settings ファイル（~/.claude/settings.json も含む）のフックを止めておきます。
  • -p と SDK はダイアログを出さずに信頼済みとみなすので、リポジトリにコミットされたフックが動きます。他人のリポジトリでは .claude/ を確認するか、--bare か --settings '{"disableAllHooks": true}' を使います。
  • 入力の検証、"$VAR" の引用、.. の拒否、絶対パス、.env・.git/・鍵の回避を推奨しています。

管理

  • disableAllHooks は優先順位を適用した後の値で効きます。プロジェクトの false はユーザーの true に勝ちます。managed のフックを止められるのは managed の設定だけです。
  • 個別のフックを無効にする方法はありません。
  • allowManagedHooksOnly（managed）は managed・SDK・強制有効化プラグインのフックだけを動かします。strictPluginOnlyCustomization の "hooks" でも絞れます（Ch58）。
  • allowedHttpHookUrls・httpHookAllowedEnvVars は managed を含む全ソースの HTTP フックに効きます。

確認とデバッグ

  • /hooks は読み取り専用の一覧で、各フックの出どころを表示します。末尾の All events で全イベントを見られます。
  • claude --debug-file <path> か --debug（~/.claude/debug/<session-id>.txt）でログを取ります。v2.1.296 以降、Hooks: で始まる行に結果と所要時間が出ます。
  • JSON が効かないときは、ログで Hook output does not start with {（シェルプロファイルの出力が先に出ている）と Hook JSON output had unrecognized keys（階層の誤り）を探します。
