Skills

SKILL.md で Claude に手順や知識を足す仕組みです。この章では、配置と名前の解決、frontmatter の全フィールド、呼び出し制御、引数と動的コンテキスト注入、allowed-tools と信頼モデル、context: fork、説明文の予算、可視性と権限ルールを扱います。バンドル Skill の一覧は Ch12 にあります。

全体像: SKILL.md と custom commands の統合

  • Skill は SKILL.md（YAML frontmatter と Markdown の本文）です。Claude が Skill ツールで呼ぶか、ユーザーが /skill-name で呼びます。毎ターン文脈に載るのは名前と説明文だけです。
  • custom commands は Skills に統合されました。.claude/commands/deploy.md と .claude/skills/deploy/SKILL.md は、どちらも /deploy を作り、同じように動きます。
  • コマンドファイルは name と paths を除く同じ frontmatter を受け付けますが、supporting files は持てません。同名なら Skill が勝ちます。
  • Agent Skills のオープン標準に準拠し、呼び出し制御・サブエージェント実行・動的注入を拡張しています。
  • 経緯: 2.0.20 で追加、2.1.0 でホットリロード・context: fork・frontmatter のフック、2.1.3 でスラッシュコマンドと統合。
  • claude.ai へのアップロード、Skills API、package_skill.py は name・description・license・compatibility・metadata・allowed-tools の 6 つだけを受け付け、他はエラーになります。
---
name: my-skill
description: What this skill does
disable-model-invocation: true
allowed-tools: Read Grep
---

Your skill instructions here...

frontmatter の解析規則

  • frontmatter として読むのは、1 行目が --- のときだけです。それ以外はファイル全体が本文になります。
  • フィールドはすべて任意で、推奨は description だけです。表に無いフィールド名は、エラーなしで無視されます。
  • 真偽値は true・false に加え、yes・no・on・off・1・0 を大文字小文字を問わず受け付けます。
  • YAML が解析できないと、フィールドなしで読み込まれます。claude plugin validate .claude/skills（v2.1.233 以降）か --debug で見つけます。

動的コンテキスト注入 (1/2): 構文と実行

---
name: pr-summary
description: Summarize changes in a pull request
context: fork
agent: Explore
allowed-tools: Bash(gh *)
---

## Pull request context
- PR diff: !`gh pr diff`
- PR comments: !`gh pr view --comments`
- Changed files: !`gh pr diff --name-only`

## Your task
Summarize this pull request...
## Environment
```!
node --version
git status --short
```
  • !`<command>` は、Skill の内容を Claude へ送る前にシェルで実行し、出力で置き換えます。Claude はコマンドではなく結果を受け取ります。
  • インライン形式は、! が行頭か空白の直後にあるときだけ認識します。KEY=!`cmd` は文字のまま残ります。複数行は ```! で始まるフェンスで書きます。
  • 置換は元のファイルに 1 回だけ行い、出力は再走査しません。
  • 実行するのは Bash ツールです。shell: powershell で PowerShell ツールが有効なら PowerShell ツールです。shell: bash で bash が無い環境（Git Bash の無い Windows）では、実行前に失敗します。
  • 作業ディレクトリはセッションのシェルの現在地で、cd で動きます。固定したいパスには ${CLAUDE_SKILL_DIR} か ${CLAUDE_PROJECT_DIR} を使います。
  • bash では stderr を stdout に合流します。タイムアウトは Bash ツールの既定の 2 分です。バックグラウンドへ移るコマンドなら Skill は描画され、移らないコマンドは止められて呼び出しが中断されます。
  • 出力が大きいと、ファイルパスと短いプレビューになります。

動的コンテキスト注入 (2/2): 失敗・権限・無効化

失敗したとき

  • 1 つでも失敗すると、Skill の呼び出し全体が中断され、Claude は内容を受け取りません。表示は Shell command failed for pattern "..." で、コマンドの出力を含みます。
  • bash では 0 以外の終了コードが失敗です。検索・比較コマンドの終了コード 1 だけは正常として扱い、2 以上は失敗です。PowerShell では対象が違い、grep・git diff を含み find・diff を含みません。
  • 0 以外で終わると分かっているチェックには || true を付けます。
  • No shell command in <name> was run は、受け付けない文字が含まれているという意味です（2.1.290 以降、タブと改行以外の生の制御文字を拒否）。

無効化

  • "disableSkillShellExecution": true は、user・project・plugin・追加ディレクトリの注入を [shell command execution disabled by policy] に置き換えます。バンドルと managed の Skill は対象外で、managed の true は覆せません。

権限の確認

  • 注入コマンドは描画中に確認を出しません。先に権限ルールと照合し、deny に一致すると Shell command permission check failed for pattern "..." で中断します。
  • auto mode 以外では、allow 以外の結果（ask を含む）もすべて中断です。中断させないには allowed-tools で事前に承認します。deny と ask は allowed-tools より優先です。
  • auto mode（2.1.271 以降）では、承認が要るコマンドでも中断しません。Skill は「先にそのコマンドを実行する」という指示付きで読み込まれ、Claude の呼び出しが auto mode の通常の審査を受けます。
  • ただし、agent を指定したフォークの Skill と、シェルツールの無いセッションでは中断します。
  • 2.1.299 以降、UserPromptSubmit フックは Skill の展開より先に動きます。プロンプトを止めれば注入コマンドも動きません。
  • claude.ai から同期した Skill は、自分のマシンでは ! を実行しません（v2.1.228 以降）。

allowed-tools・disallowed-tools と信頼モデル

---
name: commit
description: Stage and commit the current changes
disable-model-invocation: true
allowed-tools: Bash(git add *) Bash(git commit *) Bash(git status *)
---
  • 付与は Skill を呼び出したターンだけ有効で、次のメッセージで解除されます。本文は文脈に残っても、許可は残りません。再び呼べば再適用されます。
  • ツールを制限はしません。一覧に無いツールは通常の権限設定に従います。セッション全体で許可するなら allow ルールを使います。
  • deny と ask のルールは allowed-tools より優先します。
  • disallowed-tools（2.1.152）は、Skill が有効な間ツールプールから外し、次のメッセージで解除されます。全体で止めるなら deny ルールを使います。
  • ${CLAUDE_SKILL_DIR}・${CLAUDE_PROJECT_DIR} は allowed-tools の Bash ルールでも置換されます。本文と同じ変数を使えば、同梱スクリプトを確認なしで実行できます。

信頼モデル

  • ワークスペースの信頼は allowed-tools を止めません。一度も信頼していないフォルダの -p でも、プロジェクトの Skill の付与が効きます（実測）。リポジトリの Skill は実行前に中身を確認します。
  • allowManagedPermissionRulesOnly（managed、v2.1.282 以降）は、project・personal・--add-dir の Skill などの allowed-tools を無視します。無視した Skill は /status に出ます。managed とバンドルの Skill は付与を保ちます。
  • strictPluginOnlyCustomization が hooks を含むと、hooks を宣言した personal・project の Skill は allowed-tools を失い、フックも動きません（2.1.304）。
  • 修正の履歴: 対話ツール（AskUserQuestion など）を allowed-tools に入れると空の回答で自動許可された問題（2.1.69）、managed の ask ルールを allowed-tools が迂回できた問題（2.1.74）。

説明文の文字数予算と /skill-doctor

  • Claude は毎ターン、Skill の名前と説明文の一覧を受け取ります。名前は必ず全件載りますが、予算を超えると説明文を落とします。
  • 落とすのは呼び出しの少ない Skill からです。名前だけの Skill も呼べますが、Claude が自分から選ぶ可能性は下がります。
上限既定変え方
1 件の description＋when_to_use1,536 文字skillListingMaxDescChars
一覧全体コンテキストウィンドウの 1%skillListingBudgetFraction（0 より大きく 1 以下）、または固定の文字数を SLASH_COMMAND_TOOL_CHAR_BUDGET
  • env-vars は SLASH_COMMAND_TOOL_CHAR_BUDGET を「1% で伸縮し、フォールバックは 8,000 文字。互換のための旧名」と説明しています。
  • 経緯: 1 件の上限は 2.1.86 で 250 文字、2.1.105 で 1,536 文字。全体は 2.1.32 で「コンテキストの 2%」と告知され、現行 docs は 1% です。

調べ方

  • /doctor は一覧のコストを見積もり、/context の Skills 行は予算適用後の大きさです（v2.1.196 以降）。超過時は --debug のログに警告が出ます。
  • 予算を空けるには、優先度の低い Skill を skillOverrides で "name-only" にします。

/skill-doctor

  • Skill ごとのコンテキストコストと使用頻度を示し、一度も呼ばれていない Skill と止める場所、最近使っていないプラグインを挙げます。
  • バンドルと Enterprise の Skill は対象外です。対話では /plugin の Stats タブに、-p ではテキストで出ます。
  • feature flag の取得が必要で、Remote Control からは使えません。2.1.261 で追加されました（changelog）。

skills ページと commands ページは、/skill-doctor を「v2.1.252 以降」と記載しています。

ライブリロードと skillOverrides

  • ~/.claude/skills/、プロジェクトの .claude/skills/、--add-dir の .claude/skills/ を監視し、追加・編集・削除をセッション中に反映します（bare mode を除く）。
  • 起動後に作ったトップレベルの skills ディレクトリは監視されません。/reload-skills を実行し、その後の変更のたびに再実行します。/reload-skills は Skill とコマンドのディレクトリを再走査し、増減の数を報告します。
  • 監視の対象は SKILL.md の本文だけです。プラグインを兼ねる Skill フォルダの hooks/・.mcp.json・agents/・output-styles/ には /reload-plugins が要ります。--add-dir の commands/・agents/ は再起動が要ります。
  • SessionStart フックが reloadSkills: true を返すと、Skill のディレクトリを再走査します（2.1.152）。
  • 2.1.304 以降、圧縮の後は Skill の一覧を送り直し、/reload-skills は新規と変更分だけを送ります。
  • skillOverrides の別名（/doctor の checkup など）のキーは、managed と --settings でだけ効き、絞る方向にだけ働きます。

  • 書かれていない Skill は "on" です。"off" は Remote Control と Agent SDK のコマンド一覧からも隠れ、正式名で呼ぶと skillOverrides のエラーになります。プラグインの Skill には効きません。

実機検証: init への出現と実行

$ claude -p '/lab-echo banana split'
ECHO banana split / FIRST banana / DYN injected-42

$ claude -p '/lab-grant'
RAN

$ claude -p '/lab-nogrant'
DENIED

いずれもプロジェクトの Skill（disable-model-invocation: true）。-p --model haiku --setting-sources project で、一度も信頼していないフォルダで実行。lab-echo の本文は ECHO $ARGUMENTS / FIRST $0 / DYN !`echo injected-$((40+2))` を返す指示。lab-grant・lab-nogrant は touch を 1 回実行させる指示
