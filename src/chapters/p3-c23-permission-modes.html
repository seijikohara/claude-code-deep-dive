パーミッションモード

セッションが確認なしで実行できる範囲を決める 6 つのモードを扱います。Manual への改名、開始モードの決まり方、Shift+Tab での切り替え、各モードの細部、どのモードでも自動承認されない操作と保護パス・危険な rm の扱いまでを示します。

  • 2.1.200 で、CLI・--help・VS Code・JetBrains の表示名が "default" から "Manual" に変わりました。設定値は default のままで、フックや SDK もこの値を使います。

Shift+Tab と各サーフェスでの切り替え

  • CLI では auto から 1 回押すと default になり、以降 default → acceptEdits → plan と巡回します。
  • 任意のモードは plan の後に入ります。順序は bypassPermissions が先、auto が最後です。auto へは確認なしで切り替わります。
  • bypassPermissions が巡回に入るのは、--permission-mode bypassPermissions・--dangerously-skip-permissions・--allow-dangerously-skip-permissions で起動したときか、user・--settings・managed の defaultMode が "bypassPermissions" のときだけです。
  • dontAsk は巡回に入りません。フラグか defaultMode で指定します。
  • Manual と acceptEdits の Bash 確認には、auto mode が使えると Yes, and switch to auto mode が加わります（v2.1.247 以降）。ask ルールやフックが強制した確認と、PowerShell の確認には出ません。
サーフェス選べるモードと既定の決め方
VS CodeManual / Edit automatically / Plan / Auto / Bypass permissions。Bypass は Allow dangerously skip permissions の有効化が必要
JetBrains BetaIDE のターミナルで CLI と同じ操作
Desktopモードセレクタ。Bypass は Pro・Max・Ultra では Allow bypass permissions mode、Team・Enterprise では組織ポリシー。選択はフォルダごとに記憶
クラウドAccept edits（default に相当）/ Plan / Auto。Bypass なし

サブエージェントの permissionMode

  • 親が bypassPermissions・acceptEdits・auto なら親のモードで動き、指定は無視されます。親が plan なら plan のままです。
  • 親が default・dontAsk なら指定に従います。ただし bypassPermissions（v2.1.267 以降）と使えない auto は親のモードになります。

acceptEdits と plan

acceptEdits

  • ファイル編集に加え、mkdir・touch・rm・rmdir・mv・cp・sed を自動承認します。対象は作業ディレクトリと additionalDirectories 内のパスだけです。
  • touch 以外は、LANG=C のような安全な環境変数や timeout・nice・nohup を前に付けても承認されます。
  • 確認が残るもの: 範囲外のパス、保護パス、クリティカルパスの削除、オプション・glob・前置きつきの touch、読み取り専用以外の Bash。各パスは symlink の検査も通ります。
  • PowerShell Preview では Set-Content・Add-Content・Clear-Content・Remove-Item も対象です。引用符を含む位置引数は確認になるので -Value で渡します。

plan

計画中のシェルコマンドは、上から最初に当たる条件で扱いが決まります。

  1. bypass が使える対話ターミナル: 分類器も確認も適用されない
  2. auto mode が使え useAutoModeDuringPlan（既定 true、user・local・managed のみ）が有効: 分類器が審査（クリティカルパス削除を除く）
  3. それ以外: 読み取り専用以外は確認。サンドボックスの auto-allow でも確認
  • 入り方: Shift+Tab、プロンプト先頭の /plan、--permission-mode plan。
  • 承認の選択肢: Yes, and use auto mode（auto が使えなければ Yes, auto-accept edits）/ Yes, manually approve edits / No, keep planning。Ctrl+G で計画をエディタで編集できます。
  • PreToolUse フックの "allow" は、読み取り専用以外の呼び出しを承認できません（ExitPlanMode を除く）。
出典: permission-modes#auto-approve-file-edits-with-acceptedits-mode · #analyze-before-you-edit-with-plan-mode · settings-reference#useautomodeduringplan · permissions#hook-approvals-in-plan-mode

dontAsk と非対話実行での拒否

  • dontAsk は確認が必要な呼び出しを自動拒否します（mod は一部を承認可）。読み取り、読み取り専用の Bash、permissions.allow 一致、PreToolUse フックの承認は実行されます。
  • allow があっても拒否: 明示の ask 一致、AskUserQuestion、組織が ask にしたコネクタ、requiresUserInteraction の MCP ツール、クリティカルパス削除、ネットワークパスの読み取り。
  • フラグか defaultMode でだけ指定できます。クラウドセッションは設定の "dontAsk" を無視します。
claude -p "run the test suite" --permission-mode dontAsk \
  --allowedTools "Bash(npm test)" "Read"

モード未指定の -p も、allow ルール・フック・canUseTool・--permission-prompt-tool がなければ拒否します。user 設定なしで touch new.txt を実行させた結果:

touch in '<dir>/new.txt' needs approval. The path is inside the working directories for this session …

permissions.denyInsteadOfPrompting（v2.1.319 以降。user・managed・--settings）-p 以外（対話・VS Code・Desktop のローカル）でも同じ拒否。EnterPlanMode・ExitPlanMode も外し、canUseTool とプロンプトツールに問い合わせない

bypassPermissions と 2 つのフラグ

フラグ動作
--dangerously-skip-permissions--permission-mode bypassPermissions と同等。bypass で開始
--allow-dangerously-skip-permissions巡回に bypass を加えるだけで、開始はしない。-p・SDK・VS Code では後から選べるようにする
  • 確認と安全確認を省き、保護パスへの書き込みも即実行します。それでも「どのモードでも自動承認されないもの」とセッション間メッセージングの保護は残ります。
  • bypass が使える対話ターミナルでは plan mode の制限が強制されません（ask ルールと危険な rm は確認）。-p・SDK・VS Code では plan の制限が残ります。
  • 有効にせず始めたセッションから bypass には入れません。
  • 初回の対話起動で警告ダイアログが出ます。承諾すると ~/.claude/settings.json に skipDangerousModePermissionPrompt: true が書かれ、拒否すると終了します。-p では出ません。
  • Linux と macOS では root・sudo での起動を拒否します。認識されたサンドボックス内ではこの検査を省きます。
--dangerously-skip-permissions cannot be used with root/sudo
privileges for security reasons
  • Preview バックグラウンドセッションは承諾の記録がないと bypass 起動を拒否し、承諾が .claude/settings.local.json だけなら bypass 要求を無視して通知します。
  • permissions.disableBypassPermissionsMode: "disable" はどのスコープでも効き、フラグとエージェント定義の permissionMode: bypassPermissions を無効にします。--restricted も bypass を拒否します。クラウドセッションは設定の "bypassPermissions" を黙って無視します。

プロンプトインジェクションに対する保護はありません。インターネットに出られないコンテナや VM でだけ使います。

どのモードでも自動承認されないもの

  1. 明示の ask ルールに一致したツール
  2. 組織が ask に設定したコネクタツール（その設定が届くセッション）
  3. AskUserQuestion と requiresUserInteraction の MCP ツール
  4. 認識された rm・rmdir のクリティカルパス削除と、Dangerous rm operation not ruled out と判定されたコマンド
  5. セッション間メッセージングの保護
  6. permissions.blockReadsOutsideWorkingDirectories が有効なときの作業ディレクトリ外の読み取り（v2.1.257 以降）。追跡できないコマンドも確認になる
  7. permissions.blockWritesOutsideWorkingDirectories が有効なときの外部への書き込み（v2.1.314 以降）。Write・Edit・NotebookEdit を拒否

4 の確認は bypass でだけ消せます（危険な rm (2/2)）。

危険な rm: クリティカルパスと判定対象 (1/2)

クリティカルパス

  • ファイルシステムのルートと、その直下（/usr、/etc、/data など）
  • ホームディレクトリ（Windows の 8.3 短縮名を含む）
  • Windows のドライブルートとその直下（\\?\C:\ などの表記も含む）
  • 作業ディレクトリとその親
  • 追加ディレクトリとその親。ただし rm -rf <dir>/* のような glob 削除のときだけ

(...)・{ ...; }・$(...)・<(...) の中と、sh・bash・zsh の -c スクリプトの中も調べます。どの allow ルールも PreToolUse の "allow" も承認できません。

対象として扱う例理由
rm -rf "$DIR"/*変数が空ならルートからの削除になる
rm -rf "$1"/*値が与えられない位置パラメータ
rm -rf "$TMPDIR/mnt"空展開で /mnt を削除する
D=$(pwd); rm -rf "$D"作業ディレクトリやリポジトリルートを指しうる
rm -rf "$(pwd)"実行前に対象を確認できない
rm -rf ~/$(cmd)空展開でホームが残る
rm -rf "\\"Git Bash は現在のドライブのルートと解釈する
rm -rf logs/*/*どのディレクトリに届くか実行前に分からない

rm -rf "${DIR:?}"/* のように展開をガードすると検査を通ります。シェルが解析と違う読み方をしうるコマンドには次の理由が付き、削除と同じ扱いになります。

Dangerous rm operation not ruled out — the shell may read
this command differently than it was parsed
