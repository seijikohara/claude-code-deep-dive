クラウドセッション

Claude Code をクラウドの VM で動かし、手元のマシンを閉じても作業を続ける仕組みです。この章では、CLI からの起動と追送、バンドル送信、Teleport、GitHub の接続、クラウド環境（ネットワーク・変数・シークレット・セットアップスクリプト）、VM の制限と Auto-fix を扱います。

claude --cloud で新しいクラウドセッションを作る

claude --cloud "Fix the auth bug in src/auth/login.ts"

# 計画はローカル、実行はクラウド
claude --permission-mode plan
#   計画をリポジトリに保存し、commit して push
claude --cloud \
  "Execute the migration plan in docs/migration-plan.md"

# --cloud ごとに独立したセッションが並列に動く
claude --cloud "Fix the flaky test in auth.spec.ts"
claude --cloud "Update the API documentation"
  • クラウド VM は、カレントディレクトリの GitHub リモートを現在のブランチで clone します。ローカルの checkout ではないため、先に push します。
  • Branch <name> is not on GitHub が出ても、セッションは push 済みの祖先コミットか既定ブランチから始まります。
  • 1 回の --cloud で扱うリポジトリは 1 つです。旧表記 --remote は非推奨の別名として動きます。
  • VM の準備中は、clone やセットアップスクリプトの進行をチェックリストで表示します。準備中に入力したメッセージは、準備完了後に送られます。
  • CLI からの受け渡しは一方向です。既存のターミナルセッションをクラウドへ送ることはできません。Desktop は Open in メニューで送れます（Ch52）。
  • claude.ai のサインイン（claude auth login）が必要です。Bedrock・Agent Platform などのサードパーティプロバイダでは使えません。ANTHROPIC_BASE_URL だけで設定したゲートウェイはサードパーティ扱いになりませんが、サインインは必要です。
  • 組織ポリシー allow_remote_sessions が有効である必要があります。Enterprise のカスタムロールでは、クラウドセッションの権限が要ります。
  • 環境の選び方: /remote-env で選んだ環境、なければ Anthropic ホストの環境、なければ一覧で最初の bridge 以外の環境です。--environment ccpool_... はその 1 回だけセルフホスト環境を指定します（env_ の ID は拒否）。
  • --cloud と --remote-control は無関係です（Ch49）。

GitHub を使わないバンドル送信

  • git リモートがない、または Claude GitHub App が入っていない github.com のリポジトリでは、--cloud がローカルリポジトリをバンドルして直接アップロードします。/web-setup で接続済みでも同じです。
  • 完全な clone なら、全ブランチの履歴と、追跡ファイルの未コミット変更を含みます。未追跡ファイルは含みません（git add しておく）。
  • macOS・Linux・WSL では、.env・*.tfvars・id_rsa・*.pem など認証情報らしい名前のファイルと、Git LFS などの filter 管理ファイルの未コミット変更を除外し、Left on this machine: で通知します。
  • ネイティブ Windows では除外しません。追跡ファイルの未コミット変更は名前にかかわらずそのまま送られます。
  • リモートがあってもバンドルさせるには CCR_FORCE_BUNDLE=1 を付けます。GitLab・Bitbucket などもこの方法で送れますが、結果をそのリモートへ push できません。
CCR_FORCE_BUNDLE=1 claude --cloud \
  "Run the test suite and fix any failures"

制限

  • 1 つ以上のコミットがある git リポジトリであること。
  • 100 MB 未満であること。超えると現在のブランチだけ、次に作業ツリーの単一スナップショットに縮め、それでも大きければ失敗します。
  • バンドルから作ったセッションが GitHub へ push できるのは、GitHub 接続にその push 権限がある場合だけです。
  • macOS・Linux・WSL では git 2.31 以降が必要です。次の構成は Not uploading this working tree: で拒否されます。
    • submodule の中、--separate-git-dir・--shared・--reference の clone、core.worktree の設定、reftable
    • sparse checkout の linked worktree（worktree.sparsePaths を含む）
    • 作業ツリー内のファイルを include する git 設定
  • git clone --filter の部分 clone は、履歴なしのスナップショットとして送られます。

クラウド環境: Default・選択・ネットワークアクセス

  • 環境は、ネットワークアクセス・環境変数・ネットワークシークレット・セットアップスクリプトをまとめた保存済み設定です。Desktop・モバイル・claude.ai/code・--cloud・クラウドのスケジュールタスク・Claude Tag で共通です。

環境変数とネットワークシークレット

環境変数

  • .env 形式で 1 行に KEY=value です。クォートしない値では # 以降がコメントになるため、# や改行を含む値はクォートします。
  • Claude が実行するコマンドから読めます。ただし OTEL_* は Claude Code 自身のテレメトリ送信に使い、コマンドには渡しません。
  • セッション作成時と、VM で Claude Code が再起動するとき（アイドル後の復元、回収後の再構築）に読みます。編集は実行中のセッションに即時反映されません。
  • CLAUDE_AUTOCOMPACT_PCT_OVERRIDE はセッションが自分で設定するため、ここに書いても効きません。
  • 環境を使う全員が値を読めます。キーはネットワークシークレットに置きます。

ネットワークシークレット

  • Anthropic の agent proxy が、VM を出た後のリクエストにキーを付けます。キーは VM に入りません。
  • 既定の種類は Bearer（Authorization: Bearer）です。ホストは *. でサブドメインを指定できます。Team・Enterprise の管理者ロールがない人は、1 ホストの短いフォーム（Token か Username and password、ワイルドカード不可）を使います。
  • 付けない宛先: GitHub、api.anthropic.com、registry.npmjs.org・jsr.io・npm.jsr.io・pypi.org・files.pythonhosted.org・index.crates.io・proxy.golang.org、セットアップスクリプトの通信、テレメトリ送信。
  • 完全一致しない重なったホストを持つ 2 つのシークレットは、片方だけ送られ、印も付きません。
  • セルフホスト環境と CMEK の組織では使えません。値は保存後に再表示できません。

GitHub プロキシとセッションへのリンク

  • Anthropic ホストの環境では、GitHub への操作はすべて専用プロキシを通ります。VM 内の git はスコープ付きの認証情報を使い、プロキシが本物のトークンに差し替えます。
  • ブランチの削除とタグなどの push を拒否します。push 先のブランチは制限しないため、ブランチ保護や rulesets で絞ります。
  • API はセッションに付けたリポジトリだけを通します。他は 403 GitHub access to … is not enabled for this session です。
  • GraphQL は 403 GitHub GraphQL is not available from Claude Code sessions です。gh pr・gh issue も失敗するため、gh api repos/{owner}/{repo}/... を使います。
  • GH_TOKEN・GITHUB_TOKEN を設定しない場合、両方とも proxy-injected という文字列として見えます。
  • セッションは CLAUDE_CODE_REMOTE_SESSION_ID で自分の ID を読めます。CLAUDE_CODE_REMOTE はクラウドセッションで true です。
  • Claude が作るコミットには Claude-Session: <url> トレーラーが付き、PR 本文にはセッション URL が入ります。attribution.sessionUrl: false で止めます。
  • それ以外の場所にリンクを書くときは、cse_ を session_ に置き換えます（下の 1 行目）。
  • claude.ai/code の URL には prompt（別名 q）・prompt_url・repositories（別名 repo）・environment を付けて事前入力できます（下の 2 行目）。
echo "https://claude.ai/code/${CLAUDE_CODE_REMOTE_SESSION_ID/#cse_/session_}"
https://claude.ai/code?prompt=Fix%20the%20login%20bug&repositories=acme/webapp

VM・時間制限・セッション中の操作・Auto-fix

  • VM は Ubuntu 24.04 x86_64 で、目安は 4 vCPU・16 GB RAM・30 GB ディスクです。Python・Node 20/21/22・Ruby・PHP・Java 21・Go・Rust・Docker・PostgreSQL 16・Redis 7.0・Chrome for Testing などが入っています（check-tools で確認）。シェルには入れず、Claude がすべて実行します。
  • Bash は既定 2 分・最大 10 分で、超えるとバックグラウンドへ移って最大 30 分続きます。BASH_DEFAULT_TIMEOUT_MS・BASH_MAX_TIMEOUT_MS で延ばせます。SessionStart フックは 600 秒です。
  • 数分アイドルで VM は一時停止し、後で回収されることがあります（Environment expired）。再開すると会話は戻りますが、シェル・サブエージェント・セッション内のスケジュールタスクは戻りません。
  • 権限モードは Auto・Accept edits・Plan です。/model・/effort・/color・/rename は引数で指定し、/fast は v2.1.271 以降で使えます。Agent Teams Experimental は CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1 で有効にします。
  • レート制限は他の利用と共有です。組織の IP 許可リストがあると、Anthropic ホストのセッションは認証エラーになります。

Auto-fix pull requests

  • Claude が PR の CI 失敗とレビューコメントを受け取り、明確な修正なら push します。曖昧な指摘は確認を求めます。Claude GitHub App が必要です。
  • 有効化: セッションの Changes カードの PR メニュー、ターミナルで /autofix-pr [prompt]（gh で PR を検出しクラウドセッションを起動）、モバイルでの指示、PR の URL を貼って指示。
  • ベースブランチの進行による競合は GitHub が webhook を出さないため、自動では対応しません。
  • レビュースレッドへの返信は自分の GitHub アカウント名で投稿され、Claude Code 作成と明示されます。

Atlantis・Terraform Cloud・issue_comment で動く Actions など、コメントで起動する自動化があるリポジトリでは、Claude の返信がそれらを起動しうると docs は警告しています。
