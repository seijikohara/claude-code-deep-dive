診断

設定が効かないとき、何が読み込まれ、どの値が勝ったかを確かめる手段をまとめます。/status、claude doctor、--debug、--setting-sources による切り分け、--safe-mode と clean-config による再現の順に扱います。

/status: 読み込まれた設定ソースを見る

  • 設定ダイアログの Status タブを開きます。バージョン、モデル、アカウント、接続状態を表示し、Claude の応答中でも使えます。/config は同じダイアログの別タブです。
  • Setting sources 行は、このセッションが読んだファイルを並べます（User settings、Project local settings など）。
  • managed が効いていると Enterprise managed settings の後ろの括弧に経路が出ます。
  • 見つかったが選ばれなかった managed ソースは Skipped sources 行に出ます（2.1.242 以降）。
  • Session kind 行は interactive か、背景セッションでは background job · attached などです。
  • Organization policy 行は、組織ポリシーを読めたかと、その結果を待っている機能（WebFetch など）を示します。
括弧内の表示経路
(remote)server-managed settings（claude.ai・gateway）
(plist)・(HKLM)MDM・OS ポリシー
(file)・(drop-ins)・(file + drop-ins)managed-settings.json と managed-settings.d/
(remote + file, merged) などmanagedSourcesBehavior: "merge" で合成
(HKCU)ユーザーが書けるレジストリ
(parent process)埋め込みホストが渡した制限

Setting sources は読んだファイルを示すだけで、各キーをどのファイルが決めたかは示しません。project や managed が model を決めた場合は、起動時のヘッダーがそのファイルを示します。

claude --debug='mcp,startup'
claude --debug='!mcp'

どの設定が勝ったかを突き止める

  1. /status で、読まれたファイルと managed の経路を確かめる。
  2. settings-reference でキーの「Per-session overrides」行を読み、フラグや環境変数が上書きしていないかを確かめる（Ch18）。
  3. claude doctor で、不正として捨てられたファイルとエントリを確かめる。
  4. --setting-sources で読むファイルを 1 つずつ絞り、-p --output-format stream-json --verbose の init にある model や permissionMode を比べる。プロンプトを /advisor のようなローカルコマンドにすると、モデルへのリクエストは送られない（実測）。
  5. デバッグログで、どの設定パスが存在し、どれが無いかを確かめる。
  6. それでも分からなければ、次のスライドの clean-config で再現させる。

--safe-mode・--bare と clean-config での切り分け

--safe-mode（CLAUDE_CODE_SAFE_MODE=1）

  • 読み込まないもの: CLAUDE.md、Skill、プラグイン、フック、MCP サーバー、カスタムコマンドとエージェント、出力スタイル、workflow、カスタムテーマ、キーバインド、ステータスラインとファイル候補のコマンド、LSP サーバー、auto memory。
  • 認証、モデル選択、組み込みツール、権限は通常どおり動きます。managed のポリシーとフックは残り、managed のプラグイン・Skill・CLAUDE.md・MCP は止まります。
  • 問題が消えたら、止めたもののどれかが原因です。

--bare（CLAUDE_CODE_SIMPLE=1）

  • 自動検出を省き、ツールは Bash・Read・Edit だけです。診断よりスクリプト向けで、詳細は Ch44 です。

clean-config で再現させる

mkdir -p ~/claude-clean/empty && cd ~/claude-clean/empty
CLAUDE_CONFIG_DIR=~/claude-clean/config \
  claude --setting-sources user
  • 初回セットアップ画面が出れば、空の設定ディレクトリが効いています。managed settings と claude.ai のコネクタは残ります。
  • 問題が消えた: 原因は user か project の設定です。~/.claude.json と ~/.claude のファイルを 1 つずつ戻して探します。
  • 問題が残った: /status で managed を確かめ、シェルの環境変数を確かめます。

よくある取り違え

  • permissions・hooks・env を ~/.claude.json に書いている。
  • mcpServers を settings.json に書いている。project は .mcp.json、user は claude mcp add --scope user。
