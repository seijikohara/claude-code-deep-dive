08

チェックポイント

Claude がファイル編集ツールで変えたファイルを、プロンプトごとに自動で退避する仕組みです。この章では、スナップショットの単位と保持期間、/rewind メニューの各操作、巻き戻せない変更、Agent SDK からの利用を扱います。

仕組みと保持

  • ターンを開始するプロンプトを送るたびに、チェックポイントが 1 つ作られます。
  • 対象は Claude のファイル編集ツールによる変更です。Claude Code は編集の前にファイルの内容をスナップショットします（SDK ページでは Write・Edit・NotebookEdit と明記）。
  • スナップショットは、セッション内の直近 100 チェックポイント分を保持します。古いチェックポイントを捨てると、残りのどれからも参照されないスナップショットを削除します。
  • 例外として、各ファイルの最初のスナップショットは残ります。VS Code 拡張がセッション差分の基準に使うためです。
  • チェックポイントは会話と一緒に保存されます。--resume で再開した後も /rewind できます。
  • git とは独立した、セッション単位の復旧手段です。履歴管理と共同作業には引き続き git を使います。
項目内容
保存先~/.claude/file-history/<session>/
削除retention sweep が削除する。既定ではセッションが最後にスナップショットを保存してから約 30 日後（cleanupPeriodDays）
削除後の巻き戻しNo files were restored で失敗し得る。長く残すには cleanupPeriodDays を延ばす
設定で無効化"fileCheckpointingEnabled": false。/config の Rewind code (checkpoints) 行と同じキー
環境変数で無効化CLAUDE_CODE_DISABLE_FILE_CHECKPOINTING=1。設定と環境変数は、どちらかが off にすると他方で戻せない
-p と SDKfileCheckpointingEnabled を無視する。SDK は enableFileCheckpointing、素の -p は CLAUDE_CODE_ENABLE_SDK_FILE_CHECKPOINTING=true で有効にする

/rewind メニュー

開き方: /rewind（エイリアス /checkpoint、/undo）、または入力欄が空のときに Esc を 2 回。入力中の文字があると、Esc 2 回は文字を消して入力履歴に退避します（↑ で戻せる）。一覧から送信済みのプロンプトを選び、操作を選びます。

操作効果
Restore code and conversationコードと会話の両方をその時点へ戻す
Restore conversation会話だけ戻し、現在のコードは残す
Restore codeファイルだけ戻し、会話は残す
Summarize from here選んだ地点以降を要約に圧縮する
Summarize up to here選んだ地点より前を要約に圧縮し、後ろは残す（2.1.141 で追加）
Never mind何もせず一覧へ戻る
  • コードを戻す 2 つの操作は、選んだチェックポイントに追跡済みの変更があるときだけ表示されます。
  • Restore conversation と Summarize from here の後は、選んだプロンプトが入力欄に戻ります。Summarize up to here の後は入力欄が空のままです。
  • 要約した箇所には Summarized conversation の印が付きます。元のメッセージはトランスクリプトに残り、ディスク上のファイルは変わりません。
  • 要約の方針は、矢印キーで Summarize を選び add context (optional) 行に入力して Enter。数字キーで選ぶと指示なしで即実行します。
  • 同じプロセスで /clear を実行していると、先頭に /resume <session-id> (previous session) が出ます。/clear 前の会話へ戻れます。
  • 巻き戻した直後に終了すると、消したメッセージが戻ることがあります。終了前に次のプロンプトを 1 つ送ります。
  • DISABLE_COMPACT を設定すると、Summarize の 2 つは表示されません（2.1.311）。キャッシュへの影響は Ch6。

追跡されない変更と SDK からの利用

変更の種類巻き戻しの扱い
Bash による変更Claude がファイル編集ツールで一度編集したファイルなら、その後の Bash の変更も戻る。Bash だけが触ったファイルは追跡されない。sed -i も 2.1.309 からほかの Bash 編集と同じ扱い
サブエージェント原則として記録されない。例外は前景で動く context: fork の Skill（background: false）。背景の fork Skill と背景の /code-review --fix は戻らない
外部の変更エディタでの手動編集や並行する別セッションの編集は、同じファイルに当たらない限り記録されない
ターン途中に送ったメッセージNo code restore と表示され、自身のチェックポイントを持たない。ターンを開始したプロンプトから戻す
symlink・ハードリンクスキップして Restored the code, but skipped N files と警告する（2.1.216）。/debug を有効にすると ~/.claude/debug/<session-id>.txt にパスが出る
リモートの副作用DB・API・デプロイは対象外

Agent SDK とヘッドレス

  • 有効化: enableFileCheckpointing: true（Python は enable_file_checkpointing=True）。
  • 復元点の UUID を受け取るには extraArgs: { "replay-user-messages": null } も必要です。ストリームの各ユーザーメッセージの uuid が復元点になります。
  • rewindFiles(uuid) はファイルだけを戻します。会話は戻りません。作成したファイルは削除し、変更したファイルは当時の内容に戻します。
  • ディレクトリの作成・移動・削除は戻りません。チェックポイントは作成したセッションに紐づきます。
CLAUDE_CODE_ENABLE_SDK_FILE_CHECKPOINTING=true \
  claude -p --resume  --rewind-files

--rewind-files は claude --help に載りません。成功すると Files rewound to state at message <checkpoint-uuid> を出力し、プロンプトを送らずに終了します。
