コードレビュー

Claude Code のレビュー機能は 4 層です。セッション内の /code-review、クラウドで多数のエージェントが検証する ultrareview、GitHub の PR を自動でレビューする Code Review、脆弱性を深く探す Claude Security プラグインです。この章では、それぞれの書式、課金、制限、CI での使い方を扱います。

/code-review: セッション内のレビュー

書式は /code-review [level] [flags] [target] です。/review は v2.1.223 以降エイリアスです。全プランで使え、通常の利用量として数えます。

対象入力
現在のブランチと未コミットの変更/code-review
直近 15 コミット/code-review HEAD~15..HEAD
ブランチ同士/code-review main...my-feature
1 コミット/code-review abc1234^..abc1234
PR 番号/code-review 1234
ファイル・ディレクトリ/code-review src/auth
  • --fix: 結果を作業ツリーに適用します（権限モードに従う）。
  • --comment: GitHub の PR にインラインコメント、GitLab の MR には glab で 1 つのノートを付けます（v2.1.257 以降。MR は URL か !123）。
  • --max-findings <n>・all・default: 報告数の上限です（v2.1.288 以降）。findings ツール経由の上限は 32 です。
  • レベル: low は確度の高い指摘だけ、medium〜max は範囲を広げます。ultra はクラウドの ultrareview です。
  • レベルを省くと、前回入力した low〜max を別セッションでも再利用します（Reusing high effort, the level you typed last time）。-p の値と ultra は記憶せず、未入力ならセッションの effort です。
  • 実行場所: 端末ではバックグラウンドの fork サブエージェントです。-p・SDK、CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1、実行中の再実行では待ちます。
  • 読むもの: CLAUDE.md に従います（-p でも）。REVIEW.md は読みません。
  • 出力: 端末と -p は文章、Desktop などは ReportFindings ツールです。バックグラウンドの --fix の編集は /rewind で戻らないため git で戻します。
  • Claude が自分から実行することもあります（feature flag を取得しないセッションでは v2.1.246 以降）。止めるには "skillOverrides": { "code-review": "user-invocable-only" } です。同名の project・personal skill は同梱版より優先します（/review は同梱版）。

ultrareview: 仕組み・料金・制限 Preview

  • クラウドセッションのサンドボックスで多数のレビューエージェントが動き、指摘はすべて独立に再現・検証されます。通常 5〜15 分かかり、バックグラウンドのタスクとして /tasks に出ます。
  • 起動は /code-review ultra だけです。利用できるアカウントでは /ultrareview がエイリアスです。Claude が自分から始めることはありません。
  • 書式: /code-review ultra develop（比較の基点）、ultra 1234（#1234・PR 1234・URL も可）、ultra check my auth changes（複数語はメモ扱い）、ultra --fix、ultra 1234 --post。
  • ブランチモードはリポジトリの状態を束ねてアップロードします（.env などはクラウドセッションの規則に従う）。PR モードは github.com 専用で、/web-setup で接続した GitHub アカウントでクラウドに clone し、何もアップロードしません。
  • --post は所見を自分の GitHub アカウントから PR へ 1 件の通常コメントとして投稿します（末尾に「Generated by Claude Code」）。投稿するのは Anthropic API です。
  • サブコマンドの再実行は前のレビューを再開せず、新しいレビュー（無料分か課金）を始めます。
プラン無料無料分の後
Pro・Max・Ultra3 回（アカウントごとに 1 度だけ。補充なし）usage credits で通常 $5〜$25
  • 有料の起動には usage credits の有効化が必要です。クラウドセッションが始まった時点で 1 回と数え、途中で止めた有料レビューは実行分だけ課金します。
  • ブランチレビューの上限は既定で 500 ファイル・8,000 行です。
  • 最初のコミットは対話で確認してから全体をレビューします。サブコマンドと -p は拒否します（v2.1.277 以降）。共通の祖先がなければ、確認後にリポジトリ全体をレビューし（-p は拒否）、ref のない detached HEAD は拒否します。
  • claude.ai へのログインが必要です。Bedrock・Agent Platform・Foundry、ZDR、HIPAA 構成ではローカルのレビューに切り替わり、CMEK の組織は使えません。
  • claude ultrareview を自分で実行すると、全体レビューと課金への同意とみなします。Claude が Bash で実行した場合、全体レビューは拒否されます。

Code Review: GitHub の PR を自動でレビューする

  • Team・Enterprise 向けの管理型サービスです。GitHub・GHES・データレジデンシー付き GHE Cloud に対応し、ZDR・HIPAA 構成・CMEK では使えません（BAA 対象外）。
  • Anthropic の基盤で 4 段階（Find・Verify・Rank・Post）で動きます。読み取り専用でビルド・実行・push はせず、モデルは選べません。
  • インラインコメント・要約・check run「Claude Code Review」を残します。check run は neutral か skipped で終わり、PR の承認もブロックもしません。
  • レベルは Quick・Standard（既定）・Deep で、組織とリポジトリで設定します。
  • 実行は Once after PR creation・After every push（新規の既定。実行回数が最も多い）・Manual (@claude review)。draft と fork の PR は自動の対象外です。

重大度は Important（マージ前に直すべきバグ）・Nit（軽微で止めない）・Pre-existing（この PR より前からあるバグ）の 3 段階です。

コメント動作
@claude review / once1 回だけレビュー。以後の push は購読しない
@claude review alwaysレビューし、以後の push でもレビュー
@claude review stop / off / pausepush での購読をやめる。実行中は取り消さない
  • PR へのトップレベルの新規コメントで、1 行目の先頭に書きます。書き込み・maintain・admin 権限が必要で、bot は無視されます。
  • GitHub Action の既定のトリガー語 @claude とぶつかるため、Action 側の trigger_phrase を変えます。

check run の詳細の最終行を読んでマージを止められます。

gh api repos/OWNER/REPO/check-runs/CHECK_RUN_ID --jq '
  (.output.text | split("\n") | last
    | scan("^$")[0] | fromjson)?
  // error("no severity line")'

normal が Important の件数です。タイトルが Code review not repeated で始まる場合は、件数の行がありません。

REVIEW.md とコスト

  • Code Review はリポジトリのルートの CLAUDE.md と、変更ファイルの親ディレクトリの CLAUDE.md を読みます。
  • REVIEW.md はレビュー専用の自由形式の Markdown です。ベースブランチか既定ブランチから読み、PR 自身の変更からは読みません。既定ブランチを保護します。
  • 保護したブランチでは、サブディレクトリの REVIEW.md も使えます（tests・generated・vendor などの名前の下は除外。合計 150,000 バイトまで）。
  • @file.md の行で他のファイルを取り込めます（ルートの 1 段だけ）。@.claude/skills/<folder>/SKILL.md で skill の本文も取り込めますが、skill は実行しません。
  • ローカルの /code-review は REVIEW.md を読みません。

コスト

  • usage credits でトークン量に応じて組織に課金し、Bedrock などの組織でも Anthropic の請求に載ります。1 回の定額はなく、試験運用で Average cost 列から見積もります。
# Review instructions

## What Important means here

Reserve Important for findings that would break behavior, leak data,
or block a rollback: incorrect logic, unscoped database queries, PII
in logs or error messages, and migrations that aren't backward
compatible. Style, naming, and refactoring suggestions are Nit at
most.

## Cap the nits

Report at most five Nits per review.

docs の REVIEW.md の例の前半です。後半は「Do not report」と「Always check」の箇条書きです。

  • 月の上限は claude.ai/admin-settings/usage で設定します。上限・組織の上限・残高が尽きるか、残りが 1 回分に満たないとスキップし、PR に理由をコメントします。

Claude Security プラグインと /security-review

  • セッション内で多数のエージェントが脆弱性を探すプラグインです。リポジトリ全体では、アーキテクチャの把握、脅威モデル、探索、各所見の独立したレビューの順に進みます。ブランチの差分・PR・単一コミットも対象にできます。
  • インストールは /plugin install claude-security@claude-plugins-official、実行は /claude-security です。Scan codebase・変更のスキャン・Suggest patches のメニューが開き、/claude-security scan my branch at high のように文章でも頼めます。
  • effort は low（アーキテクチャと脅威モデルを省く）・medium（既定）・high です。
  • 独自のモデル呼び出しはなく、セッションのモデルで動きます（一部の補助手順は sonnet）。利用量に数えます。
  • 要件: 有料プラン・API・サードパーティのプロバイダ（dynamic workflows を使うため。Pro は /config で有効化）と、PATH 上の python3 3.9 以上。auto mode で最もよく動きます。

出力

  • CLAUDE-SECURITY-<timestamp>/ に、CLAUDE-SECURITY-RESULTS.md・.jsonl・.sarif（SARIF 2.1.0、CWE 分類）と CLAUDE-SECURITY-REVISION-<commit>.json を書きます。専用の .gitignore 付きです。
  • パッチは patches/ に書かれ、自動では適用しません。独立したエージェントがテストを走らせてレビューします。適用は git apply CLAUDE-SECURITY-<timestamp>/patches/F1.patch です。
