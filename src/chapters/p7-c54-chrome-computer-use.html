Chrome と Computer use

Claude Code がブラウザとデスクトップを直接操作する 2 つの仕組みです。この章では、Claude in Chrome の有効化・権限・組織による制御と、CLI の Computer use（research preview）の有効化と安全策を扱います。

Claude in Chrome: 要件と有効化

  • Claude in Chrome 拡張を通じて、ログイン状態を共有したままブラウザを操作します（コンソール・DOM の確認、テスト、データ抽出、アップロード、GIF 録画など）。Claude は自分のタブを開き、セッションのタブグループにまとめます。ログイン画面や CAPTCHA では止まります。
  • CLI と VS Code 拡張（@browser）から使えます。claude remote-control --chrome でも有効にできます（Ch49）。

要件

  • Chrome か Edge。Brave・Arc・Vivaldi・Opera でも検出されます。WSL では使えません。
  • 拡張 1.0.36 以降と、Pro・Max・Ultra・Team・Enterprise の直接契約。/login でのサインインが必要で、API キーや claude setup-token のトークンでは --chrome を付けてもオフのままです。
  • Bedrock・Agent Platform・Foundry では使えません。HIPAA 構成の Enterprise では既定オフです（Owner が有効化）。
claude --chrome       # このセッションで有効
claude --no-chrome    # このセッションで無効
  • /chrome: 状態（Status: Enabled、Extension: Installed）、権限の管理、Reconnect extension、Select browser…（複数接続時）、Enabled by default。
  • Enabled by default は global config の claudeInChromeDefaultEnabled で、CLI と VS Code で共有します。VS Code では v2.1.287 以降、セッション開始時に接続します。
  • ブラウザツールと説明が常にロードされるため、既定でオンにするとコンテキストの消費が増えます。
  • 起動時の「Claude in Chrome extension detected」で Yes, use my browser を選ぶと既定オン、No, keep browser tools off で既定オフになります。
  • 拡張が見つからないと、インストール案内を 1 セッションに 1 回だけ出します（Don't ask again で以後出さない）。

Claude in Chrome: 権限・組織の制御・トラブル対応

  • サイト単位の権限は拡張の設定から継承します。確認は Claude in Chrome wants to で始まり、そのサイトをセッション中すべて許可する選択肢があります。
  • auto mode で分類器がブラウザ操作を承認した場合、拡張は自身のサイト確認を省きます。ただし権限ルールでいずれかのサイトを deny していれば省きません。
  • plan mode では、GIF 録画・新しいタブ・ショートカット実行（を含む browser_batch）の前に確認します。
  • プロジェクトの設定では有効にできません。.claude/settings.json の env にある CLAUDE_CODE_ENABLE_CFC=1 は警告付きで無視されます。
  • アップロードは合計 10 MB までです。複数のハードリンクを持つファイルと、.env・.pem・.key・.ssh 配下（v2.1.293 以降）は拒否します。Read の deny も効きます。
  • /clear はタブグループを閉じます。/resume や終了では、空の新規タブだけのグループを閉じます。

組織の制御

  • deniedMcpServers で claude-in-chrome を拒否するか、managed-mcp.json を配布すると、インストール案内は出ません。
  • managed-mcp.json と併用するには "allowClaudeInChromeWithManagedMcp": true を設定します。
  • 2.1.321 から、Desktop の Code タブなどアプリが提供する Claude in Chrome のツールも、組織の Claude in Chrome ポリシーに従います。

うまく動かないとき

  • 初回の有効化でネイティブメッセージングホストの設定を書きます。Chrome は起動時に読むため、検出されなければ Chrome を再起動します。
  • Receiving end does not exist（service worker の休止）は、/chrome の Reconnect extension で直します。
  • 拡張は Claude Code と同じ claude.ai 組織にサインインしている必要があります（/status の Organization 行）。違うと Browser extension is not connected になります。

CLI の Computer use Preview

  • macOS の research preview で、Pro・Max・Ultra のみです（Team・Enterprise 不可）。対話セッション専用で、-p では使えません。
  • 組み込みの MCP サーバー computer-use です。/mcp で選んで Enable にします。設定はプロジェクトごとに保存されます。
  • 初回にアクセシビリティと画面収録の許可を求めます。許可後に Try again を選びます（画面収録後は再起動が要ることがあります）。
  • アプリごとにセッション単位で Allow for this session か Deny を選びます。ターミナル・IDE には Equivalent to shell access、Finder には Can read or write any file、System Settings には Can change system settings の警告が付きます。
  • 操作の段階: ブラウザと取引プラットフォームは閲覧のみ、ターミナルと IDE はクリックのみ、その他は全操作です。
  • Claude はまず MCP サーバー、Bash、Claude in Chrome を試し、どれも当てはまらないときに画面操作を使います。
  • マシン全体で 1 セッションだけが使えます。最初の操作でロックを取り、セッション終了時に解放します（タスク完了では解放しない）。他は Computer use is in use by another Claude session で失敗します。
  • 操作中は他のアプリを隠し、ターン終了時に戻します。自分のターミナルは表示されたまま、スクリーンショットから除外されます。
  • スクリーンショットは自動で縮小されます（例: 3456×2234 から約 1372×887）。設定はありません。
  • Esc でどこからでも中止できます。キー入力は消費されるため、プロンプトインジェクションに使われません。Ctrl+C でも止まります。
